# 1. 实现范围

阶段 8 在既有幂等结算和不可变 `DailySummary` 基础上，新增只读的
`HistoryReviewService`，集中完成：

1. 查询当前生活日之前的已结算摘要；
2. 选择最近一个有数据的已结算生活日；
3. 区分“昨日总结”和“上次记录日总结”；
4. 按 `lifeDay` 关联每日实际状态和相对校正；
5. 选取最近 7 个标准或弱有效使用日；
6. 汇总消耗、恢复、分类分布和校正方向；
7. 向首页提供描述性复盘模型。

UI 不自行推断有效日、日期称谓或观测归属。

# 2. 历史数据边界

## 2.1 不可变摘要

系统估计数据只读取已结算的 `DailySummary`：

- 初始估计；
- 最终估计；
- 总消耗；
- 总恢复；
- 分类时长、净变化和变化总量；
- 标准 / 弱有效日标记。

历史页面不重放活动，也不更新摘要。

## 2.2 迟到观测关联

每日实际状态和“此刻校正”保存在 `energy_observations`。查询服务按
`lifeDay` 与摘要关联，因此在下一生活日补写的实际状态可以立即展示，
同时不会修改冻结的系统计算结果。

无每日实际状态时明确展示“未确认”，不会把最终估计冒充实际状态。

## 2.3 排除当前日

即使数据源异常返回当前或未来生活日，历史查询仍只接受：

```text
summary.lifeDay < currentLifeDay
observation.lifeDay < currentLifeDay
```

当前未结算生活日不会混入历史日或滚动窗口。

# 3. 昨日与上次记录日

最近一个有摘要的生活日作为首页复盘入口：

- 它严格等于 `currentLifeDay.previous` 时称“昨日总结”；
- 它更早时称“上次记录日总结”。

多日没有使用记录时不会错误地把较早日期称为“昨日”。

轻详情展示：

- 日期；
- 系统初始估计 → 最终估计；
- 独立的实际状态；
- 总消耗 / 总恢复；
- 相对校正总次数及偏低、相符、偏高方向；
- 各大类时长、变化总量和净变化。

底部常驻说明：“系统估计不代表你的实际状态。”

---

# 4. 最近 7 个有效日

滚动窗口口径：

1. 只取 `isStandardEffectiveDay` 或 `isWeakEffectiveDay`；
2. 从当前生活日之前的摘要中选择最近 7 个；
3. 展示时按生活日从旧到新排列；
4. 不足 7 日时展示已有的 1～6 日；
5. 无有效日时不展示滚动入口。

累计内容：

- 总消耗 / 总恢复；
- 有每日实际状态的天数；
- 相对校正次数和方向；
- 各大类累计时长、净变化和变化总量。

分类仍按 `grossDelta` 降序，避免恢复与消耗互相抵消后隐藏活动量。

滚动总结只描述已有数据，不：

- 创建 `CalibrationCycle`；
- 计算 `personalFactor`；
- 建立个人能力基准线；
- 生成自动调整按钮或建议；
- 对活动和状态做原因归因。

# 5. 首页交互

首页工具区下方增加低权重历史复盘卡片：

- 最近记录日摘要标题、日期、最终估计和实际状态；
- 点击摘要行展开当日轻详情；
- 点击“最近 N 个有效日”展开滚动汇总；
- 1～6 日入口明确标记“数据积累中”；
- 当前没有历史摘要时不占用首页空间。

历史查询失败不会伪造数据；首页的当日记录主路径仍可使用。

# 6. 自动化验收

新增覆盖：

1. 严格上一生活日显示“昨日总结”；
2. 更早的最近摘要显示“上次记录日总结”；
3. 无实际状态显示“未确认”；
4. 迟到实际状态按生活日正确关联；
5. 三种相对校正方向分别计数；
6. 非有效日和当前日不进入滚动窗口；
7. 1～6 个有效日显示部分总结；
8. 8 个以上有效日只保留最近 7 个；
9. 分类时长、净变化和变化总量正确累计；
10. Widget 验证估计 / 实际来源分离和无自动调整入口。
