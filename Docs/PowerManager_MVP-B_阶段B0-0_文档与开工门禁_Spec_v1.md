# PowerManager MVP-B 阶段 B0-0：文档与开工门禁 Spec v1

## 0. 文档状态

- 版本：1.0
- 日期：2026-08-15
- 状态：已确认，作为 MVP-B 开工基线
- 前置阶段：MVP-A Stage 19
- 下一阶段：B0-1 迁移准备版

本 Spec 只验收方向、合同和阶段门禁，不授权生产自动学习。所有生产学习开关和两个参数族的
自动应用开关继续保持关闭。

## 1. 阶段目标

在修改 Flutter 代码前，建立一套能够回答以下问题的唯一文档基线：

1. MVP-B 最终要交付什么用户价值；
2. 自动学习使用什么证据，哪些数据永远不能冒充证据；
3. 基准线与活动影响如何独立学习、安排、生效、评估和撤回；
4. 数据库如何从 schema v1 分步升级到 v5；
5. 每一阶段何时可以进入、何时必须停止；
6. 哪些生产参数必须等待真实影子数据，不能由工程实现猜测；
7. 如何区分工程完成与产品假设验证。

## 2. 权威输入

- 当前实现：MVP-A Stage 19，提交 cb5d0a4；
- 现有规则：energy-rules-v2-mvp-a；
- MVP-A v2 PRD、规则配置、算法和技术方案；
- Stage 14、16、19 的备份、数据体检、事务与生活日边界约束；
- 项目作者明确目标：MVP-B 实现自动学习。

## 3. 必须冻结的决策

### 3.1 产品边界

- 自动学习是 MVP-B 核心，不是只给建议的辅助页面；
- 基准线和活动影响两个参数族都属于退出条件；
- 系统只改善估计与用户主观观测的长期对齐，不声称测量生理能量；
- 登录、云同步、健康设备、高级规则编辑和复杂预测不进入 MVP-B。

### 3.2 数据边界

- 估计与实际必须属于同一参考时刻；
- 当前生活日可编辑数据只能显示进度，结算后才可成为证据；
- legacy 数据保留历史语义，不因迁移自动获得学习资格；
- currentMoment 与 previousLifeDayEnd 分组，不互相补足门槛；
- 用户主动活动反馈不进入生产倍率学习，生产倍率只允许使用无结果选择偏差的抽样反馈。

### 3.3 自动化边界

- 基准线和活动影响分别保存 off、review、automatic；
- 两个参数族默认 off，授权不能互相继承；
- automatic 不要求逐条批准，但必须有持久通知、取消、未来生效和撤回；
- 一次运行只改变一个参数族；
- 全局最多一个未处理模型版本；
- 每次真实激活或撤回开启新 model regime epoch。

### 3.4 未知参数边界

方向阈值、步长、累计边界、冷却、证据年龄、候选寿命、最短通知时间、恶化门、活动样本门、
倍率范围和反馈负担上限均不得隐藏在代码、数据库默认值、测试夹具或 Widget 中。它们只能由
B1-1 或 B3-0 的真实数据决策记录发布。

## 4. 文档交付物

阶段必须同时交付并互相引用：

1. 产品 PRD；
2. 数值与功能门配置；
3. 算法规则；
4. 技术方案；
5. Backlog；
6. 总分阶段计划；
7. 规则与实现追踪矩阵；
8. B0-0 至 B3-2 的逐阶段独立 Spec；
9. MVP-B 总体验收 Spec。

职责冲突时，产品行为回到 PRD，常量回到规则配置，计算与状态机回到算法规则，存储和事务
回到技术方案，顺序与阶段门回到总分阶段计划。

## 5. 审计过程

1. 对照 MVP-A 当前字段、备份格式和生活日语义，列出兼容风险；
2. 对照自动学习目标推演从采集、结算、运行、候选、安排、激活到撤回的全生命周期；
3. 对每个生命周期节点补充幂等键、失败分类和恢复语义；
4. 对模式切换、跨 04:00、恢复旧备份、手动修改和多参数族竞争做状态推演；
5. 将每条 P0 规则映射到数据结构、服务和测试；
6. 把真实数据才能回答的问题移入实验门，不填写猜测值；
7. 执行文档结构、链接、术语、开关和 schema 版本一致性检查。

## 6. 验收证据

- 八份总基线文档存在且职责清楚；
- 十二份阶段 Spec 和一份总体验收 Spec 存在；
- 追踪矩阵中的每项能力都有产品来源、规则来源、技术落点和验证方式；
- 所有生产门均为 false，两个默认模式均为 off；
- 文档没有把 schema 文档版本 v3 与数据库 schema v3 混为一谈；
- 文档没有使用旧的 3 条、2 日、70%、0.70～1.30 等未审计参数；
- Markdown 结构、表格、代码围栏、行尾和 git diff 检查通过；
- 项目作者已明确确认自动学习方向并要求按 Spec 开发。

## 7. 停止条件

出现以下任一情况，不得进入 B0-1：

- 两个参数族是否属于 MVP-B 仍有冲突；
- 任一生产阈值在无真实证据情况下被写成默认值；
- legacy 数据被描述为可自动学习；
- automatic 缺少通知、取消或撤回；
- 阶段没有独立验收和停止条件；
- 文档职责或 schema 升级顺序仍互相矛盾。

## 8. 退出条件

本阶段退出只表示可以实施 B0-1。它不表示自动学习有效，也不允许开启任何生产学习路径。
代码实现必须继续逐阶段接受独立 Spec 和测试门约束。
