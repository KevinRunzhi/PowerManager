# PowerManager MVP-B 分阶段开发计划 Spec v1

## 0. 文档信息

- 版本：1.7
- 日期：2026-08-15
- 状态：B3-1 工程实现、自动化与模拟器已通过，产品轨延期到最终安装后；下一阶段 B3-2
- 当前实现起点：MVP-A Stage 19

本计划把“能安全采集证据”“自动学习能在影子中成立”和“模型能安全自动生效”设为三道不同
门禁。MVP-B 的终点是基准线与活动影响的自动学习能力，不是停在候选建议页面。

每个阶段另有独立 Spec，负责该阶段的实现步骤、测试矩阵、真实实验协议、停止条件和验收
证据。本计划只负责总体顺序与跨阶段依赖；两者冲突时，先停止开发并修正文档，不自行选择
较宽松的门。

## 1. 总体依赖

```text
B0-0 文档确认
  -> B0-1 迁移准备版
  -> B0-2 schema v2 与备份兼容
  -> B0-3 正确观测合同 + 活动绑定反馈
  -> B1-0 schema v3 + 自动影子学习器
  -> B1-1 真实观察与基准线生产决策门
  -> B2-0 schema v4 + 学习模式 + 模型版本
  -> B2-1 基准线自动学习与安全激活
  -> B2-2 调整后监测
  -> B3-0 活动影响生产参数门
  -> B3-1 schema v5 + 活动影响学习器
  -> B3-2 活动影响安全激活与监测
  -> MVP-B 自动学习验收
```

活动绑定反馈从 B0-3 开始自然积累，可与 B1 / B2 的基准线工作并行积累数据；活动参数的
生产学习仍必须等待 B3-0。任何一个学习运行只允许改变一个参数族。

## 2. 全局完成定义

每个开发阶段必须：

1. 先更新唯一来源文档，再修改 schema 或代码；
2. 包含 Domain、Data、Application 和受影响 Widget 测试；
3. 通过 `dart format`、`flutter analyze`、全量测试，并把当前代码安装到指定 Android 模拟器完成
   非破坏性验证；
4. 涉及迁移时通过旧版本 fixture、备份往返和失败回滚；
5. 涉及用户流程时完成 Android 模拟器非破坏性验收；
6. 记录未验证的真实产品假设，不用补造数据冒充真实使用；
7. 阶段结束后审查静默变化、重复应用、参数串扰和历史漂移；
8. 功能门未打开时，生产写路径必须不可达，而不只是 UI 隐藏。

需要验证关闭功能时，使用版本化的测试 / 预生产配置走真实 gate，不允许 mock 掉门禁；该配置
不得进入最终交付构建。

### 2.1 设备与构建策略（2026-08-15 决策）

- B0-1 至 B3-2 的阶段放行只使用自动化测试和 Pixel_7 Android 模拟器；
- 阶段内允许 `flutter run` 为模拟器生成并安装临时调试 / profile 构建，但不产出、交付或安装
  最终 APK；
- 物理手机保持现有版本和数据不动，直到全部阶段与 MVP-B 模拟器总验收完成；
- 最终 APK、schema v1 真实数据外部备份、v1 → v5 覆盖升级和真机恢复只在总体验收执行；
- 中间阶段原有“真机”步骤统一视为最终真机矩阵中的延期项，不阻塞后续工程阶段；
- 真实自然数据不足时，baseline / activityImpact 产品状态必须是 `inconclusive`，生产学习和自动
  应用门保持关闭；可用带水印的预生产配置在隔离 fixture 与模拟器中完成工程生命周期；
- 只有最终真机门和相应真实证据通过后，才允许发布生产自动应用配置。工程能力完成不等于产品
  学习效果已经得到验证。

## 3. B0-0：文档确认

### 目标

建立自动学习目标明确、无隐藏阈值、可逐阶段验收的 MVP-B 基线。

### 产物

- MVP-B v3 PRD、规则配置、算法、技术方案；
- Backlog、阶段计划和追踪矩阵；
- 项目作者的范围确认。

### 退出条件

- 自动学习被定义为 MVP-B 核心，活动影响不再是可选实验；
- 两个参数族各自的三种模式、参数族隔离、版本化和未来生效规则一致；
- 暂未决定的生产参数有明确真实数据门禁；
- 自动学习总门、两个生产学习门和两个自动应用门均保持关闭，两个参数族默认模式均为 `off`；
- 确认不再追加与 P0 无关的 MVP-A Stage 20 功能。

## 4. B0-1：迁移准备版

### 目标

在仍使用 schema v1 时证明真实数据有可恢复副本。

### 工作

- 自动或一键生成最新本机备份；
- 完成备份再解析和数据体检；
- 显示备份时间、完整性和升级准备状态；
- 在模拟器执行一次备份、导出、恢复演练；真机复验延期到 MVP-B 总体验收。

### 停止条件

- 备份无法解析；
- 恢复后聚合数量不一致；
- 发现活动、摘要或规则版本错误。

任何停止条件命中时不得进入 schema v2。

## 5. B0-2：schema v2 与备份兼容

### 目标

无损增加观测合同和活动反馈存储。

### 工作

- 实现显式 Drift `onUpgrade`；
- 重建观测表约束；
- 新增 activity feedback 表；
- 更新 Repository、DTO、备份 codec 和 Data Health；
- v1 数据标记为 legacy，不回填伪快照。

### 退出条件

- 合成 v1 数据库升级、约束、外键和触发器测试通过；
- v1 JSON → v2 App 和 v2 JSON 往返通过；
- 迁移失败回滚通过；
- 模拟器升级前后历史与聚合一致；
- App 没有任何学习或模型激活写路径。

## 6. B0-3：正确观测与反馈合同

### 目标

开始积累真正可以被学习器使用的新证据。

### 工作

- 同日状态保存事务快照；
- 昨日补填绑定最终摘要；
- 活动覆盖确认；
- 统一资格和 reason code；
- Data Health 展示合格进度；
- 当前生活日的活动绑定直接反馈与编辑 / 删除失效。

### 退出条件

- currentMoment / previousLifeDayEnd 主流程模拟器通过；
- 跨后台、重启和 04:00 快照不漂移；
- legacy、缺字段和不确定覆盖均正确排除；
- 当前生活日数据在结算前不进入学习资格；
- 活动反馈冻结完整上下文且不会改变估计或参数；
- 用户理解新增问题且没有明显阻断日常记录。

## 7. B1-0：自动影子学习器

### 目标

证明相同证据能自动、确定地生成可重现证据结论，同时完全不碰当前模型。

### 工作

- 实现统一可学习资格和模型分组；
- 通过 schema v3 保存只读、可重现的 learning run；
- 实现证据规范化、哈希和双窗口分析；
- 自动生成只读 learning run；当前没有候选算法配置时不输出候选值；
- 展示进度、排除原因和原始方向分布；
- 对基准线和活动影响保留独立参数族接口。

### 退出条件

- v2 → v3 迁移、备份往返和失败回滚通过；
- 相同输入与版本得到相同结果；
- 新证据触发运行，无新证据零写入；
- 只有生活日结算后的不可变证据可触发学习；
- 重启、后台和重复请求不生成重复运行；
- 影子候选不能进入 pending、current 或 activity calculation；
- `automaticLearningEngineEnabled` 只有满足上述条件的新配置版本才允许开启影子能力。

## 8. B1-1：真实观察与基准线生产决策门

### 目标

用真实数据决定基准线生产阈值，而不是为了让系统产生变化而降低标准。

### 执行

- 只使用真实需要下的日常记录，不用 ADB、fixture 或补造状态通过产品门禁；
- 在单一 model regime 中积累配置要求的观测；
- currentMoment 与 previousLifeDayEnd 分组审计，不混合补足门槛；
- 记录填写负担、覆盖确认理解、排除率和主观参考价值；
- 先发布 shadow-only 候选配置，再回放候选值并评估方向改善、过度反应和累计漂移风险；
- 冻结生产阈值、步长、边界、冷却、恶化保护及自动安全门。
- 冻结自动变化的最短通知 / 取消时间，覆盖临近 04:00 才生成候选的情况。
- 冻结生产证据最大年龄和候选最长生命周期。
- 冻结基准线的最小有用改善、不恶化边界和最大撤回 / 暂停比例。

### 可能结论

- **通过**：数据完整、方向稳定且保护规则可定义，进入 B2；
- **继续观察**：数据完整但方向不稳定，保持影子；
- **修正采集**：排除率高或参考时刻理解错误，回 B0-3；
- **停止基准线假设**：学习无法改善参考价值，不开启该参数族生产门。

### 必须产物

- 新规则配置与基准线算法版本；
- 反事实和极端输入审计；
- 模式与变更通知 UI Spec；
- schema v4 迁移 Spec；
- 更新后的追踪矩阵。

没有这些产物，不得把 `baselineProductionLearningEnabled` 改为 `true`。即使产物齐全，
`baselineAutoApplyEnabled` 仍要等 B2 的自动安排、取消、激活和撤回验证全部通过后再开启。

本轮手机安装延期时，B1-1 先交付工程决策包和不可发布的预生产配置，产品状态记为
`inconclusive`，两个 baseline 生产门均保持关闭；这不阻塞 B2 通用生命周期的工程实现。

本轮工程轨已按上述分支退出：候选回放保持无 IO，预生产配置强制水印，模式 / 通知 UI 与
schema v4 最终迁移合同已形成；正式产品来源和阈值仍等待最终真机自然证据。

## 9. B2-0：schema v4、模式与模型版本

### 目标

先建立不可变、幂等、可恢复的学习基础设施，再允许任何生产候选生效。

### 工作

- `learning_runs` 与 `personalization_versions`；
- 初始 active 模型和唯一状态约束；
- Stage 19 legacy pending base 到手动来源模型版本的幂等桥接；
- schema v4 前结清并校验 legacy pending rule，未决时阻断而不猜测迁移；
- 两个参数族各自的 `off / review / automatic` 设置与首次说明；
- 模式升降级时旧候选不偷跑、未生效自动安排可安全退回待审核；
- 候选、安排、取消、激活、失效、暂停和撤回事务；
- schema v4 备份、恢复和 Data Health。

### 退出条件

- v3 → v4 迁移与失败回滚通过；
- 初始模型参数未变时沿用 B1 regime，真实证据不因数据库版本 ID 改变而清零；
- 每次真实激活或撤回创建新 epoch，回到旧数值也不复用旧窗口；
- legacy pending base 的未来 / 到期值不丢失、不重复，字段残缺时安全阻断；
- pending rule 未决 / 残缺以及旧备份含未决规则时安全拒绝；
- 备份恢复不会出现零个或多个 active 模型；
- 恢复出的过期自动安排不会在首次 prepare 静默补应用，明确手动决定不被误删；
- 相同幂等键不重复创建候选；
- 全局最多一个待审核或待生效版本；
- `off` 取消未激活版本，已激活历史不静默回退；
- 手动设置冲突有确定结果。

## 10. B2-1：基准线自动学习与安全激活

### 目标

让基准线在 `automatic` 模式下真正自动学习和未来生效，同时保留用户控制。

### 工作

- 新证据触发基准线生产学习；
- `review` 的接受 / 拒绝 / 稍后；
- `automatic` 的安全门、自动安排和非阻断通知；
- 最早可生效生活日的幂等激活、激活前取消和激活后撤回；
- 新 model regime 与历史快照隔离。

### 退出条件

- 全模式、全状态和备份恢复测试通过；
- 重启、重复 prepare 和跨日不重复生成或激活；
- 激活前证据、源 regime 或父模型变化时旧候选失效；
- `review` 未接受不变化，`automatic` 只在全部门通过时变化；
- 用户能看到来源、当前值、候选值、生效日、取消和撤回；
- 真实数据不足时返回“继续学习”，不伪造一次更新。

阶段工程验收通过后可以继续 B2-2；`baselineAutoApplyEnabled` 的生产配置仍保持关闭，直到
MVP-B 最终真机门和相应真实产品证据通过。

## 11. B2-2：基准线调整后监测

### 目标

判断自动学习是否持续有帮助，并在恶化时停止继续变化。

### 工作

- 新 model regime 独立积累后续观测；
- 对比方向分布和用户主观参考价值；
- 验证冷却、累计边界、恶化暂停和撤回；
- 记录取消、拒绝、撤回、误解、提示负担和数据错误。

### 退出条件

- 恶化门命中后暂停，不发生自动来回震荡；
- 用户可以理解当前模型为何被暂停并选择撤回或恢复；
- 数据、备份和历史解释没有 P0 / P1 问题。

如果真实结果无帮助，基准线参数族可以以“假设未通过并保持关闭”结束；不能以增加模型
复杂度或降低门槛掩盖失败。

最终安装前，B2-2 只用隔离 fixture 验证监测、暂停和撤回状态机；真实改善结论延期，不能由
模拟器结果替代。

工程实现已完成：纯监测评估器、当前 model regime 过滤、冷却零写入、恶化暂停事务、恢复入口
与 activityImpact 隔离均已通过自动化和模拟器 gate。产品结论仍固定为 `inconclusive`。

## 12. B3-0：活动影响生产参数门

### 目标

用自然积累的直接反馈确定活动影响学习的可行键和生产参数。

### 必须回答

- 哪些“子类 × 影响方向”有足够跨日证据；
- 哪种低频抽样策略能避免只收集异常值，同时负担可接受；
- `stronger / aboutRight / weaker` 如何确定候选倍率；
- 同一键跨时长档位是否足够一致，可否使用一个倍率；
- 单次步长、倍率范围、冷却和恶化保护是什么；
- 零值、方向不符、截断和编辑失效如何排除；
- 多少 `directionMismatch` 必须直接否决该键的倍率候选；
- 多个键同批更新是否仍可解释和安全。
- 活动影响的最小有用改善、不恶化边界、最大提示负担和最大撤回 / 暂停比例是什么。

### 退出条件

- 发布 B3 配置、算法、schema v5 和迁移 Spec；
- 没有数据支持的键明确保持 `1.0`；
- 不使用同子类相反影响方向的反馈补样本；
- 未完成上述产物时 `activityImpactProductionLearningEnabled` 和
  `activityImpactAutoApplyEnabled` 都保持 `false`；后者还必须等待 B3-2 生命周期验证通过。

若当前真实反馈不足，继续积累反馈；活动影响学习仍是 MVP-B 范围，但不得用补造数据启动
生产变化。工程生命周期可以用明确标记的 fixture 验证，不能把 fixture 计为产品证据。

本轮手机安装延期时，B3-0 可以用完整、带水印、不可发布的预生产参数合同放行 B3 工程实现；
两个 activityImpact 生产门保持关闭，产品状态记为 `inconclusive`。

工程合同已冻结并通过：`ActivityImpactKey` 按键审计、userInitiated 与 sampledPrompt 来源隔离、
SHA-256 结果盲抽样、每日上限/跳过与未响应冷却、directionMismatch veto、时长异质门、倍率范围/步长/
取整/恢复上限均由纯领域代码覆盖。合同水印为 `PREPRODUCTION_ONLY_ACTIVITY_IMPACT_V1`，当前
`activityImpactProductionLearningEnabled=false`、`activityImpactAutoApplyEnabled=false`；schema v5
持久化与正式 learner 仍属于 B3-1；B3-1 已完成 schema v5、备份桥接、快照保持和确定性 shadow learner，
正式激活仍属于 B3-2。

## 13. B3-1：活动影响学习器与 schema v5

### 目标

实现按方向隔离、版本化、可重现的活动影响自动学习。

### 工作

- `personalization_activity_factors` 和活动倍率快照；
- ActivityFeedbackSampler、采样来源与策略版本；
- ActivityImpactKey 资格、聚合与候选生成；
- 零值、截断、方向不符和失效反馈排除；
- 主动反馈只进研究，只有受支持的抽样反馈进入生产倍率学习；
- schema v5 迁移、备份和恢复；
- 与基准线参数族的串行优先级。

### 退出条件

- 相同输入确定且幂等；
- 恢复反馈绝不修改消耗倍率，反之亦然；
- 活动倍率更新后不复用旧 regime 反馈，单纯基准线变化不重置活动 regime；
- 固定规则表、旧活动和摘要不重算；
- 仅新增默认倍率能力时不切换有效模型 regime；
- 没有合格键时得到稳定 `insufficientEvidence / noChange`；
- fixture 覆盖完整的候选与版本生命周期。

工程实现已通过：v4 → v5 迁移、失败回滚、v5 备份往返、sample/feedback 生命周期、活动快照保持、
factor regime 隔离和按键 learner 均已完成；生产门保持关闭，下一阶段为 B3-2。

## 14. B3-2：活动影响安全激活与监测

### 目标

让活动影响在 `automatic` 模式下复用统一的自动安排、安全激活和暂停能力。

### 退出条件

- `review / automatic` 模式矩阵通过；
- 自动变化前通知和取消、变化后撤回可用；
- 活动记录冻结实际使用的模型版本和倍率；
- 与基准线同时具备条件时只有一个参数族变化；
- 后续反馈触发恶化门时暂停，不重复震荡；
- 真实数据运行结果如实为更新、无需变化或证据不足之一。

阶段工程验收通过后可以进入总体验收；`activityImpactAutoApplyEnabled` 的生产配置仍保持关闭，
直到 MVP-B 最终真机门和相应真实产品证据通过。

## 15. MVP-B 总退出条件

MVP-B 只有同时满足以下条件才完成：

1. B0 数据、迁移、备份和模拟器门通过，并在最终安装前通过一次集中真机数据安全门；
2. B1 自动影子学习确定、幂等且零生产副作用；
3. 基准线生产学习具备独立三模式、安全激活、监测和撤回闭环；
4. 活动影响学习具备按方向隔离的生产算法与同等级安全闭环；
5. 两个参数族不会同时变化或错误归因；
6. 所有模型变化可由冻结证据、算法和配置版本重现；
7. 真实数据不足时系统能自动选择“不变化”，而不是伪造学习成果；
8. 没有未解决的数据错误、静默变化、不可恢复升级或历史漂移 P0。

工程退出后仍必须单独记录产品假设状态：`validated / rejected / inconclusive`。真实证据不足只
能标记 `inconclusive`，不能因为生命周期测试通过就宣称自动学习对用户有效。

## 16. 范围控制

MVP-B 核心完成前不顺带实施：

- 登录、云同步和多人账号；
- 高级规则编辑或历史迁移；
- 复杂趋势图与预测平台；
- 健康设备或系统数据自动采集；
- 与 P0 无关的能量球视觉重做；
- 为了填满阶段编号而新增 MVP-A 优化。
