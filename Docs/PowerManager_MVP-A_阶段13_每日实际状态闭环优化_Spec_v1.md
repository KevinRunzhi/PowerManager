# PowerManager MVP-A 阶段 13：每日实际状态闭环优化 Spec v1

## 0. 背景

2026-08-09 真实数据审计确认：6 个有效日、27 条活动、0 次每日实际状态。数据层没有
错误，但双轨反馈闭环没有形成。现有入口位于首页底部工具带，昨日补充入口也与设置、概览、
此刻校正并列，真实使用中发现性不足。

本阶段只优化入口与提示，不改变观测唯一性、生活日边界、先选后揭示和历史只读规则。

---

# 1. 目标

1. 当日已有活动但未填写每日实际状态时，让入口在活动区附近可见；
2. 昨日缺少实际状态且仍处于允许补充窗口时，把补充入口放入昨日总结卡；
3. 完成后立即去重，不重复提醒；
4. 不弹窗、不阻断活动记录、不使用报警或失败叙事；
5. 不增加数据库表、埋点、通知权限或自动学习逻辑。

---

# 2. 交互规则

## 2.1 当日提示卡

显示条件必须同时满足：

- 当前生活日至少有 1 条有效活动；
- 当前生活日尚无 `dailyAbsolute` 观测。

位置：当天活动列表之后、底部工具带之前。

文案：

- 标题：`今天结束前，留一次实际感受`
- 说明：`先按自己的感受选择，保存后才显示系统估计。`
- 操作：`记录实际状态`

点击继续使用现有 `ActualStateSheet`，不得复制保存逻辑。

## 2.2 昨日补充

当且仅当 `canSupplementYesterdayProvider == true` 时，在昨日总结卡内部显示
`补充昨日实际状态`。入口不再重复出现在底部工具带。

保存后必须同时刷新：

- 当前每日状态 provider；
- 昨日可补充 provider；
- 历史回顾 provider。

## 2.3 不打扰原则

- 不自动打开 sheet；
- 不写 `prompt_receipts`；
- 不要求用户当天必须填写；
- 没有活动的生活日不显示当日提示卡；
- 已填写后不显示提示卡或补充入口。

---

# 3. 实现范围

- 调整 `home_page.dart` 的入口编排；
- `ActualStateSheet` 保存成功后刷新历史回顾；
- 增加 Widget 回归测试；
- 更新阶段 12 / 13 验收记录。

不在本阶段实施：

- 系统通知；
- 后台定时提醒；
- 允许补填更早历史日；
- 修改实际状态数据模型；
- 自动基准线或 personalFactor。

---

# 4. 验收标准

1. 0 条活动时不显示当日提示卡；
2. 有活动且未填写时显示当日提示卡；
3. 已填写时提示卡消失；
4. 当日提示点击后仍保持先选后揭示；
5. 昨日可补充时，总结卡内显示补充入口；
6. 非昨日、昨日已填写或已超过补充窗口时不显示；
7. 底部工具带不再出现重复的昨日入口；
8. 保存后历史卡的“实际 未确认”可以刷新；
9. 200% 字号下无溢出；
10. `dart format`、`flutter analyze`、完整 `flutter test` 通过；
11. Pixel_7 模拟器主流程通过；真机综合验收仍按既定决策延期到 MVP-B 完成后。
