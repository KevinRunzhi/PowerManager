# 1. 结论摘要

GitHub 上没有一个可以直接替代 PowerManager 能量球的完整案例。现有案例分别解决了
Flutter Shader 工程接入、流体融合、径向菜单和个人状态记录等局部问题，但没有同时具备：

```text
连续精力色温 + 呼吸流体球 + 估计透支薄雾态
+ 晨间点亮仪式 + 活动反馈 + 径向记录手势
+ 本地优先且可重放的正式业务状态
```

因此 Stage18 不引入或照搬任何完整项目，而采用组合借鉴：

1. 以 PowerManager HTML 小样作为唯一视觉基准；
2. 以 Flutter 官方 `simple_shader` / `simple_sdf` 作为 Shader 工程接入基准；
3. 参考 `flutter_metaballs` 的流体融合、光晕、速度和触控隔离思路；
4. 保留当前 `CustomPainter` 作为加载失败、编译失败和兼容性异常时的兜底；
5. 不改变精力算法、数据状态、径向手势状态机和首页信息结构。

本轮重点不是让能量球变得更炫，而是让它更接近已经确认的“安静、有生命感、像水和光一样
缓慢变化”的产品语义。

# 2. 当前实现审计

## 2.1 当前结构

当前 Flutter 能量球位于：

- `app/lib/features/home/presentation/home_page.dart`
- `_EnergyBall`
- `_EnergyBallState`
- `_EnergyBallPainter`

当前实现已经具备：

- 屏宽约 58% 的自适应直径；
- HTML 对应的九段连续色温轴；
- 5.5 秒呼吸和透支时 8 秒浅呼吸；
- 三个按轨迹运动的径向渐变光团；
- 外光晕、球体边缘细描和透支透明度；
- 系统“减少动态效果”适配；
- 数值变化动画和“估计透支”文字标签。

## 2.2 当前差距

当前实现本质上仍是 `CustomPainter + 三个径向渐变圆`，与 HTML 小样使用的是同类绘制逻辑，
所以可以复现位置、颜色和基础运动，却很难继续提升流体质感。主要差距如下：

1. 三个光团边界始终是规则圆形，运动轨迹容易被看出是“几个圆在移动”；
2. 光团之间只有加亮混合，没有连续的形变、拉伸、融合和分离；
3. 球体内部缺少低频大形变与高频细纹理两级结构，近看偏平；
4. 当前光晕只随精力比例变化，没有完整的点亮扩散和活动入球后的短促余波；
5. 颜色本身已经基本正确，但颜色在球内的分布过于均匀，降低了色温变化的感知；
6. 视觉逻辑、参数计算和 Canvas 绘制集中在首页文件中，不利于独立测试和迭代；
7. 当前没有 Shader 加载失败时的正式降级边界，因为尚未接入 Shader。

## 2.3 根因判断

本轮问题不是继续增加更多 Canvas 圆形就能解决。若仍沿用现有结构，增加第五、第六个光团只会
提高绘制复杂度，并不能从根本上消除“圆形渐变叠加”的人工感。

需要把球体内部的颜色分布改成按每个像素连续计算的噪声场和融合场，同时保留现有 Flutter
Widget、业务状态与手势层。

# 3. GitHub 类似案例调研

## 3.1 Flutter 官方 samples

- 仓库：<https://github.com/flutter/samples>
- 直接相关目录：
  - <https://github.com/flutter/samples/tree/main/simple_shader>
  - <https://github.com/flutter/samples/tree/main/simple_sdf>
- 定位：Flutter 官方可运行示例和最佳实践参考。

可借鉴：

- `.frag` 资源在 `pubspec.yaml` 中声明；
- `FragmentProgram` 的异步加载和 `FragmentShader` 创建；
- 在 `CustomPainter` 中设置 uniform 并绘制；
- 分辨率、时间、颜色等输入与 Widget 状态分离；
- Signed Distance Field 用于稳定构造圆形和柔化边缘。

不照搬：

- 示例中的具体画面、配色和演示布局；
- 为展示 API 而保留的最简状态结构；
- 与 PowerManager 生命周期和减少动态效果不一致的动画驱动方式。

本项目落点：

- 作为 Shader 资源、加载生命周期、uniform 顺序和测试边界的工程基准；
- 不作为能量球视觉效果的设计基准。

## 3.2 flutter_metaballs

- 仓库：<https://github.com/T99Rots/flutter_metaballs>
- 协议：MIT
- 定位：使用 Shader 实现的 Flutter metaballs 流体融合组件。

可借鉴：

- 使用 GPU 逐像素计算连续融合，而不是堆叠大量 Widget；
- 将球数量、速度、半径、光晕和颜色作为独立参数；
- 让 Shader 层不抢占或干扰上层手势；
- 不同屏幕尺寸下按归一化坐标计算；
- 通过低数量大形变获得流动感，而不是依靠大量粒子制造热闹感。

不照搬：

- 不直接增加 `metaballs` 包依赖；
- 不采用跟随手指生成流体球的效果；
- 不使用 40 个随机球、弹跳背景或铺满全屏的展示方式；
- 不允许视觉动画拥有或修改精力业务状态。

本项目落点：

- 在自有 `energy_orb.frag` 中实现 2～3 个低频融合场；
- 结合两层轻量噪声打破规则圆边界；
- 继续由 `energyRatio` 和既有 `EnergyPalette` 控制色温与状态语义。

## 3.3 flutter_radial_menu

# 4. Stage18 目标与非目标

## 4.1 目标

1. 将能量球内部主渲染从规则径向渐变圆升级为 Impeller 兼容的 Fragment Shader；
2. 在不改变现有色温语义的前提下，形成可感知但安静的流体融合、形变和内部深度；
3. 能量充足、平静、中低、低、透支和未点亮状态之间具有连续且可解释的视觉差异；
4. 晨间点亮和数值变化时形成短暂、克制的光晕与球体余波；
5. 动画帧只更新渲染参数，不触发当前生活日重放、数据库读取或首页业务树重建；
6. Shader 不可用时自动回退到现有 `CustomPainter`，核心信息和记录入口仍可用；
7. 支持系统减少动态效果，并具备可重复的静态截图与参数测试入口；
8. 在 Pixel_7 模拟器完成视觉、功能、回归和初步性能验收。

## 4.2 非目标

- 不改变精力估算算法、连续色温端点或“100 不是上限”的产品定义；
- 不改变晨间确认、活动记录、实际状态、提醒、结算或备份恢复逻辑；
- 不改变首页当前信息结构和能量球尺寸基线；
- 不修改径向手势的长按、停留、速度、滞回、回滑和松手提交规则；
- 不增加粒子爆炸、闪电、火焰、液面进度条或红色报警效果；
- 不让球体跟随手指大幅变形，避免干扰径向选项识别；
- 不增加第三方 Shader、metaballs 或动画依赖；
- 不实施 Pixy、Nomie、StarBook 或 Jotsy 的日历与数据功能；
- 不在本阶段完成真机 60fps、耗电、OLED 表现或 20 次手势任务验收；
- 不以跨 GPU 的逐像素完全一致作为自动化目标。

# 5. 目标视觉模型

## 5.1 渲染层次

能量球最终保持四个语义层，但由清晰边界管理：

1. 外光晕：球外约 1.6 倍半径的低透明径向光，表达房间中的唯一光源；
2. 流体本体：圆形距离场内的深色基底、2～3 个融合场和两层缓慢噪声；
3. 呼吸与反馈：整体半径呼吸、晨间点亮扩散、记录完成后的短促涨落；
4. 信息层：`估计精力`、数字和`估计透支`标签，继续由普通 Flutter Widget 绘制。

信息层不得进入 Shader，确保文字清晰、可访问、可测试，并避免纹理缩放影响字体。

## 5.2 流体结构

Shader 内部使用两级变化：

- 低频层：2～3 个大尺度融合场，继承 HTML 三团运动的相位与速度关系；
- 细节层：最多两层轻量 value noise / fbm，对场坐标进行小幅扭曲。

约束：

- 不追求真实流体模拟；
- 不使用高阶多层噪声或大量循环；
- 任何时刻仍应一眼看出是一个完整、稳定的圆形能量球；
- 内部形变速度必须慢于普通加载动画，禁止形成“沸腾”或“熔岩灯”感；
- 噪声主要改变颜色边界，不能让球体外轮廓持续剧烈抖动。

## 5.3 状态参数

| 状态 | 流速 | 呼吸周期 / 幅度 | 本体 | 光晕 | 噪声观感 |
|---|---:|---|---|---|---|
| 未点亮 | 0.18 | 极弱或静止 | 冷灰暗 | 约 10% | 很慢、低对比 |
| 充足 | 1.00 | 5.5s / ±1.8% | 清亮青绿 | 最高约 35% | 细、连续 |
| 平静 | 0.68～0.87 | 5.5s / ±1.8% | 天青与青绿 | 随比例降低 | 稳定缓慢 |
| 中低 | 0.51～0.68 | 5.5s / ±1.8% | 琥珀与天青 | 继续降低 | 稍显粘稠 |
| 低 | 0.35～0.51 | 5.5s / ±1.8% | 暖橙与褐色 | 接近 12% | 较慢、较厚 |
| 估计透支 | 0.35 | 8s / ±0.8% | 灰紫、45% 薄雾 | 约 12% | 颗粒更大更稀 |

具体颜色仍全部来自 `EnergyPalette.forRatio`，Shader 不得再维护第二份色温端点。

## 5.4 状态过渡

### 晨间点亮

```text
灰暗球 → 光晕先扩张 → 色温由灰暗注入 → 流动恢复 → 数字更新
```

- 完整点亮目标时长约 800ms；
- 同一生活日最多播放一次完整仪式；
- 同日编辑晨间答案只播放弱化更新；
- 减少动态效果开启时直接切换到最终状态，只保留必要的短淡入。

### 数值变化

- 估计值变化继续触发数字动画；
- 球体只增加一次最大约 3% 的短促涨落和轻微光晕余波；
- 不因每个动画帧重复触发业务计算；
- 撤销时允许反向数值变化，但不播放比记录完成更强的效果。

### 透支切换

- 颜色连续过渡到灰紫，不瞬间闪烁；
- 负数照常显示；
- 本体存在但稀薄，不缩小、不破碎、不熄灭；
- 退出透支时同样连续恢复，不播放“胜利”特效。

# 6. 技术方案

## 6.1 建议目录边界

```text
app/
├─ lib/features/home/presentation/energy_orb/
│  ├─ energy_orb.dart
│  ├─ energy_orb_parameters.dart
│  ├─ energy_orb_shader_renderer.dart
│  └─ energy_orb_fallback_painter.dart
├─ shaders/
│  └─ energy_orb.frag
└─ test/features/home/presentation/energy_orb/
   ├─ energy_orb_parameters_test.dart
   └─ energy_orb_widget_test.dart
```

文件名可依照仓库实际风格微调，但必须把能量球从 `home_page.dart` 的私有大段实现中拆出，且不把
业务 provider、数据库访问或活动用例移动进渲染目录。

## 6.2 参数模型

`EnergyOrbParameters` 只接收已经派生好的显示值：

- `timeSeconds`
- `resolution`
- `energyRatio`
- `flowSpeed`
- `breathScale`
- `activationProgress`
- `pulseProgress`
- `mistAmount`
- `primaryColor`
- `secondaryColor`
- `reduceMotion`

约束：

- 参数模型必须是纯计算、可单元测试；
- 色温仍由现有 `EnergyPalette` 生成；
- Shader uniform 写入顺序必须集中定义并加注释，禁止在多个文件各维护一套索引；
- `initialEstimate == 0` 的现有保护逻辑必须保留；
- 比例高于 1.00 和低于 -0.30 时继续由 `EnergyPalette` 钳制颜色，但负值语义不能被钳制掉。

## 6.3 Shader 资源与加载

在 `pubspec.yaml` 中声明：

```yaml
flutter:
  shaders:
    - shaders/energy_orb.frag
```

加载规则：

1. 组件创建后异步加载 `FragmentProgram`；
2. 加载期间显示现有 Painter，不显示空白或加载指示器；
3. 加载成功后在保持相同尺寸和中心点的情况下切换到 Shader；
4. 加载或创建失败时本次运行继续使用 Painter，并在调试环境提供可诊断信息；
5. 不因每次能量值变化重新加载 Program；
6. Widget dispose 后不得继续 tick 或调用 setState。

## 6.4 绘制与动画驱动

- 保留一个常驻 `AnimationController` 或等价 ticker；
- 每帧只更新 Shader uniform 并请求局部重绘；
- Shader 画布限制在能量球及光晕所需区域，不绘制全屏；
- 数字与标签不随 Shader 纹理重绘；
- 手势层继续使用原有几何尺寸，不能从 Shader 像素反推命中区域；
- 估计值、晨间状态或减少动态效果变化时更新参数，不重新创建整套首页状态；
- App 不可见或动画被禁用时停止 ticker；
- 页面恢复时从当前时间相位继续，不补算离屏动画帧。

## 6.5 Shader 复杂度上限

- 噪声 octave 最多 2 层；
- 固定次数循环必须可在编译期展开，不使用依赖数据的长循环；
- 不采样网络或运行时生成纹理；
- 不引入大尺寸离屏图片；
- 不使用会导致 Android / Impeller 不兼容的 GLSL 特性；
- 避免高精度不是性能目标时仍全程使用高成本计算；
- 若目标质感需要突破以上限制，必须先以模拟器性能证据修订本 Spec。

## 6.6 降级策略

| 情况 | 行为 |
|---|---|
| Shader 正常 | 使用新流体渲染器 |
| Program 尚未加载 | 使用现有 Painter |
| Shader 加载或创建失败 | 本次页面生命周期固定使用 Painter |
| 系统减少动态效果 | Shader 停在稳定相位，关闭呼吸和流动 |
| 极端小屏或大字体 | 球尺寸按现有规则适配，文字独立缩放 |
| 截图/测试固定时间 | 注入固定相位，生成可重复画面 |

降级只影响视觉表现，不得影响估计值、文字标签、`+` 入口、径向手势或业务写入。

# 8. 验收标准

## 8.1 自动化与构建

- `dart format` 通过；
- `flutter analyze` 为 0 issue；
- 全量 `flutter test` 通过；
- Android Release APK 构建通过；
- `EnergyOrbParameters` 覆盖至少以下比例：`1.20 / 1.00 / 0.80 / 0.65 / 0.50 /
  0.37 / 0.25 / 0.12 / 0.00 / -0.10 / -0.30`；
- 覆盖未点亮、正常、透支、`initialEstimate == 0` 和减少动态效果；
- 覆盖 Shader 加载中、成功和失败 fallback；
- 测试固定时间时，同一输入产生相同参数和稳定画面结构；
- 动画 tick 不触发数据库读取、当前日重放或活动写入。

## 8.2 视觉忠实度

在 Pixel_7 模拟器固定尺寸下，对未点亮、80%、50%、25%、0%、透支分别验收：

- 球心位置和直径与 Stage18 前基线相比不出现可感知跳位；
- 色温端点继续与 HTML 和 `EnergyPalette` 一致；
- 外光晕半径约为球体 1.6 倍，边缘自然消失，无明显矩形裁切；
- 内部至少存在两个可连续融合的颜色区域；
- 不再明显看出三个规则径向渐变圆沿固定轨道移动；
- 流体边界缓慢形变，但球体外轮廓保持稳定；
- 20 秒观察内不出现闪白、闪黑、接缝、色带、锯齿或周期性抽动；
- 数字、标签和透支标记全程保持清晰；
- 透支使用低饱和灰紫，不出现红色警告或破裂效果；
- 高于 100 时不出现封顶、爆条或庆祝效果。

视觉判断优先级：

```text
产品语义正确 > HTML 气质一致 > 流体层次提升 > 装饰性细节数量
```

## 8.3 动效与状态

- 正常呼吸为约 5.5 秒、幅度约 ±1.8%；
- 透支呼吸为约 8 秒、幅度约 ±0.8%；
- 流速随比例由约 1.00 连续下降至 0.35；
- 完整点亮约 800ms，顺序为光晕扩张、色温注入、数值稳定；
- 活动记录后的球体涨落最大约 3%，反馈一次后回到正常呼吸；
- 进入和退出透支均连续过渡；
- 开启减少动态效果后，持续流动、呼吸和粒子级变化停止；
- 切后台 10 秒再恢复，不补播离屏帧、不突然加速；
- 连续进入首页三次，不重复加载 Program 或错误重播晨间完整点亮。

## 8.4 性能与稳定性

模拟器阶段采用相对和行为性指标：

- Profile 或 Release 模式连续停留首页 60 秒无崩溃、黑球或 Shader 丢失；
- 动画期间不出现连续 5 帧以上的明显卡顿；
- 与 Stage18-0 基线相比，不出现持续性帧耗时恶化；
- 首页 Widget 树不随每个 Shader 帧整体重建；
- 连续打开和关闭径向菜单 20 次，无渲染残留或内存持续明显增长；
- Shader 失败时 fallback 在一个页面生命周期内保持稳定，不反复尝试造成闪烁；
- 页面退出后 ticker 正确停止。

真机 60fps、功耗、温升和长时间稳定性不在本轮作最终结论，统一记录为 MVP-B 完成后的真机验收项。

## 8.5 交互与无障碍回归

- 能量球中心、可长按区域和径向菜单几何与 Stage17-D 保持一致；
- 长按、候选、停留确认、回滑、取消和松手保存均不因 Shader 改变；
- 点击式 `+` 始终可用；
- Semantics 仍可朗读“估计精力 + 当前值”；
- 200% 字体下文字不被球体裁切；
- 颜色之外仍有“估计精力”“中低/低/估计透支”等文字语义；
- Shader 或 fallback 均不拦截上层触控事件。

# 9. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| Shader 在部分 GPU 编译失败 | 能量球空白 | 启动即有 Painter fallback，失败后固定降级 |
| uniform 顺序漂移 | 颜色、尺寸异常 | 单一映射文件、索引注释、参数测试 |
| 视觉过度活跃 | 偏离安静产品气质 | 限制噪声层数、速度和形变幅度，20 秒观察验收 |
| Shader 画布过大 | 帧耗时增加 | 只绘制能量球及光晕局部区域 |
| 动画驱动业务重算 | 卡顿或数据风险 | Shader 只消费派生参数，每帧不得读取数据库 |
| 点亮状态重复触发 | 仪式感变成干扰 | 区分生活日状态与组件生命周期，测试反复进入首页 |
| 模拟器表现掩盖真机问题 | MVP-B 后出现差异 | 明确暂定结论，保留真机专项验收 |
| 第三方协议污染 | 发布和分发受限 | 不复制 GPL 代码，不增加第三方流体包 |
