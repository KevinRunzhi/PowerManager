# 2. 指标口径

## 2.1 自动证据

以下项目以应用数据和每日 JSON 导出为准：

- 活动记录条数；
- 是否完成每日实际状态；
- 当前仍存在的补记、编辑结果和逻辑删除记录；
- 随时校正的方向；
- 每日总结、04:00 结算和重算结果；
- 规则版本与基准线生效日期。

每天结束后可导出一次 JSON，文件名已包含导出时间。导出文件不提交 Git；阶段
结束时只在最终报告记录统计结果和异常，不复制私人活动明细。

## 2.2 人工短日志

以下信息无法从当前 schema v1 准确恢复，必须当天手工填写：

- 是否为真实需求主动打开；
- 补记 / 编辑 / 删除的实际操作次数；
- 无法分类或必须绕路的次数；
- 崩溃、卡死、数据看起来不一致等异常；
- 当天主观记录负担；
- 估计是否有参考价值。

不新增埋点或新数据表，避免为了测量而改变 MVP-A 的日常使用负担。

## 2.3 “主动使用”的定义

满足以下任一项记为“是”：

- 因真实活动完成而打开并记录；
- 因真实状态变化而打开并校正；
- 主动查看今日概览、昨日总结或滚动总结来辅助判断。

仅安装、跑测试、ADB 操作、截图、调试或为了填满 7 日指标而打开，均记为“否”。

## 2.4 主观量表

记录负担使用 1～5：

| 分数 | 含义 |
|---:|---|
| 1 | 几乎无负担 |
| 2 | 轻微，但不影响继续使用 |
| 3 | 可以接受，但已有明显摩擦 |
| 4 | 较重，开始逃避记录 |
| 5 | 无法持续 |

估计参考价值使用三档：

- 有：帮助判断了是否继续投入、休息或调整；
- 一般：偶尔有帮助，但需要频繁忽略或自行修正；
- 无：数字基本不能辅助判断，甚至产生干扰。

# 4. 数据一致性检查

每日结束或发现疑问时检查：

- 首页活动条数与活动列表一致；
- 每条活动的分类、时长和估计变化符合当时选择；
- 编辑最早活动后，后续恢复上限与当前估计已重放；
- 删除后活动不参与当前估计，但 JSON 仍保留逻辑删除记录；
- 04:00 后旧生活日只读，新生活日正常开始；
- 实际状态先保存再揭示系统估计；
- JSON 能正常生成并打开为合法对象。

发现数据错误时：

1. 当天立即停止继续写入；
2. 导出 JSON 并记录复现步骤；
3. 阶段 12 判定中止；
4. 修复、回归测试并提交；
5. 清理测试环境后重新开始完整 7 个自然日。

布局、文案或操作摩擦不会自动中止，但必须写入“最大摩擦”。

# 5. 七日通过判定

所有条件均满足才通过：

- 7 个自然日中至少 5 天真实主动使用；
- 至少 4 次每日实际状态确认；
- 补记、编辑、删除、重算和结算无数据错误；
- 估计精力对当天判断具有实际参考价值；
- 无法分类或必须绕路没有频繁发生；
- 点击式 `+` 稳定可用；
- 没有为了达标而伪造活动或打开次数。

手势转正条件保持独立：

- 20 次真实手指任务至少 18 次成功；
- 0 次错误记录；
- 取消任务不落库。

该真机手势门槛已延期到整个 MVP-B 完成后，因此阶段 12 即使通过，也不会自动
降低 `+` 的视觉权重。
