# 1. 双轨边界

本阶段保持两个互不覆盖的数据轨：

```text
估计轨
base + morningAdjustment + shortTermAdjustment + activity replay

主观状态轨
dailyAbsolute / relativeCorrection 原始观测
```

主观状态不会：

- 改写 `currentEstimate`；
- 改写活动 delta；
- 改写个人基准线；
- 自动调整规则；
- 反向修改已经冻结的每日摘要。

界面统一使用“估计精力”“实际状态”“你的感受”等不同名称，避免把估计冒充实际。

# 2. 晨间确认

四步输入：

1. 综合状态：差 / 一般 / 好；
2. 可自由安排时间：少 / 中 / 多；
3. 主要压力来源：学习 / 实践事务 / 都有 / 压力不大；
4. 睡眠恢复感：差 / 一般 / 好。

保存规则：

- 四项原始选择全部保存；
- 只有综合状态映射为 `-6 / 0 / +6`；
- 自由时间、压力来源和睡眠恢复感仅作上下文；
- 睡眠恢复感不会重复计分；
- 已完成晨间确认可再次进入并修改；
- 修改后当天活动从头重放，恢复上限同步更新。

## 2.1 跳过

晨间确认可以跳过，跳过写入幂等 `prompt_receipt`，不创建伪 MorningCheckIn。

跳过后：

- 初始估计仍为“基础值 + 相邻上一生活日短期修正”；
- `morningAdjustment = 0`；
- 活动记录入口完全可用；
- 能量球显示实际估计值，不显示占位符；
- 光晕使用弱点亮；
- 首页显示“今天已跳过晨间确认 · 可补做”。

## 2.2 四种可测试状态

| 状态 | 首页表现 |
|---|---|
| 首次未回答 | 晨间确认（可跳过） |
| 已跳过 | 今天已跳过晨间确认 · 可补做 |
| 补做 / 首次完成 | 晨间已确认 · 可修改 |
| 再次编辑 | 预载原四项选择，保存后仍为已确认 |

# 3. 每日实际状态

五档原始枚举：

```text
耗尽 / 偏低 / 尚可 / 良好 / 充足
```

## 3.1 防锚定顺序

实际状态 Sheet 在选择前只显示五档按钮和说明：

```text
先按自己的感受选择；系统估计会在保存后揭示。
```

选择并保存成功后，才显示：

- 用户选择；
- 系统当时或结算时估计；
- 描述性差异；
- “不会覆盖估计或自动修改规则”的边界说明。

自动化测试通过 key 直接验证揭示节点在保存前不存在。

## 3.2 唯一性与修改

- 数据库部分唯一索引保证每个生活日最多一条 dailyAbsolute；
- 当天已有选择时使用原记录 ID 更新，可再次修改；
- 下一生活日只允许补充严格相邻昨日；
- 昨日必须存在不可变摘要；
- 昨日一旦补充后只读；
- 迟到观测不更新摘要。

## 3.3 描述性差异

系统估计只映射为档位序数用于生成自然语言：

- 疲惫不少；
- 更疲惫一些；
- 大致一致；
- 更有余力一些；
- 更有余力不少。

不会把“实际状态”伪造为某个精确能量数值。

# 4. 随时相对校正

三档：

```text
比估计低 / 差不多 / 比估计高
```

每条校正保存：

- 当前生活日；
- 原始枚举；
- 发生 UTC 时间；
- 发生时 `currentEstimate` 快照。

保存前后当前估计保持一致。成功反馈明确说明“MVP-A 规则保持不变”。

---

# 5. 写入与事务

晨间确认、跳过、每日状态和相对校正全部：

1. 串行化用户写入；
2. 在事务中调用 `prepare(beforeWrite)`；
3. 重新校验目标生活日；
4. 写入原始数据；
5. 必要时完整重放；
6. 失败时回滚。

为支持当天实际状态修改，Repository 增加 observation 按 ID 更新；数据库唯一约束仍是最终防线。
