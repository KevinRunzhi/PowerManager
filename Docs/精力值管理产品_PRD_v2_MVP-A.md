# 1. 产品定义

PowerManager 是一个移动端个人精力估计与观察工具。

它不测量客观生理能量，也不评价个人能力。产品通过活动记录生成可解释的“估计精力”，同时采集用户独立提供的“实际状态”，帮助用户观察一天中的负荷、恢复和估计偏差。

产品采用双轨状态：

- **估计精力**：系统根据个人基准线、早间综合状态、上一生活日短期修正和活动记录计算出的参考值。
- **实际状态**：用户通过每日五档确认或随时三档校正提供的主观观测。

两者必须分别保存和展示，不能用系统估计结果冒充用户实际状态。

---

# 2. 当前用户与产品边界

MVP-A 首先只供项目作者本人使用。默认活动、作息和交互优先满足真实自用，但代码、数据结构和规则版本不绑定具体姓名、账号或单一设备。

未来可以扩展到有精力管理需求的大学生或个人用户，但多人留存和通用画像覆盖不属于 MVP-A 的验收目标。

MVP-A 不做：

- 任务清单、日程和番茄钟
- 登录、云同步和社交
- 自动读取课表、屏幕时间或健康设备
- 自动调整个人基准线
- 自动更新活动个性化参数
- 高级规则编辑和历史规则迁移
- 复杂趋势图表
- 自定义子类名称

# 3. 核心概念

## 3.1 默认尺度

- `100` 是默认参考点，不是生理满值或能力评分。
- 估计精力可以高于 100，也可以低于 0。
- 低于 0 称为“估计透支”，只表示当前规则下的估计结果。

## 3.2 个人基准线

- 默认 100。
- 用户可以在设置中手动调整 60～140。
- 修改从下一个生活日起生效。
- 不重算当前生活日和历史。
- MVP-A 不自动提出基准线调整建议。

## 3.3 生活日

- 每个生活日在本地时间 04:00 切换。
- 00:00～03:59 的记录归入前一个生活日。
- 当前生活日可以补记和纠错。
- 结算后的历史在 MVP-A 中只读。

# 4. 每日使用流程

## 4.1 早间确认

每个生活日首次打开时提供早间确认，可跳过，不阻断记录。

输入包括：

1. 综合状态：差 / 一般 / 好
2. 可自由安排时间：少 / 中 / 多
3. 主要压力来源：学习 / 实践事务 / 都有 / 压力不大
4. 睡眠恢复感：差 / 一般 / 好

只有综合状态直接影响初始估计。自由时间、压力来源和睡眠恢复感只作为解释与后续分析上下文，避免重复计分。

## 4.2 白天活动记录

用户完成一段活动后选择：

1. 大类
2. 子类
3. 固定时长档位

系统立即更新估计精力和今日概览。

记录入口：

- 点击式入口首先作为稳定主路径。
- 能量球连续滑动手势通过真机验证后，才升级为默认主入口。
- 两种入口调用同一记录用例和计算规则。

## 4.3 随时校正

用户可以主动反馈：

- 比估计低
- 差不多
- 比估计高

反馈保存原始选择和发生时间，不直接覆盖估计精力，也不在 MVP-A 中自动改变规则。

## 4.4 每日实际状态

每个生活日提供一次实际状态确认：

- 耗尽
- 偏低
- 尚可
- 良好
- 充足

用户先选择实际状态，再看到系统估计和二者差异，减少锚定。

当天未确认时，可以在下一生活日首次打开时补充上一生活日状态。确认可跳过。

## 4.5 结算与复盘

- 04:00 后首次启动、回前台或业务写操作前，幂等结算更早生活日。
- 结算生成不可变的每日摘要。
- 展示昨日或上次记录日的描述性总结。
- 展示滚动最近 7 个有效使用日的描述性总结。
- MVP-A 不生成自动基准线建议。

# 5. 活动分类

MVP-A 使用 4 个大类、24 个子类。

## 5.1 学习

- 上课
- 自学 / 论文
- 写作业
- 复习 / 备考
- 整理 / 总结
- 其他学习

## 5.2 实践 / 事务

- 实现 / 开发
- 做实验
- 项目推进
- 调试 / 修改
- 组织 / 事务
- 其他事务

## 5.3 休息恢复

- 午睡 / 小睡
- 轻活动
- 放空 / 调整
- 运动恢复
- 生活休整
- 其他恢复

夜间睡眠不作为普通活动记录，通过次日早间“睡眠恢复感”表达。

## 5.4 娱乐消遣

- 打游戏
- 刷视频 / 短内容
- 看剧 / 观影
- 聊天 / 社交
- 兴趣娱乐
- 其他娱乐

四个“其他”使用所属大类的保守通用规则，MVP-A 不允许自定义名称。

# 6. 活动记录与纠错

## 6.1 时长

使用固定档位：

```text
15、30、45、60、90、120 分钟
```

## 6.2 当前生活日纠错

在当前生活日结算前允许：

- 补记活动并选择大致完成时间
- 编辑大类、子类、时长和完成时间
- 删除记录

修改后重新派生当天估计与汇总。

记录完成后的 5 秒撤销是快捷入口，不是唯一纠错方式。

## 6.3 历史边界

- 04:00 结算后的活动历史只读。
- 新规则不修改历史记录。
- 每条记录保存计算时使用的规则版本。

---

# 7. 估计、提醒与展示

## 7.1 初始估计

```text
初始估计 = 个人基准线 + 早间综合状态修正 + 上一生活日短期修正
```

上一生活日的估计透支继续产生 `-1～-4` 的次日短期修正。该规则是产品中的负荷延续机制，不是生理恢复结论；空生活日中断影响。

## 7.2 恢复上限

正向活动只能补回到当日初始估计，不能超过初始估计。负向活动允许使估计低于 0。

## 7.3 提醒

- 中低、低和透支提醒均明确使用“估计”表述。
- 提醒轻量、不阻断记录。
- 同一生活日同一档位最多展示一次。
- 记录 5 秒撤销窗口结束后再展示提醒。

## 7.4 今日概览

每个大类展示：

- 总时长
- 估计精力净变化

默认按变化绝对值总量排序，避免恢复和消耗抵消后隐藏高活动量。

15. JSON 数据导出

# 9. MVP-B 前置条件

MVP-B 不因代码完成自动启用。

基准线建议至少需要：

- 14 个带每日实际状态的有效日
- 系统估计与用户实际状态出现持续、可解释的偏差
- 用户确认后才生效

子类参数建议只能使用与具体活动绑定的直接反馈。每日整体偏差不得强行分摊给某个活动。

具体样本阈值、调整步长和参数范围等待 MVP-A 真实数据后确定。

---

# 10. 自用验证标准

第一轮由项目作者本人连续验证 7 个自然日：

1. 至少 5 天主动使用。
2. 至少完成 4 次每日实际状态确认。
3. 补记、编辑、删除、重算和结算无数据错误。
4. 估计精力对当天判断具有实际参考价值。
5. 不频繁出现无法归类或必须绕路的问题。
6. 点击式入口稳定可用。
7. 能量球手势在 Android 真机 20 次独立任务中至少成功 18 次且不产生错误记录，才升级为默认主入口。
