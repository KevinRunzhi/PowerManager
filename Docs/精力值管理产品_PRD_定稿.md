# 精力值管理产品 PRD 定稿

## 0. 文档说明

本文档为精力值管理产品第一版 PRD 定稿，用于指导后续设计、开发和测试。

本文档定义：
- 产品定位与目标用户
- 第一版 MVP 范围
- 核心用户流程
- 精力值系统规则
- 首页、记录、提醒、详情、设置等主要功能边界
- 第一版暂不做内容
- 开发阶段待细化内容

算法参数不在 PRD 中展开，详见《精力值算法规则初稿》。

---

# 1. 产品定位

## 1.1 产品定义

本产品是一个面向大学生的移动端个人状态管理工具。

产品不以任务清单、日程安排或番茄钟为核心，而是以 **精力值** 作为核心单位，帮助用户理解一天中学习、实践事务、休息恢复、娱乐消遣之间的精力消耗、恢复和分配。

产品更像一个“个人精力系统”或“人生游戏面板”，而不是传统效率工具。

## 1.2 核心价值

产品要解决的问题不是“用户今天有哪些任务”，而是：

- 用户不知道当天到底有多少可用精力
- 用户不知道不同活动对精力的消耗差异
- 同样 1 小时，不同活动对状态的影响不同
- 用户缺少一种方式判断今天是否还适合继续学习、实践，还是应该恢复
- 用户不希望用复杂任务系统管理一天

第一版核心价值：

> 让用户像观察游戏角色状态一样，理解并调配自己的每日精力。

## 1.3 产品原则

- 精力优先，不以时间作为唯一解释单位
- 极简录入优先，避免复杂表单
- 游戏感但不幼稚
- 系统先给结果，用户再决定是否深看
- 系统辅助判断状态，但不替用户安排具体任务
- 用户保留控制权，关键调整需用户确认

# 2. 目标用户

## 2.1 核心用户

第一阶段目标用户为：

- 大学生
- 以计算机、工科、项目实践较多的学生为主
- 同时承担学习与实践事务投入的人
- 有自我管理意识，但不愿意使用复杂任务管理工具的人
- 对自己的状态、精力分配和长期节奏有感知需求的人

## 2.2 用户画像

### 画像 A：计算机专业本科生

- 平时要上课、写作业、复习、准备考试
- 同时在做课程实验、代码开发、项目练习
- 会通过游戏、视频、看剧、聊天放松
- 常觉得一天做了很多事，但不知道分配是否合理
- 容易在某一类活动上投入过多，导致其他事情推不动

### 画像 B：主动成长型学生

- 想兼顾绩点、项目、竞赛、技术成长
- 希望更高效，但不想被传统效率工具绑住
- 关注自己还剩多少高质量投入能力
- 对数值系统、游戏化反馈较容易接受

# 3. 第一版产品边界

## 3.1 第一版不做成什么

第一版不做：

- 传统任务管理软件
- 复杂长期规划系统
- 社交型产品
- 自动化数据整合平台
- 日志补记工具

具体不做：

- 任务清单 / 待办系统
- 排日程、任务拆解、截止日期驱动
- 朋友对比、排行榜、群体监督
- 自动读取课表
- 自动读取屏幕使用时长
- 接入健康设备数据
- 跨天补记或晚上统一回忆回填

## 3.2 第一版价值边界

第一版不是为了做到绝对科学，而是为了做到：

- 用户每天愿意打开
- 愿意快速记录活动
- 能直观看到精力变化
- 能大概知道今天精力花在哪
- 能形成状态认知，而不是任务焦虑

# 4. 核心机制概览

## 4.1 每日流程

### 早晨

- 系统基于历史状态给出自动初始精力值
- 用户通过 3 项早间确认进行轻微修正
- 首页展示今日精力值

### 白天

- 用户做完一段活动后，从首页大能量球发起记录
- 通过手势快速选择大类、子类、时长
- 系统计算本次活动精力影响
- 记录后能量球和数值即时变化

### 当天过程中

- 首页始终展示当前剩余精力
- 首页展示轻量今日概览
- 当精力进入低精力区间，系统给出轻提示

### 晚上 / 次日

- 系统按生活日自动结算
- 第二天首次打开时展示一句昨日总结
- 用户可展开昨日轻详情

### 每 7 个有效使用日

- 系统评估个人基准线是否需要调整
- 给出建议值和轻量原因摘要
- 用户确认后才生效

## 4.2 生活日规则

第一版采用“生活日”，不是严格自然日。

规则：
- 默认结算点为次日凌晨 04:00
- 凌晨 0 点后、04:00 前的记录默认归入前一天
- 系统自动完成生活日结算
- 不要求用户手动结束一天

# 5. 精力值系统

## 5.1 精力值定义

- 100 是基准线，不是上限
- 用户状态好时，当日初始精力可以高于 100
- 用户状态差时，当日初始精力可以低于 100
- 当天剩余精力可以低于 0，低于 0 表示透支

## 5.2 个人基准线

个人基准线表示用户近期稳定状态下的日常初始精力水平。

规则：
- 默认从 100 开始
- 每累计 7 个有效使用日评估一次
- 系统给出建议调整值
- 用户同意后才生效
- 用户可以拒绝调整
- 用户可以手动调整基准线
- 手动调整时需要确认提示，说明会影响之后的初始精力估算

## 5.3 当日初始精力

当日初始精力由三部分组成：

```text
当日初始精力 = 个人基准线 + 早间微调 + 短期修正
```

说明：
- 个人基准线是慢变量
- 早间确认代表当天临时波动
- 透支等短期状态会轻微影响第二天自动初始精力

首次进入产品时：
- 个人基准线默认 100
- 首次早间确认只做轻微修正
- 不要求用户手动输入初始精力值

## 5.4 透支规则

当天剩余精力低于 0 时进入透支状态。

透支影响：
- 单日透支会轻微影响第二天自动初始精力值
- 单日透支不造成惩罚式大幅下调
- 透支频率进入每 7 个有效使用日的周期评估
- 持续透支时，系统可建议小幅下调个人基准线
- 偶发透支不视为长期能力下降

具体算法见《精力值算法规则初稿》。

## 5.5 恢复上限

恢复类活动只能补回当天已经消耗的精力，不能让当天剩余精力超过当天初始精力值。

示例：
- 今日初始精力为 100
- 用户消耗到 80
- 休息恢复可以补回到 100
- 不能因为休息恢复让当天精力超过 100

# 6. 活动分类体系

第一版采用 4 大类，每类 5 个子类。

## 6.1 学习

- 上课
- 自学 / 论文
- 写作业
- 复习 / 备考
- 整理 / 总结

## 6.2 实践 / 事务

- 实现 / 开发
- 做实验
- 项目推进
- 调试 / 修改
- 组织 / 事务

## 6.3 休息恢复

- 睡觉 / 午休
- 轻活动
- 放空 / 调整
- 运动恢复
- 生活休整

## 6.4 娱乐消遣

- 打游戏
- 刷视频 / 短内容
- 看剧 / 观影
- 聊天 / 社交
- 兴趣娱乐

第一版不开放用户自定义子类。

# 7. 早间确认

## 7.1 目标

早间确认用于：

- 微调当天初始精力值
- 获取当天资源和压力信息
- 支持当天状态判断

它不是计划流程，也不是任务填写流程。

## 7.2 输入项

第一版包含 3 项：

1. 综合状态：差 / 一般 / 好
2. 今天可自由安排的时间：少 / 中 / 多
3. 今天主要压力来源：学习为主 / 实践事务为主 / 都有 / 压力不大

## 7.3 展示频率

- 每个生活日首次打开时出现
- 允许跳过
- 跳过后当天不再强弹
- 首页保留弱入口，用户后续仍可补做早间确认
- 早间确认不作为进入首页或记录活动的强制门槛

## 7.4 有效使用日

有效使用日分为两类：

标准有效使用日：
- 完成早间确认
- 至少记录 1 次活动

弱有效使用日：
- 未完成早间确认
- 但至少记录 2 次活动

两类有效使用日都计入校准进度，但弱有效使用日在模型判断中权重较低。

# 8. 首页

## 8.1 核心对象

首页围绕一个核心对象展开：

> 大能量球

大能量球承担三种角色：

- 今日精力值展示
- 当前状态主视觉
- 活动记录主入口

## 8.2 主视觉

首页优先展示：

- 当前精力值数字
- 能量球 / 能量条状态
- 轻量今日概览

首页不常驻展示“当前更适合做什么”。方向建议只在低精力提醒等场景出现。

## 8.3 备用记录入口

第一版保留一个低优先级备用记录入口。

要求：
- 很不显眼
- 不占首页主视觉位置
- 不挤压能量球和今日概览空间
- 视觉权重明显低于能量球手势入口

备用入口只用于降低新手学习成本和误操作成本，不改变能量球滑动记录的主入口地位。

# 9. 活动记录

## 9.1 记录原则

第一版以实时记录为主。

产品希望推动的是：

> 做完一段事情，顺手直接记录。

第一版不支持补记。

## 9.2 手势流程

主流程：

```text
按住能量球 → 滑向大类 → 滑向子类 → 滑向时间档位 → 松手完成记录
```

要求：
- 尽量一笔完成
- 手指不离开屏幕
- 子类确认采用轻微吸附
- 允许回滑重新选择

## 9.3 时间档位

第一版使用固定时间档位：

- 15 分钟
- 30 分钟
- 45 分钟
- 60 分钟
- 90 分钟
- 120 分钟

不使用连续刻度。

## 9.4 即时反馈

记录完成后：

- 能量球立即变化
- 精力值数字立即变化
- 首页概览动态更新
- 给出一行轻量说明

反馈以数值变化为主，文案为辅。

## 9.5 撤销

记录完成后反馈条显示约 5 秒。

5 秒内用户可以一键撤销。

撤销后：
- 删除该条记录
- 回滚本次精力变化
- 从今日概览中移除对应影响
- 不进入校准反馈
- 不进入模型学习

超过 5 秒后，第一版不提供单条记录详情修正。

---

# 10. 今日概览与当日总览

## 10.1 首页今日概览

首页包含轻量今日概览。

规则：
- 只显示今天已有记录的大类
- 显示时间 + 精力变化
- 使用具体精力数值
- 按精力影响大小排序
- 不区分正负，只看影响大小

第一版不强制点击进入复杂分类详情，后续可预留入口。

## 10.2 当日总览详情

第一版包含当日总览详情。

定位：
- 第二层查看
- 不压在首页主区域
- 从首页今日概览进入

内容边界：
- 展示今天整体时间 / 精力分布
- 展示核心汇总指标和各大类分布
- 不深钻复杂分类详情
- 不做复杂曲线
- 不做时间轴

---

# 11. 低精力与透支提醒

## 11.1 阈值

第一版采用固定阈值：

- 剩余精力低于当天初始精力的 50%：中低精力
- 剩余精力低于当天初始精力的 25%：低精力
- 剩余精力低于 0：透支

后续可逐步转为个人动态阈值。

## 11.2 展示规则

- 只在首页能量球下方或附近轻量出现
- 不弹窗
- 不阻断记录
- 同一生活日内，同一档位只提醒一次
- 用户可以手动关闭当前提示

## 11.3 内容原则

- 文案保持中性
- 不评价用户表现
- 不制造失败感
- 推荐方向只到大类，不推荐具体任务

透支状态：
- 不使用大红色强警告
- 使用低饱和警示色
- 使用“透支”标签
- 文案采用“当前负荷已超过今日储备”一类中性表达

---

# 12. 昨日结果与轻详情

## 12.1 昨日提示

第二天首次打开时，展示一句昨日总结。

规则：
- 只出现一次
- 用户关闭后当天不再出现
- 作为轻量条展示
- 不弹窗
- 不阻断早间确认
- 不阻断首页记录

## 12.2 昨日轻详情

用户可从昨日提示展开昨日轻详情。

第一版内容边界：
- 昨日初始精力
- 昨日最终剩余精力
- 昨日总消耗 / 总恢复
- 各大类时间 + 精力影响
- 3 个以内状态标签

昨日详情保持轻量，不做复杂报告。

## 12.3 昨日标签

标签要求：
- 数量控制在 3 个以内
- 偏状态结果型，而不是原因型
- 表达中性
- 采用固定标签 + 一句短解释

# 13. 近 7 天趋势与周调整

## 13.1 近 7 天趋势

第一版只保留核心趋势信息：

- 个人基准线变化
- 每日最终剩余精力
- 低精力 / 透支次数

不做复杂图表分析。

入口：
- 不常驻首页
- 从周调整页或设置 / 数据入口进入

## 13.2 周调整

每累计 7 个有效使用日，系统评估个人基准线是否需要调整。

周调整页面原则：
- 先给结论，再看原因
- 只调整每日初始精力基准
- 不直接暴露活动消耗系数
- 第一版只展示轻量原因摘要
- 不做完整原因展开和详细趋势解释

## 13.3 提示时机

周调整提示在累计 7 个有效使用日后的第二天首次打开时出现。

不在用户刚完成一次活动记录后弹出。

用户可以暂时关闭周调整提示。

如果本次不处理：
- 保持原个人基准线不变
- 下次打开时可以再轻提醒一次

# 14. 校准期与个性化

## 14.1 校准期

第一版校准期为 7 个有效使用日。

校准期不是自然连续 7 天。

校准期内：
- 系统使用默认规则启动
- 通过记录与少量抽样反馈理解用户模式
- 抽样反馈每天最多 1～2 次
- 只在高影响记录后出现
- 同一天内两次抽样之间至少间隔一段时间
- 用户可以跳过反馈

## 14.2 稳定期

校准期结束后进入稳定期。

稳定期内：
- 系统减少主动询问
- 更多依赖记录和趋势判断
- 用户仍可通过设置和规则修改保留控制权

## 14.3 个性化模型

第一版采用可解释的规则算法。

规则：
- 前期默认规则启动
- 后期按子类学习用户趋势
- 单次修改不直接改变模型
- 系统学习趋势，不学习偶发异常

算法细节见《精力值算法规则初稿》。

# 15. 设置

第一版设置分为两层：

## 15.1 常用设置

- 修改个人基准线
- 动态学习 / 个性化调整开关
- 查看新手引导

动态学习关闭后：
- 不再自动调整个人模型
- 不再给出基于趋势的个人基准线调整建议
- 普通记录计算仍保留
- 手动基准线仍保留
- 等级映射仍保留

## 15.2 高级规则

- 修改等级到精力值的映射
- 恢复默认规则
- 规则变更后重算最近 7 个有效使用日

等级映射入口默认折叠，不在新用户主流程里强调。

## 15.3 本地数据提示

第一版不做账号登录和云同步。

设置页需要轻量提示：

> 第一版数据仅保存在本机，卸载或换机可能导致数据丢失。

# 16. 新手引导

第一版必须包含新手引导。

新手引导控制在 4 页：

1. 产品理念  
   说明这是精力值系统，不是任务管理工具。

2. 100 基准线  
   说明 100 是基准线，不是上限。

3. 活动影响  
   说明同样 1 小时，不同活动产生不同精力影响。

4. 能量球手势演示  
   演示如何从能量球滑出完成记录，并简短带过校准期和用户控制权。

设计原则：
- 每页只讲一个核心概念
- 不使用长篇说明
- 尽量用例子解释
- 保留后续重新查看入口

# 18. 第一版暂不做

第一版不做：

1. 账号登录 / 云同步
2. 社交功能
3. 排行榜
4. 任务清单 / 待办系统
