# 1. 背景与问题

阶段 16 已完成 MVP-A 的业务、数据与备份闭环。当前主要风险不再是“功能缺失”，而是
日常使用成本和界面主次关系仍不足以支撑长期自用。

2026-08-09 的代码与 Pixel_7 模拟器审计确认：

1. 首页同时展示晨间确认、能量球、活动列表、四个工具入口、历史卡片和调试横幅，偏离
   “单核、安静、围绕能量球生长”的设计总纲；
2. 点击式活动记录为“大类 → 子类 → 时长 → 完成时间 → 保存”，刚结束的活动也必须经过
   完成时间步骤；
3. 每日实际状态按钮单击后立即持久化，没有独立确认步骤；
4. 活动删除单击后立即逻辑删除，没有确认或撤销；
5. 径向手势时长层只需停留 160ms，比大类层更容易误确认；
6. 每日实际状态入口虽存在，但真实数据中 6 个有效日的实际状态覆盖仍为 `0 / 6`，说明
   入口位置和出现时机尚未形成自然习惯；
7. 实际状态五档使用同一种高权重天蓝按钮，没有落实低饱和色温轴；
8. 调试横幅覆盖首页底部，200% 字体时会明显遮挡主内容；
9. 部分返回、关闭图标没有可朗读名称，显式动画也未全部尊重减少动态效果。

审计问题仍作为产品待办依据，但阶段 17 本轮不再同时处理整条每日流程，只优化径向记录的
操作稳定性，以及与现有界面直接相关的视觉、动效、触觉和无障碍质量：

```text
长按能量球 → 稳定选择大类 → 稳定选择子类 → 稳定选择时长 → 松手记录
```

本轮不以增加功能数量或重排首页为目标，而以降低径向手势误触、补齐既有动效与触觉语义、
提高动态字体和辅助技术下的可用性为目标。

# 2. 产品原则

阶段 17 的所有实现必须遵守以下优先级：

1. 稳定高于速度：手势确认必须允许用户停稳和纠正，不能以更短等待换取误选；
2. 首页结构保持不变：本轮不得移动、隐藏或合并首页现有功能；
3. 点击入口始终完整可用：径向手势仍是可选加速路径，不得成为唯一入口；
4. 动效表达因果：只强调能量球、手势层级、选择确认和保存反馈；
5. 中性叙事：不以红色、警报或失败感强化精力变化；
6. 无障碍不是兜底模式：动态字体、减少动态效果、语义标签和 48dp 触控面积与默认体验同时设计；
7. 视觉延续既有方案：颜色、光晕、流体和弹簧以外观规格及 HTML 原型为准，不另起视觉体系。

若通用 UI 建议与项目既有视觉规格冲突，以项目的“呼吸流体”设计令牌和 HTML 原型为准。
不得引入新的通用蓝色主题、拟物阴影体系或第三套视觉语言。

# 3. 目标与非目标

## 3.1 目标

1. 径向手势降低灵敏度，所有阈值集中配置并具备测试；
2. 增加选择滞回与速度门槛，快速掠过、轻微抖动和未 ready 松手不得误记录；
3. 径向菜单的层级、颜色与动画继续复现 HTML 小样和“呼吸流体”外观规格；
4. 现有实际状态五档视觉对齐项目色温轴，但不改变其保存流程；
5. 补齐本轮所触及控件的触觉映射、减少动态效果和语义标签；
6. 保持首页信息结构、点击式记录流程、业务计算、数据结构、备份格式和生活日边界不变；
7. 通过自动化测试与 Pixel_7 模拟器验收，真机验收继续延后到 MVP-B 完成后。

## 3.2 非目标

- 不修改精力算法、活动规则值、恢复上限或档位定义；
- 不修改 Drift 表结构、JSON schemaVersion 或备份恢复格式；
- 不进入 MVP-B，不生成基准线或活动参数建议；
- 不新增账号、云同步、系统通知或后台定时任务；
- 不重写能量球 Fragment Shader / CustomPainter；
- 不简化首页，不移除首页活动列表、历史卡片、工具入口或调试横幅；
- 不新增统一“回顾” Sheet 或首页上下文插槽；
- 不实现活动删除撤销、实际状态二次确认或此刻校正错误反馈；
- 不缩短点击式活动记录步骤，不改变完成时间与保存逻辑；
- 不进行完整设置页信息架构重构；
- 不删除点击式记录入口；
- 不在模拟器阶段宣称完成真机手势 18/20 验收；
- 不新增新的活动大类、子类或时长档位；
- 不把“此刻校正”与“每日实际状态”合并为同一种数据。

## 3.3 与既有规格的裁决

本 Spec 经用户确认后，对以下交互细节形成有意识的局部修订：

| 既有约定 | 阶段 17 裁决 | 原因 |
|---|---|---|
| 径向手势长按 120ms 激活 | 默认候选提高到 200ms，并允许模拟器调优后回写 | 已收到“过于灵敏”的真实使用反馈 |
| 每日实际状态点击档位后直接保存并揭示 | 本轮保持；二次确认方案转入待办 A | 避免本轮同时改动数据写入流程 |
| 首页工具带为今日概览 / 实际状态 / 设置 | 保持现状 | 用户确认当前首页无需简化 |
| 首页直接展示当天活动与历史卡片 | 保持现状；原回顾 Sheet 方案仅作待办 C 参考 | 不再默认假设首页减法更符合真实自用需求 |
| 点击记录包含独立完成时间步骤 | 本轮保持；缩短方案转入待办 B | 本轮只解决径向手势、视觉与无障碍 |

本轮唯一立即生效的交互裁决是径向手势调优。A / B / C 的内容不构成本轮实现或验收要求，
后续如重新启用，必须先按届时真实使用反馈复审，不得直接照搬。

# 4. 首页信息架构（保持现状，原方案转入待办 C）

> 本章不在阶段 17-D 实施。首页当前结构继续作为产品现状；以下原提案只保留为待办材料，
> 不构成本轮开发、测试或验收依据。

## 4.1 首屏结构

首页从上到下固定为：

1. 晨间状态入口；
2. 能量球；
3. 初始估计与当前档位短标签；
4. 唯一上下文插槽；
5. 点击式记录 `+`；
6. 低权重工具带；
7. 底部安全留白。

首屏不再常驻：

- “今天的记录”标题与活动列表；
- 独立历史总结卡片；
- 最近 7 个有效日按钮；
- Stage 调试横幅。

这些内容统一从“回顾”入口展开。用户仍可从回顾层编辑、删除当天活动，不减少纠错能力。

## 4.2 唯一上下文插槽

能量球与 `+` 之间最多显示一个上下文行动。优先级从高到低为：

1. 刚跨入新精力档位的估计提醒；
2. 当天已有至少一条有效活动且尚未保存每日实际状态时的实际状态提示；
3. 当天已保存每日实际状态时的轻量状态摘要；
4. 无内容。

具体规则：

- 撤销条继续显示在系统 Snackbar 区域，不占上下文插槽；
- 精力提醒被关闭或按去重规则不再显示后，插槽可显示实际状态提示；
- 实际状态提示文案使用“今天结束前，留一次实际感受”，不使用未完成、遗漏或警告措辞；
- 已保存状态只显示“实际状态 · 已记录”，点击后可以修改；
- 没有活动时不主动催促每日实际状态，但低权重入口仍可从工具带或回顾层到达；
- 插槽状态切换必须保持能量球和 `+` 的中心轴不跳动，允许插槽在预留高度内淡入或弹性展开。

## 4.3 低权重工具带

工具带只保留三个等宽或视觉等权入口：

1. `回顾`：打开今日记录、今日概览和历史摘要；
2. `此刻校正`：记录相对估计的即时感受；
3. `设置`：进入设置页。

每日实际状态由上下文插槽承担主要入口；当尚无活动、上下文插槽为空时，回顾层仍必须提供
“记录今日实际状态”入口，确保功能始终可达。

## 4.4 回顾 Sheet

回顾使用一个可滚动 Bottom Sheet，不新建底部导航或传统多页面结构。内容顺序为：

1. 今日摘要：活动数、总时长、当前估计；
2. 今日分类概览：仅在有活动时显示；
3. 今日活动列表：支持编辑与删除；
4. 每日实际状态：未记录时为轻入口，已记录时显示文字状态；
5. 上次记录日总结；
6. 最近最多 7 个有效日入口。

空状态规则：

- 今日无活动时不展示空分类卡、不展示“按变化总量排序”说明；
- 只显示一句“今天还没有活动记录”和一个低权重“记录活动”动作；
- 历史存在时仍可继续向下查看历史；
- 回顾 Sheet 必须支持系统返回、下滑关闭和明确关闭按钮中的至少两种退出方式。

# 5. 点击式活动记录（待办 B，本轮不实施）

> 本章保留原优化设想，但阶段 17-D 不改变点击式记录步骤、完成时间入口或保存方式。

## 5.1 新建标准路径

新建活动的标准路径调整为三层：

```text
大类 → 具体活动 → 时长
```

用户点击时长后立即以当前 `_completedAt` 保存。首次打开时 `_completedAt = now`，因此标准路径为：

```text
点击 + → 选择大类 → 选择具体活动 → 选择时长并保存
```

从点击 `+` 到保存总计最多 4 次点击。

保存前必须已在时长选项上展示阶段 15 的“预计实际变化”；用户不是在未知变化下提交。

## 5.2 完成时间次级入口

Sheet 标题区下方常驻一个低权重时间入口：

`完成时间 · 刚刚`

点击后原地展开：

- 刚刚；
- 15 分钟前；
- 30 分钟前；
- 1 小时前；
- 2 小时前；
- 自定义时间。

选择后返回原记录层级，不增加正式步骤编号。预估变化必须使用更新后的完成时间重新计算。

规则：

- 预设不能跨出当前生活日；
- 自定义时间不能晚于当前时间；
- 自定义时间不能落入已结算生活日；
- 时间选择取消后保留原值；
- 加载新预估期间可显示“正在计算”，但不能把旧时间的结果冒充新结果。

## 5.3 编辑路径

编辑不是高频新建路径，不允许因为选择时长而自动提交。编辑 Sheet：

1. 加载原活动的大类、子类、时长和完成时间；
2. 用户可以逐层修改；
3. 修改时长后进入或保留在可检查状态；
4. 只有点击明确的 `保存修改` 才写入；
5. 关闭有未保存修改的编辑 Sheet 时，提示“放弃修改 / 继续编辑”；
6. 没有实际变化时，`保存修改` 禁用或直接关闭但不得重复写入。

## 5.4 Sheet 稳定性

- 三个新建层级使用同一 Sheet 容器；
- 标题、返回、关闭和时间入口位置不随层级明显上下跳动；
- Pixel_7 上层级切换时标题顶部位置差不超过 8dp；
- 内容不足时保留稳定空间，内容过多时只让内容区滚动；
- 200% 字体时允许 Sheet 增高和滚动，不压缩触控目标；
- 每个选项最小触控区域 48 × 48dp，选项间距至少 8dp；
- 所有选项在按下后 100ms 内出现视觉反馈。

## 5.5 保存与撤销反馈

新建保存成功后：

1. Sheet 收回；
2. 光点入球或简化完成反馈；
3. 数字更新；
4. 显示 5 秒撤销条；
5. 撤销条结束后才允许精力提醒出现。

撤销条继续展示：

`{子类} {时长} · 估计 {实际应用变化}`

失败时：

- Sheet 保持打开；
- 保留当前选择；
- 在主动作附近显示可理解错误和重试路径；
- 不播放完成触觉或成功动画；
- 不显示内部异常、ID 或数据库信息。

# 6. 活动删除与撤销（待办 A，本轮不实施）

> 本章不进入本轮开发，不新增恢复用例，也不改变当前删除行为。

## 6.1 用户流程

活动从回顾 Sheet 删除后：

1. 该行立即从有效列表移除；
2. 当日估计与概览重新计算；
3. 显示 5 秒撤销条：`已删除 {子类} {时长} · 撤销`；
4. 点击撤销后恢复原记录并完整重放当日派生结果；
5. 撤销窗口结束后保持逻辑删除。

本阶段优先使用撤销，不增加阻断式确认弹窗。编辑与删除图标仍需保持至少 8dp 触控间距。

## 6.2 恢复规则

新增领域用例 `restore(activityId)` 或等价命名，必须满足：

- 只恢复当前未结算生活日的逻辑删除记录；
- 原记录 ID、创建时间、分类、时长、规则版本保持不变；
- `status` 恢复为 active，`deletedAt` 清空，`updatedAt` 更新；
- 恢复后按 `completedAt, createdAt, id` 完整重放；
- 重复恢复同一 active 记录幂等返回，不重复产生记录；
- 找不到记录、记录属于已结算日或记录不属于当前生活日时安全失败；
- 恢复失败时显示“暂时无法撤销，请重试”等用户可理解提示；
- 不直接操作 DAO 绕过业务准备、生活日和结算检查。

## 6.3 并发与时序

- 同一记录的删除、恢复、编辑继续走现有串行写入队列；
- 删除后立刻编辑不可达；
- 撤销恢复完成前按钮禁用，避免连续点击；
- 记录创建撤销和删除撤销使用同一反馈组件，但调用不同业务用例；
- 连续产生多个撤销反馈时进入队列，每个 5 秒窗口从实际显示时开始计时；
- 撤销反馈显示期间，普通成功提示和精力提醒排队等待，不得覆盖当前撤销条；
- 队列中的记录必须携带自己的 mutation ID，不得让后一个撤销操作作用于前一条记录；
- Snackbar 被其他反馈替换不能自动恢复记录，只有明确点击“撤销”才恢复。

# 7. 每日实际状态（交互待办 A；五档视觉纳入 D）

> 7.1 与 7.3 本轮不实施；7.2 五档视觉属于阶段 17-D，可在不改变保存时序的前提下实现。

## 7.1 选择、确认、揭示

流程改为：

```text
选择实际状态 → 确认并保存 → 揭示系统估计 → 完成
```

详细规则：

1. 第一次点击五档中的任一档只更新 Sheet 内临时选择，不写数据库；
2. 选中后出现或启用主动作 `确认并揭示`；
3. 再次选择其他档位只替换临时选择；
4. 点击 `确认并揭示` 后按钮进入 loading，其他选择禁用；
5. 保存成功后才显示系统当时估计和描述性差异；
6. 保存失败保留临时选择并显示重试，不揭示估计；
7. 关闭未确认的 Sheet 不产生数据；
8. 成功揭示使用一次 `lightImpact`，不使用重震；
9. 当天已有每日实际状态时进入修改模式，预选原状态，但仍需明确保存修改；
10. 昨日补充沿用相同确认流程，但已经存在昨日状态时不得覆盖。

## 7.2 五档视觉

未选中状态统一使用：

- `bg/overlay` 或透明 raised surface；
- `line` 描边；
- `text/primary` 文字；
- 不使用大面积高饱和填充。

选中后使用对应色温 12%～18% 透明背景和清晰描边：

| 实际状态 | 选中色来源 | 必须同时显示 |
|---|---|---|
| 耗尽 | 灰紫 / 薄雾端 | “耗尽”文字 + 选中语义 |
| 偏低 | 暖橙 | “偏低”文字 + 选中语义 |
| 尚可 | 琥珀 | “尚可”文字 + 选中语义 |
| 良好 | 天青 | “良好”文字 + 选中语义 |
| 充足 | 青绿 | “充足”文字 + 选中语义 |

# 9. 径向手势降低灵敏度

## 9.1 参数集中化

手势参数集中为不可变配置对象，例如 `RecordGestureTuning`，UI 不再散落魔法数字。

模拟器阶段默认候选值：

| 参数 | 当前 | 阶段 17 候选值 | 含义 |
|---|---:|---:|---|
| activationDelay | 120ms | 200ms | 长按后进入径向菜单 |
| categoryDwell | 280ms | 300ms | 大类与子类停留确认 |
| durationDwell | 160ms | 300ms | 时长停留确认 |
| backCooldown | 220ms | 260ms | 层级变化后允许回滑 |
| newNodeHitSlop | 16px | 12px | 新节点进入范围 |
| stickyNodeHitSlop | 30px | 28px | 当前节点保持范围 |
| centerBackRatio | 0.55 | 0.48 | 回到球心触发回退的范围 |

以上是模拟器起始值，不是永久规则。实现时允许依据模拟器观察在本 Spec 中回写最终值。

## 9.2 选择滞回

- 进入节点后，在手指明显离开 `stickyNode` 范围前不切换到邻居；
- 从当前节点切换到新节点必须先离开旧黏附区，再进入新命中区；
- 移动速度明显过快时不立即启动 dwell，稳定后再计时；
- dwell 进度与当前候选节点视觉同步；
- 进入 ready 状态后，松手才提交；
- 未达到 ready、完成原点无效、超时或系统取消均不得写入；
- 层级切换后的第一次回滑不得因手指仍在中心附近而立即退回；
- 系统返回、应用失焦或 Overlay 被移除时必须清理 Timer 和状态。

## 9.3 模拟器与真机边界

阶段 17 在模拟器验收：

- 节点命中、滞回、停留、回滑、取消和超时状态机；
- 20 次脚本化选择不出现错误记录；
- 快速掠过节点不确认；
- 停稳后可以确认；
- 点击式入口始终可用。

真机验收继续延后到 MVP-B 完成后统一执行：

- 真实手指遮挡；

- 60fps；

- 20 次独立任务至少成功 18 次。

# 10. 动效与触觉

## 10.1 动效边界

本阶段不重写能量球绘制，也不改变首页布局，只统一现有高频流程的动效语义：

- 记录层级切换：snappy，但标题位置不移动；
- 记录完成光点：bouncy；
- 实际状态选中：轻量 state layer，不缩放布局；
- 揭示：gentle + 细线生长；
- 普通设置与说明文字不增加入场动画。

动效实现优先复用外观规格的 gentle / snappy / bouncy 三档弹簧。若 Flutter 组件无法直接使用
SpringSimulation，必须记录等价参数和原因，不允许继续增加互不相关的 duration / curve。

## 10.2 触觉映射

阶段 17 补齐以下已定义语义：

| 时机 | 触觉 |
|---|---|
| 点击式活动保存成功 | mediumImpact ×1 |
| 现有活动创建撤销成功 | lightImpact ×1 |
| 晨间确认点亮 | lightImpact ×2，间隔约 80ms |
| 每日实际状态揭示 | lightImpact ×1 |
| 精力首次跨入低 / 透支档 | heavyImpact ×1 |
| 径向节点吸附 | selectionClick |

失败、取消、返回和预览加载不得播放成功触觉。重震仍只服务精力档位跨越。

## 10.3 减少动态效果

当 `MediaQuery.disableAnimationsOf(context)` 为 true：

- 停止能量球呼吸和粒子级流动；
- 关闭光点飞行、缩放和 stagger；
- Sheet 内容直接切换或仅做极短淡入；
- 保留保存、错误和选择状态的必要反馈；
- 触觉仍遵循系统触觉设置，不用动画替代文字状态。

# 13. 技术设计

## 13.1 组件拆分

阶段 17-D 只允许为手势配置、状态机测试和复用动效做必要的小范围拆分，建议但不强制使用：

```text
features/activity/application/
  record_gesture_tuning.dart

features/activity/presentation/
  record_gesture_controller.dart
  record_gesture_overlay.dart
```

约束：

- 不因拆分改变首页 Widget 树的信息结构；
- 不建立第二套业务状态或 HomeViewModel；
- 手势层只维护候选、停留、ready、回退和取消等临时 UI 状态；
- 松手提交仍调用现有创建活动 application use case；
- 动画帧不得触发当前日重放或数据库读取；
- 所有 Timer、Ticker 和 AnimationController 必须在取消或 dispose 时清理。

## 13.2 手势配置与状态机

新增不可变 `RecordGestureTuning` 或等价配置，作为阈值的唯一来源。状态机至少显式区分：

- idle；
- activating；
- selectingCategory；
- selectingSubcategory；
- selectingDuration；
- ready；
- cancelled / timedOut。

状态迁移必须可在不启动 Flutter 帧动画的条件下测试。UI 只消费状态结果并绘制，不复制 dwell、
滞回或回退判断。

## 13.3 命中、滞回与速度门槛

- 新候选使用 `newNodeHitSlop`；已选节点使用更宽的 `stickyNodeHitSlop`；
- 指针必须离开旧黏附区后才允许切换到新节点；
- 高于速度门槛的移动只更新指针位置，不开始 dwell；
- 速度降低并稳定命中后重新开始 dwell；
- 每次层级推进重置候选与回退冷却；
- 未进入 ready 的松手、系统取消、失焦和超时均不得调用写入用例。

## 13.4 动效、触觉与无障碍边界

- 动效继续复用 gentle / snappy / bouncy，不新建第四套节奏；
- `disableAnimations` 下跳过装饰动画，但保留清晰的文字和选中状态；
- 每个径向节点必须提供名称、层级和选中状态语义；
- selectionClick 只在稳定吸附到新节点时触发，抖动期间不得重复震动；
- 点击式入口继续作为完整替代路径，不因手势改造退化。
