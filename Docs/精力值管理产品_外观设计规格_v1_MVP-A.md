## 0. 文档状态

- 版本：1.0
- 日期：2026-07-25
- 承接：《精力值管理产品 PRD v2（MVP-A）》《技术方案 v2（MVP-A）》
- 参考原型：`../prototypes/PowerManager_动效小样.html`
- 已确认方向：方向 A「呼吸流体」深色视觉 + 通用动效系统全套 + 触觉反馈跟满
- 已确认决策：
  1. 今日概览默认隐藏，首页上滑浮现（首页只留能量球）。
  2. 点击式记录入口为能量球正下方一颗小「+」；能量球手势通过真机验证转正后，「+」降低视觉权重但保留。
  3. 估计透支使用低饱和灰紫「薄雾态」，不使用红色警示。

设计总纲一句话：

> 一个安静的、有生命感的单核界面——所有信息围绕能量球生长，所有操作从能量球出发，页面之间不是“切换”而是“展开”。

# 1. 设计原则

1. 单画布结构：早间确认、记录流程、概览、总结均以浮层 / 卡片展开 / 球体形变出现，尽量不使用传统多页面 push 跳转。元素在动画中保持连续性。
2. 中性叙事：颜色、文案、动效均不制造“报警感”和“失败感”。档位变化是“天色变了”，不是“警报响了”。
3. “估计精力”标签常驻：视觉上不允许估计值冒充实际状态（双轨分离的界面落实）。
4. 100 不是上限：任何视觉元素（进度条、液面、爆条特效）都不得暗示 100 封顶。
5. 表现力集中在能量球一个对象上，其余界面保持极简。

# 2. 设计令牌（Design Tokens）

## 2.1 底色体系（三层空间深度）

| 令牌 | 值 | 用途 |
|---|---|---|
| bg/base | #0D1017 | 全局底（冷蓝夜空灰，非纯黑） |
| bg/raised | #151A24 | 卡片、sheet |
| bg/overlay | #1C2230 | 浮层、径向菜单节点 |
| text/primary | #E8ECF4 | 主文字（非纯白，降眩光） |
| text/secondary | #8A93A6 | 辅助说明、“估计精力”标签 |
| line | #FFFFFF @ 8% | 分割线、描边 |

## 2.2 能量色温轴（全局唯一取色来源）

精力档位不做三段红黄绿跳变，而是一条连续色温轴。能量球、提醒条、概览 delta 数字、实际状态按钮均从此轴取色，档位间用 lerp 连续插值。

| 档位（相对当日初始估计） | 主色 | 渐变辅色 | 意象 |
|---|---|---|---|
| ≥ 初始 80% | #5EEAD4 青绿 | #A7F3D0 | 清晨水面 |
| 50% ~ 80% | #7DD3FC 天青 | #5EEAD4 | 平静 |
| 25% ~ 50%（中低） | #FCD34D 琥珀 | #7DD3FC | 黄昏 |
| 0 ~ 25%（低） | #F0A868 暖橙 | #B08968 | 烛光 |
| < 0（估计透支） | #9B8AB8 灰紫 | #6E6284 | 薄雾 |

透支色刻意为低饱和灰紫，延续 PRD“当前负荷已超过今日储备”的中性表达。

## 2.3 文字

- 数字字体：带 tabular figures（推荐 Manrope，或 Roboto Flex 开启 tnum），保证数字滚动时不抖动。
- 球心大数字：64pt / SemiBold。
- “估计精力”标签：13pt / text/secondary，常驻于数字上方。
- 正文：15pt，行高 1.5。
- 字重全局仅三档：Regular / Medium / SemiBold。

## 2.4 形状与间距

- 圆角：卡片 20，sheet 顶部 28，按钮 14。
- 间距：4 的倍数栅格，页面左右留白 20。

# 3. 能量球规格

球体由四层叠加，绘制在单个 CustomPaint / fragment shader 内：

## 3.1 四层结构

1. 外光晕：径向渐变柔光，半径约球体 1.6 倍。透明度随精力衰减：充足 35% → 透支 12%。这是“房间里唯一光源”的来源。
2. 流体本体：直径约屏宽 58% 的圆。内部为 2~3 个缓慢漂移的噪声渐变团（shader 内两层 simplex noise 叠加）。流速参数 flowSpeed 随精力从 1.0 降至 0.35——精力低时流动变“粘稠”。
3. 呼吸：整体半径以 5.5s 周期正弦缩放 ±1.8%；透支时周期拉长至 8s、幅度降至 ±0.8%（呼吸变浅）。
4. 数字层：球心估计值 + 上方常驻“估计精力”小标签。数字变化用滚轮 rolling（逐位滚动，约 120ms/位，弹簧收尾）。

## 3.2 关键状态

- 尚未处理晨间确认：球体存在但灰暗、流速极慢，数字位显示呼吸的占位符。
- 已跳过晨间确认：使用“个人基准线 + 上一生活日短期修正”生成并显示初始估计；若没有可用的上一生活日修正，则该项按 0 计算。球体保持弱点亮和较低流速，并常驻小标签“未进行晨间确认”，但不阻断活动记录。
- 完成或后续补做晨间确认：按正式规则重新派生当天估计，并播放一次约 800ms 的“点亮”：光晕扩张 → 当日色温注入 → 数字滚动至新的初始估计。每天最多播放一次完整开机仪式；同一生活日后续编辑仅播放较弱的数值更新反馈。
- 估计透支（薄雾态）：球体不消失不缩小；本体透明度降至 45%，噪声颗粒变大变稀，负数照常显示，旁挂小标签“估计透支”。存在但稀薄，与“透支只是估计结果”的产品语义对齐。
- 高于 100 / 高于初始：无爆条特效，仅色温更清亮、光晕更足。

# 4. 首页结构（单画布）

自上而下：

1. 状态栏留白。
2. 晨间下拉区：当日未确认时顶部有一条细微下拉暗示线；下拉展开早间确认（见 6.5）。
3. 能量球：视觉中心，位置略高于屏幕几何中心（约 42% 高度处）。
4. 提醒条插槽：低精力提醒在此弹性浮现，平时零高度不占位。
5. 点击式记录入口“+”：球正下方一颗小圆钮。MVP-A 期间为主路径之一，尺寸适中可发现；手势入口通过 20 次 18 成功验收转正后，降为更小、更低对比度。
6. 底部工具带：极轻的文字入口（今日概览上滑提示 / 实际状态 / 设置），视觉权重最低。

今日概览：默认隐藏。首页上滑（或点底部提示）→ 概览以底部 sheet 弹性浮现。每条大类卡片：左侧大类名 + 总时长，右侧净变化数字（取色温轴颜色，正值带 +），按 grossDelta 排序、展示 netDelta（与 PRD 7.4 一致）。卡片点击原地长大为当日总览详情（容器变形，不跳页）。

# 5. 通用动效系统

## 5.1 三档全局弹簧（全 App 只用这三档）

| 名称 | stiffness | damping | 用途 |
|---|---|---|---|
| gentle | 170 | 26 | sheet 展开、卡片容器变形、提醒条 |
| snappy | 280 | 22 | 径向菜单吸附、撤销条出入 |
| bouncy | 220 | 16 | delta 光点入球等小元素 |

原则：全部用物理弹簧（SpringSimulation），禁止固定时长 + easeInOut 的“简单页面切换”式过渡。

## 5.2 容器变形代替页面跳转

概览卡片 → 详情、昨日总结条 → 轻详情，均为共享元素连续变形（Material container transform；Flutter 用 animations 包 OpenContainer 或手写 Hero + PageRouteBuilder）。

# 6. 五个核心动效场景编排

## 6.1 径向手势记录

- 按住球 120ms 后触发（防误触）。
- 4 个大类节点从球缘以 stagger 30ms 依次浮出（每个从 scale 0.85 + 透明 0 弹到位，snappy）。
- 手指滑入某节点 → 该节点放大 1.08 吸附 + 轻震；其余节点亮度降 40%。
- 确认大类后：大类环缩细退至外围成“面包屑”，6 个子类接力浮现；再进 6 个时长档位（15/30/45/60/90/120 排成弧）。
- 松手于时长档 → 所选项收束成光点飞入球体，完成记录。
- 中途松手 → 全部元素以 gentle 弹簧缩回球内（“水收回去”）。
- 回滑：手指退回球心附近 → 逆序回退一层（时长 → 子类 → 大类 → 取消）。
- 每层 10 秒无动作自动收回（沿用技术方案初稿状态机规则）。
- 吸附动画本身就是操作反馈，服务真机 18/20 验收。

## 6.2 记录完成反馈

光点入球 → 球体涨落一拍（scale 1.03 回落，bouncy）→ 数字滚动至新值 → 底部浮出 5 秒撤销条：

- 左侧轻文案：“自学 45 分钟 · 估计 −14”。
- 条底色从左至右缓慢褪色作倒计时可视化（不用数字倒数，零压迫感）。
- 右端“撤销”。
- 撤销窗口结束后才允许提醒条浮现（PRD 7.3 时序要求的动画编排落实）。

## 6.3 低精力提醒

- 不弹窗。提醒条插槽从高度 0 弹性展开（gentle）。
- 底色取当前档位色温 12% 透明度。
- 文案中性：如“估计已低于今日初始的一半”。
- 右端手动关闭。同日同档去重由 prompt_receipts 保证，动画层不管去重。

## 6.4 每日实际状态 · 揭示仪式

1. 整屏只有五档竖排大按钮（耗尽 → 充足）。按钮底色沿色温轴取色但饱和度压低，避免颜色诱导选择。
2. 选定 → 其余四档淡出下沉，所选项上移至屏幕上 1/3。
3. 停顿 250ms。
4. 系统估计从下方翻转浮现，两者之间生长一条细线，线上一句描述性差异（如“你的感受比系统估计更疲惫一些”）。
5. 全段约 1.2s。每天一次，仅次于早间点亮的第二仪式。防锚定产品逻辑（先选后揭示）由动画顺序保证。

## 6.5 晨间下拉

- 首页顶部下拉 → 晨间区域以橡皮筋阻尼展开。
- 四个问题单列大按钮，答一题自动弹性滚至下一题；答完的行收起为一枚小勾。
- 四题完成 → 区域回收 + 球体点亮动画。
- 跳过 = 不拉，或中途上滑收回，零惩罚、不阻断记录（PRD 4.1）。

# 7. 触觉反馈映射

| 时机 | 震动 |
|---|---|
| 径向菜单吸附到任一选项 | selectionClick（最轻） |
| 完成一次记录（松手瞬间） | mediumImpact ×1 |
| 撤销成功 | lightImpact |
| 球体点亮（早间完成） | lightImpact ×2，间隔 80ms |
| 跨入低精力 / 透支档位 | heavyImpact ×1（全 App 唯一重震） |
| 实际状态“揭示”瞬间 | lightImpact |

原则：重震只保留给档位跨越这一个语义，避免触觉通货膨胀。

# 8. Flutter 实现映射

- 流体层：FragmentProgram（Impeller 兼容的 fragment shader），uniform 传入 time / energyRatio / flowSpeed / colorA / colorB。档位变化即 uniform 插值，零 widget 重建。
- 呼吸与涨落：一个常驻 AnimationController + SpringSimulation。
- 径向菜单：独立 RecordGestureController 状态机（技术方案初稿 §9 已有）。手势层只产生临时选择，松手才调 CreateActivity——动画层与业务层边界在此。
- 容器变形：animations 包 OpenContainer，或手写 Hero + PageRouteBuilder。
- 数字滚动：AnimatedFlipCounter 或自绘。
- 触觉：HapticFeedback.selectionClick / lightImpact / mediumImpact / heavyImpact。
- 性能红线：动画帧不得触发当前日重放。派生结果 memoize 在 Riverpod provider，球体动画只消费缓存值；重放仅在写操作后发生。目标 60fps。

---

# 9. 无障碍与兜底

- 尊重系统 reduce motion：关闭呼吸与粒子级动效，保留必要的状态过渡。
- 点击式“+”入口提供与手势完全等价的记录能力（大类 → 子类 → 时长三步 sheet），兼顾无障碍与手势异常兜底。
- 所有色温档位同时有文字标签（中低 / 低 / 估计透支），不单靠颜色传达信息。

# 11. 已确认的跨文档决策

## 11.1 跳过晨间确认时的球体状态

已于 2026-07-25 确认采用以下口径：

- 晨间确认可以跳过，且不阻断活动记录；
- 跳过后仍使用“个人基准线 + 上一生活日短期修正”生成并展示初始估计；
- 此时不加入晨间综合状态修正，界面以弱点亮球体和“未进行晨间确认”标签明确数据上下文；
- 用户可在当前生活日内随时补做，补做后按正式规则重放当天活动并更新估计；
- 首次完成补做时播放完整点亮动效，之后编辑晨间答案只播放弱化更新反馈。

# 12. HTML 动效小样的参考边界

`../prototypes/PowerManager_动效小样.html` 是本规格的交互与视觉参考原型。Flutter 开发应优先学习并对照其整体气质、空间关系、动效节奏与状态反馈，而不是逐行翻译 HTML、CSS 和 JavaScript。

## 12.1 应当参考

- 首页深色单画布、能量球中心构图和低视觉权重工具带；
- 能量球光晕、流体、呼吸、数字和薄雾态的层次关系；
- 晨间下拉、点击式三步记录、径向手势记录和今日概览的展开方式；
- 光点入球、数字变化、5 秒撤销条、提醒条延后出现的反馈顺序；
- 每日实际状态先选择、后揭示系统估计的仪式感；
- 中性叙事、连续色温、不过度报警的整体表达。

## 12.2 不得以原型替代正式规则

- HTML 中的活动 delta、当前精力和恢复上限计算仅为演示占位；
- 原型没有承担 Drift 持久化、生活日 04:00 边界、结算、规则版本与幂等事务；
- 提醒去重、实际状态唯一性和历史只读等行为仍以 PRD、算法规则和技术方案 v2 为准；
- Flutter 实现不得为了复刻动画而让动画状态成为业务真相来源。

## 12.3 实现与验收方式

1. 先以 HTML 对照完成 Flutter 静态布局和基础交互原型。
2. 再将视觉组件连接 Riverpod 派生状态和正式应用用例。
3. 在 Pixel_7 模拟器对照首页、晨间、点击记录、概览、揭示和透支六种场景。
4. 阶段 10 及后续阶段先以 Pixel_7 模拟器和自动化测试验收；Android 真机的
   触觉、60fps、真实手指遮挡、小屏适配及 20 次任务统一延期到整个 MVP-B
   完成后执行。
5. 允许因 Flutter、Impeller、无障碍和性能约束调整实现技术，但视觉语义和交互顺序的变化必须回写本规格。
