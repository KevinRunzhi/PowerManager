# 精力值管理产品 MVP Backlog / 功能拆解

## 0. 文档说明

本文档用于把《精力值管理产品 PRD 定稿》拆解为第一版可开发、可验收的功能 Backlog。

相关文档：
- 《精力值管理产品 PRD 定稿》
- 《精力值算法规则初稿》

本文档不定义新产品规则，只承接 PRD 中已经确定的第一版范围。

---

# 0.1 术语约定

为避免开发和测试时混淆，本文档统一使用以下术语：

- 当日初始精力：生活日开始时的精力基准值
- 当前剩余精力：首页展示的实时剩余精力值
- 精力影响：一次活动实际应用到当前剩余精力上的变化值
- 理论变化值：按默认规则和个人修正计算出的原始变化值
- 实际应用值：考虑恢复上限后，真实作用到当前剩余精力的变化值
- 生活日：按次日 04:00 作为切换点的产品日期

---

# 1. MVP 目标

第一版 MVP 的目标是验证：

- 用户是否愿意以能量球作为主入口记录活动
- 用户是否能理解精力值、消耗、恢复、透支的基本关系
- 用户是否能通过每日记录获得状态认知
- 系统是否能基于 7 个有效使用日完成轻量校准
- 产品是否能在不做任务管理、不做复杂建议的前提下形成日常使用闭环

第一版不追求：
- 完整任务规划能力
- 复杂数据分析能力
- 复杂个性化算法
- 多端同步能力
- 高度可配置能力

---

# 2. 优先级定义

## P0：MVP 必须完成

没有该功能，产品闭环不成立。

## P1：MVP 应完成

属于第一版范围，应在 MVP 对外可用前完成；不一定阻塞最早的内部基础闭环联调。

## P2：可延后

可以进入第一版后的补充小版本，不阻塞 MVP 对外可用。

# 4. Backlog 拆解

## EPIC 1：新手引导

### US-1.1 首次进入展示新手引导

优先级：P0

用户故事：
作为首次使用用户，我希望先快速理解这个产品不是任务管理工具，而是精力值系统。

功能说明：
- 首次打开 App 时展示新手引导
- 新手引导共 4 页
- 用户完成或跳过后进入主流程
- 完成状态需要本地保存

输入：
- 是否首次打开
- 是否已完成新手引导

输出：
- 引导完成状态
- 进入早间确认或首页

验收标准：
- 首次打开时能看到新手引导
- 4 页内容分别对应产品理念、100 基准线、活动影响、能量球手势
- 用户可以完成引导
- 用户可以跳过引导
- 完成或跳过后再次打开不自动展示
- 设置中可以重新查看新手引导
- 首次完成新手引导后，早间确认允许使用默认选择快速开始，避免首次使用选择过载

### US-1.2 能量球手势演示

优先级：P1

用户故事：
作为新用户，我希望在真正记录前知道能量球应该怎么滑动。

功能说明：
- 在新手引导第 4 页展示能量球手势示意
- 说明能量球是主记录入口
- 简短带过校准期和用户控制权

验收标准：
- 用户能理解“按住能量球并滑动选择”的基本操作
- 文案不引入复杂规则
- 不要求用户在引导中完成真实记录

## EPIC 2：早间确认

### US-2.1 每个生活日首次打开展示早间确认

优先级：P0

用户故事：
作为用户，我希望每天开始时用很轻的方式告诉系统今天状态如何。

功能说明：
- 每个生活日首次打开时展示早间确认
- 早间确认不是强制门槛
- 用户可以跳过
- 跳过后当天不再强弹

输入：
- 当前生活日
- 当天是否已展示早间确认
- 当天是否已完成早间确认

输出：
- 早间确认记录
- 当日初始精力微调
- 当天早间确认展示状态

验收标准：
- 每个生活日首次打开会触发早间确认
- 用户可以完成 3 个输入项
- 用户可以跳过
- 跳过后当天不再强弹
- 跳过不影响进入首页和记录活动
- 跳过早间确认时，当日初始精力仍可基于个人基准线和短期修正生成

### US-2.2 早间确认输入项

优先级：P0

功能说明：
第一版包含 3 项：
- 综合状态：差 / 一般 / 好
- 今天可自由安排的时间：少 / 中 / 多
- 今天主要压力来源：学习为主 / 实践事务为主 / 都有 / 压力不大

验收标准：
- 三个问题均可选择
- 完成后生成当天早间确认记录
- 系统可基于选择计算早间微调
- UI 不要求用户填写任务或计划

### US-2.3 首页保留早间确认弱入口

优先级：P1

功能说明：
- 当天未完成早间确认时，首页提供弱入口
- 用户可以后续补做当天早间确认
- 补做后弱有效使用日可升级为标准有效使用日

验收标准：
- 未完成早间确认时可从首页进入
- 入口不抢占首页核心位置
- 完成后当天状态更新

## EPIC 3：首页能量球

### US-3.1 首页展示当前精力值

优先级：P0

用户故事：
作为用户，我希望一打开首页就知道今天还剩多少精力。

功能说明：
- 首页核心对象是大能量球
- 展示当前剩余精力值
- 根据剩余精力状态表现不同视觉状态
- 首页同时展示轻量今日概览

输入：
- 当日初始精力
- 当前剩余精力
- 今日活动记录

输出：
- 当前精力值展示
- 能量球状态
- 今日概览摘要

验收标准：
- 首页第一视觉焦点是能量球
- 当前精力值清晰可见
- 记录活动后数值即时更新
- 低精力和透支状态有明显但不强压迫的视觉差异

### US-3.2 能量球作为主记录入口

优先级：P0

功能说明：
- 用户从大能量球发起活动记录
- 能量球记录入口优先级高于其他入口

验收标准：
- 用户可以通过能量球进入记录流程
- 首页不出现更高权重的记录按钮
- 主流程不依赖备用入口

### US-3.3 低优先级备用记录入口

优先级：P1

功能说明：
- 首页保留一个非常低权重的备用记录入口
- 只用于降低新手学习成本和误操作成本
- 不改变能量球作为主入口的定位

验收标准：
- 备用入口可用
- 备用入口不占据首页主视觉区域
- 备用入口不挤压能量球和今日概览空间
- 备用入口视觉权重明显低于能量球

## EPIC 4：活动记录

### US-4.1 能量球滑动记录流程

优先级：P0

用户故事：
作为用户，我希望做完一段事情后，用一次快速滑动完成记录。

功能说明：
主流程：

```text
按住能量球 -> 滑向大类 -> 滑向子类 -> 滑向时间档位 -> 松手完成记录
```

支持：
- 一笔完成
- 手指不离开屏幕
- 子类轻微吸附
- 回滑重新选择

输入：
- 大类
- 子类
- 时间档位
- 当前生活日

输出：
- 活动记录
- 本次精力影响
- 更新后的当前剩余精力

验收标准：
- 用户能完成一条活动记录
- 记录中包含大类、子类、时长、时间、精力影响
- 记录完成后首页立即更新
- 不支持跨天补记
- 生活日归属以记录完成时刻为准
- 第一版不校验记录之间的时间重叠，按用户录入为准
- 只有滑到时间档位并松手，才算完成一次记录
- 松手时位于任何非时间档位层级，均视为取消
- 回滑按层级回退：时间档位 -> 子类 -> 大类 -> 取消
- 进入某层后 10 秒无动作自动取消本次手势

### US-4.2 活动分类选择

优先级：P0

功能说明：
第一版固定 4 大类，每类 5 个子类。

大类：
- 学习
- 实践 / 事务
- 休息恢复
- 娱乐消遣

验收标准：
- 所有 PRD 定义的子类都可选择
- 第一版不支持用户自定义子类
- 分类文案与 PRD 保持一致

### US-4.3 时间档位选择

优先级：P0

功能说明：
第一版使用固定时间档位：
- 15 分钟
- 30 分钟
- 45 分钟
- 60 分钟
- 90 分钟
- 120 分钟

验收标准：
- 用户只能选择固定档位
- 不提供连续刻度
- 记录保存准确时长

### US-4.4 记录完成即时反馈

优先级：P0

功能说明：
记录完成后：
- 能量球立即变化
- 精力值数字立即变化
- 今日概览动态更新
- 给出一行轻量说明

验收标准：
- 完成记录后无需刷新即可看到数值变化
- 反馈文案能说明本次影响
- 反馈不遮挡继续使用

### US-4.5 5 秒内撤销

优先级：P0

功能说明：
- 记录完成后反馈条显示约 5 秒
- 5 秒内用户可以一键撤销

撤销后：
- 业务上视为删除该条记录
- 回滚本次精力变化
- 从今日概览中移除对应影响
- 不进入校准反馈
- 不进入模型学习

验收标准：
- 5 秒内撤销有效
- 撤销后首页数值恢复
- 撤销后今日概览恢复
- 撤销记录不参与有效使用日、校准、模型学习
- 撤销记录统一采用逻辑删除：`status` 从 `active` 变为 `cancelled`，并写入 `cancelledAt`
- 所有业务查询、展示、结算、校准、模型学习、重算都必须只处理 `status = active` 的记录
- 撤销回滚必须基于实际应用值 `appliedDelta`
- 超过 5 秒后不提供单条记录详情修正

## EPIC 5：精力计算与生活日

### US-5.1 当日初始精力计算

优先级：P0

功能说明：
当日初始精力由三部分组成：

```text
当日初始精力 = 个人基准线 + 早间微调 + 短期修正
```

验收标准：
- 新用户个人基准线默认为 100
- 早间确认可影响当天初始精力
- 未完成早间确认时，当日初始精力可先按个人基准线和短期修正生成
- 当天后续补做早间确认时，需要重新计算当日初始精力和当前剩余精力
- 昨日透支可轻微影响第二天自动初始精力
- 计算过程可追溯
- 补做早间确认后，低精力提醒只允许向更轻方向撤回，不因补做触发更重档位的新提醒
- 同一生活日同档位已提醒状态保留，避免通过补做早间确认重复触发提醒

### US-5.2 默认活动规则配置

优先级：P0

功能说明：
- 第一版需要有一套默认活动精力影响规则
- 默认规则用于根据大类、子类、时长计算精力影响
- 个性化修正值只在默认规则基础上小幅调整

验收标准：
- 所有 20 个子类都有默认计算规则
- 所有 6 个时间档位都能计算结果
- 默认规则与代码实现分离，便于后续调整
- 默认规则变更后可触发最近 7 个有效使用日重算

### US-5.3 活动精力影响计算

优先级：P0

功能说明：
- 根据活动大类、子类、时长计算本次精力影响
- 消耗类活动通常减少精力
- 恢复类活动增加精力
- 恢复不能让当天剩余精力超过当天初始精力

验收标准：
- 每次记录都生成精力影响值
- 消耗和恢复方向正确
- 恢复上限生效
- 当前剩余精力允许低于 0
- 每条记录同时保存理论变化值 `theoreticalDelta` 和实际应用值 `appliedDelta`
- 首页、概览、结算优先使用 `appliedDelta`
- 重算时按生活日内有效记录的完成时刻顺序进行事件流重放

### US-5.4 生活日归属与结算

优先级：P0

功能说明：
- 第一版采用生活日
- 默认结算点为次日凌晨 04:00
- 凌晨 0 点后、04:00 前的记录默认归入前一天
- 系统自动完成生活日结算

验收标准：
- 04:00 前记录归入前一生活日
- 04:00 后记录归入新生活日
- 不要求用户手动结束一天
- 结算后生成昨日结果所需数据
- 如果 App 在 04:00 时未打开，下一次启动或下一次记录前需要先完成待结算生活日处理
- 多日未打开 App 时，按生活日从旧到新逐日处理待结算数据
- 无记录且无早间确认的空生活日不生成每日状态，不推进校准
- 昨日总结展示最近一个有数据的已结算生活日，不展示空日

### US-5.5 有效使用日判定

优先级：P0

功能说明：
标准有效使用日：
- 完成早间确认
- 至少记录 1 次活动

弱有效使用日：
- 未完成早间确认
- 但至少记录 2 次活动

验收标准：
- 系统能正确识别标准有效使用日
- 系统能正确识别弱有效使用日
- 弱有效使用日计入校准进度，但模型权重较低
- 当天补做早间确认后，可从弱有效使用日升级为标准有效使用日

## EPIC 6：今日概览与当日总览

### US-6.1 首页今日概览

优先级：P0

用户故事：
作为用户，我希望不用进入复杂页面，就能看到今天精力主要花在哪里。

功能说明：
- 首页展示轻量今日概览
- 只显示今天已有记录的大类
- 显示时间 + 精力变化
- 使用具体精力数值
- 按精力影响大小排序
- 不区分正负，只看影响大小
- 排序键为各大类实际应用值净和的绝对值：`sortKey = |sum(appliedDelta)|`

验收标准：
- 未记录时显示空状态
- 记录后展示对应大类汇总
- 大类按影响大小排序
- 今日概览随记录和撤销即时更新

### US-6.2 当日总览详情

优先级：P1

功能说明：
- 从首页今日概览进入
- 展示今天整体时间 / 精力分布
- 展示核心汇总指标和各大类分布
- 不深钻复杂分类详情
- 不做复杂曲线
- 不做时间轴

验收标准：
- 用户可以从首页进入当日总览
- 能看到总时间、总消耗、总恢复、各大类分布
- 页面不包含单条记录详情编辑
- 页面不包含复杂分类详情页

## EPIC 7：低精力与透支提醒

### US-7.1 阈值提醒

优先级：P1

功能说明：
第一版固定阈值：
- 剩余精力低于当天初始精力的 50%：中低精力
- 剩余精力低于当天初始精力的 25%：低精力
- 剩余精力低于 0：透支

验收标准：
- 达到阈值后出现轻量提示
- 同一生活日同一档位只提醒一次
- 提示不弹窗、不阻断记录
- 用户可以手动关闭当前提示
- 当补做早间确认导致阈值变化时，已不符合条件的提醒可以撤回
- 补做早间确认不会触发更重档位的新提醒

### US-7.2 提醒内容与表现

优先级：P1

功能说明：
- 文案保持中性
- 不评价用户表现
- 不制造失败感
- 推荐方向只到大类，不推荐具体任务
- 透支状态不使用强警告式表达

验收标准：
- 提示显示在首页能量球下方或附近
- 文案不出现批评、失败、惩罚感
- 透支状态使用“透支”标签
- 关闭后当前提示消失

## EPIC 8：昨日结果与轻详情

### US-8.1 第二天展示昨日一句总结

优先级：P1

功能说明：
- 第二天首次打开时展示一句昨日总结
- 只出现一次
- 用户关闭后当天不再出现
- 作为轻量条展示
- 不弹窗，不阻断早间确认和首页记录

验收标准：
- 有昨日结算数据时可生成总结
- 第二天首次打开展示
- 用户关闭后当天不再展示
- 不影响早间确认和记录主流程

### US-8.2 昨日轻详情

优先级：P1

功能说明：
用户可从昨日提示展开昨日轻详情。

内容包括：
- 昨日初始精力
- 昨日最终剩余精力
- 昨日总消耗 / 总恢复
- 各大类时间 + 精力影响
- 3 个以内状态标签

验收标准：
- 用户能从昨日提示进入轻详情
- 信息与昨日结算数据一致
- 标签数量不超过 3 个
- 标签采用固定标签加一句短解释
- 标签偏状态结果型，不做复杂原因归因
- 标签从固定标签库中按优先级选择，最多展示 3 个
- 标签触发规则详见《精力值算法规则初稿》
- 不做复杂报告、复杂图表和时间轴

## EPIC 9：校准期、个性化与周调整

### US-9.1 校准期进度

优先级：P1

功能说明：
- 校准期为 7 个有效使用日
- 有效使用日不是自然连续 7 天
- 标准有效使用日和弱有效使用日都计入进度

验收标准：
- 系统能展示或记录校准期进度
- 只有有效使用日才推进进度
- 撤销记录不错误推进进度
- 累计完成 7 个有效使用日后，系统在次日首次打开时展示校准完成轻提示

### US-9.2 校准期抽样反馈

优先级：P1

功能说明：
- 校准期内可在高影响记录后出现抽样反馈
- 每天最多 1 到 2 次
- 用户可以跳过反馈
- 抽样反馈在记录完成反馈条结束后出现，避免遮挡 5 秒撤销入口

验收标准：
- 反馈选项包含“系统估计偏轻 / 差不多 / 系统估计偏重”
- 不在每次记录后都询问
- 跳过不影响正常记录
- 抽样反馈不覆盖撤销按钮
- 如果记录被撤销，该记录对应的抽样反馈自动作废，不计入校准信号

### US-9.3 每 7 个有效使用日生成基准线调整建议

优先级：P1

功能说明：
- 每累计 7 个有效使用日评估一次个人基准线
- 系统给出建议调整值
- 用户确认后才生效
- 用户可以拒绝调整

验收标准：
- 满 7 个有效使用日后可生成建议
- 建议包含调整方向、建议值、轻量原因摘要
- 用户同意后更新个人基准线
- 用户拒绝后保持原个人基准线不变
- 动态学习关闭时，不生成新的趋势调整建议
- 不做完整原因展开和详细趋势解释

### US-9.4 周调整提示时机

优先级：P1

功能说明：
- 周调整提示在累计 7 个有效使用日后的第二天首次打开时出现
- 不在用户刚完成一次活动记录后弹出
- 用户可以暂时关闭

验收标准：
- 提示时机符合 PRD
- 关闭后不影响当前个人基准线
- 下次打开可轻提醒一次

### US-9.5 近 7 天趋势

优先级：P1

功能说明：
第一版只保留核心趋势信息：
- 个人基准线变化
- 每日最终剩余精力
- 低精力 / 透支次数

入口：
- 不常驻首页
- 从周调整页或设置 / 数据入口进入

验收标准：
- 用户能查看最近 7 个有效使用日的核心趋势
- 趋势信息不做复杂图表分析
- 不展示完整原因展开
- 数据与生活日结算结果一致

## EPIC 10：设置

### US-10.1 常用设置

优先级：P1

功能说明：
常用设置包括：
- 修改个人基准线
- 动态学习 / 个性化调整开关
- 查看新手引导

验收标准：
- 用户可以查看当前个人基准线
- 用户可以手动修改个人基准线
- 手动修改前有确认提示
- 手动调整范围限制为 60 到 140
- 单次调整幅度超过 16 时，需要额外二次确认
- 用户可以关闭动态学习
- 用户可以重新查看新手引导

### US-10.2 动态学习关闭规则

优先级：P1

功能说明：
动态学习关闭后：
- 不再自动调整个人模型
- 不再给出基于趋势的个人基准线调整建议
- 普通记录计算仍保留
- 手动基准线仍保留
- 等级映射仍保留

验收标准：
- 关闭后记录功能仍可用
- 关闭后不生成新的趋势调整建议
- 开关状态本地保存

### US-10.3 高级规则

优先级：P2

功能说明：
高级规则包括：
- 修改等级到精力值的映射
- 恢复默认规则
- 规则变更后重算最近 7 个有效使用日

验收标准：
- 高级规则入口默认折叠
- 新用户主流程不强调高级规则
- 规则变更不触发全量历史重算
- 重算时仅处理 `status = active` 的记录，已撤销记录不参与重算

### US-10.4 本地数据提示

优先级：P1

功能说明：
- 第一版不做账号登录和云同步
- 设置页需要提示数据仅保存在本机

验收标准：
- 设置页能看到本地数据提示
- 文案说明卸载或换机可能导致数据丢失

### US-10.5 数据导出

优先级：P2

功能说明：
- 第一版可在设置中提供本地数据导出入口
- 导出格式优先采用 JSON
- 仅作为用户自备份能力，不等同于云同步

验收标准：
- 用户可以手动导出本机数据
- 导出数据包含活动记录、每日状态、用户模型和设置
- 导出入口不进入新用户主流程
- 不提供自动云备份或多设备同步

## EPIC 11：本地数据与状态管理

### US-11.1 本地保存活动记录

优先级：P0

功能说明：
每条活动记录至少包含：
- 记录 ID
- 生活日
- startedAt
- completedAt
- 大类
- 子类
- 时长
- theoreticalDelta
- appliedDelta
- 记录状态：有效 / 已撤销
- feedbackId
- cancelledAt

验收标准：
- 记录后数据能持久保存
- 重启 App 后数据仍存在
- 撤销记录不参与展示和计算
- `status` 枚举为 `active | cancelled`
- 首页、概览、结算、校准、模型学习、重算默认只查询 `active` 记录

### US-11.2 本地保存每日状态

优先级：P0

功能说明：
每日状态至少包含：
- 生活日
- 当日初始精力
- 当日短期修正值
- 当前剩余精力
- 最终剩余精力
- 总消耗
- 总恢复
- 是否标准有效使用日
- 是否弱有效使用日
- 是否已结算
- 是否因规则变更被重算过
- 低精力 / 透支档位已提醒标记

验收标准：
- 每个生活日有唯一每日状态
- 活动记录后每日状态更新
- 生活日结算后生成最终数据

### US-11.3 本地保存用户模型与设置

优先级：P0

功能说明：
至少保存：
- 个人基准线
- 动态学习开关
- 新手引导完成状态
- 早间确认状态
- 子类个人修正值
- 低精力提示关闭状态
- 周调整提示状态
- 昨日提示关闭状态

验收标准：
- 设置修改后可持久保存
- 重启 App 后状态保持
- 用户模型数据可被精力计算读取

## EPIC 12：启动与提示编排

### US-12.1 App 启动状态准备

优先级：P0

功能说明：
每次 App 启动或从后台回到前台时，系统需要先完成状态准备：
- 判断当前生活日
- 处理待结算生活日
- 初始化当日每日状态
- 判断是否需要展示新手引导、早间确认、昨日提示、周调整提示

验收标准：
- 跨过 04:00 后重新打开 App，生活日状态正确
- 有未结算生活日时先完成结算，再展示首页数据
- 首页展示的当前精力值和当前生活日一致
- 不因重复启动创建重复每日状态
- 多日未打开 App 时，按生活日从旧到新逐日处理待结算数据
- 不为空生活日创建无意义的每日状态

### US-12.2 多提示展示规则

优先级：P0

功能说明：
当同一次打开同时满足多个提示条件时，需要有展示编排，避免互相抢占。

建议顺序：
1. 新手引导
2. 昨日总结提示
3. 早间确认
4. 周调整提示

说明：
- 新手引导只影响首次使用
- 昨日总结是轻提示条，不阻断首页记录
- 周调整是需要用户决策的独立卡片或页面，不与首页记录操作冲突
- 早间确认不是进入首页的强制门槛

验收标准：
- 同次启动多个提示不会重叠遮挡
- 用户关闭当前提示后，状态被正确保存
- 昨日总结不阻断早间确认
- 周调整不在用户刚完成活动记录后弹出
- 周调整不抢在昨日总结之前出现
- 早间确认跳过后当天不再强弹

# 5. 推荐开发顺序

## 阶段 1：基础闭环

目标：用户能完成一天的记录和精力变化。

包含：
1. 本地数据结构
2. 生活日规则
3. 启动状态准备
4. 默认活动规则配置
5. 首页能量球静态展示
6. 活动分类与时间档位
7. 活动记录
8. 精力计算
9. 今日概览
10. 5 秒撤销

## 阶段 2：每日使用闭环

目标：产品从单次记录扩展到日常使用。

包含：
1. 新手引导
2. 早间确认
3. 当日初始精力计算
4. 低精力 / 透支提醒
5. 生活日结算
6. 昨日总结与轻详情
7. 多提示展示规则

## 阶段 3：7 日校准闭环

目标：形成产品的长期反馈价值。

包含：
1. 有效使用日判定
2. 校准期进度
3. 周调整建议
4. 个人基准线确认更新
5. 近 7 天趋势
6. 校准期抽样反馈
7. 设置中的动态学习开关
8. 基础子类个人修正值

## 阶段 4：体验补齐

目标：补齐第一版可用性和解释能力。

包含：
1. 备用记录入口
2. 当日总览详情
3. 设置页完整化
4. 高级规则入口
5. 本地数据提示
6. 数据导出
