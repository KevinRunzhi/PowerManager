- 版本：1.4

## 1. 实验目标

验证基准线自动学习在真实激活后的新 model regime 中是否：

- 让估计与主观实际的方向分布不恶化并出现有用改善；
- 不因短期波动连续来回调整；
- 冷却、累计边界、暂停、取消和撤回真实可用；
- 不增加不可接受的记录与通知负担；
- 不造成当前日、历史或备份解释漂移。

本阶段分两轨：模拟器使用带水印预生产配置和 fixture 验证完整监测、暂停、撤回状态机，作为
工程放行；真机只在 MVP-B 总体验收安装后用自然证据评价产品效果。模拟器结果不得写成真实
改善，产品状态在此之前固定为 `inconclusive`，生产自动应用门保持 false。

## 2. 前置条件

- B2-1 工程生命周期全部通过；
- B1-1 已为当前执行轨定义不恶化、最小有用改善、观察窗口和暂停阈值；
- 首个隔离预生产版本的来源、证据、父模型、通知和激活时间完整；
- 激活前 latest 备份已验证并导出；
- 新 modelRegimeEpoch 已生效；
- 观察期不人为改变规则或 base。若发生手动变化，本实验结束并重新建档。

工程预生产门固定为：新 epoch 14 条 / 21 日 / 2 × 7；最小有用改善为 aligned 至少 +2 且
absolute ordinal error 至少 -2；不恶化要求 aligned 不下降、预期反向总数最多 2 且每窗最多 1；
两窗各至少 5 / 7 预期反向，或 aligned 至少 -3 且 error 至少 +3 时暂停。自动撤回关闭。以上只
用于模拟器状态机，产品轨仍需自然证据。

## 3. 观察方案

### 3.1 数据

只使用新 epoch 中自然结算的 eligible observations，并按已批准 referenceType 独立统计：

- 低于、相符、高于；
- 排除与原因；
- 日期跨度；
- 与候选预期方向是否一致；
- 用户主动取消、拒绝、撤回或手动覆盖；
- 学习通知查看和理解；
- 日常记录完成与跳过。

旧 epoch 只作为冻结的前窗口描述，不与新 epoch 拼成生产候选。

### 3.2 检查频率

- 每次新证据结算后由协调器执行一次幂等评估；
- 冷却未结束时只更新报告，不生成新候选；
- 无新 evidence hash 时零写入；
- UI 不用倒计时或频繁提醒催促用户完成观察。

### 3.3 用户主观记录

在阶段结论时记录：

- 新估计是否更有参考价值；
- 是否觉得变化太快或方向错误；
- 通知是否清楚；
- 是否需要取消或撤回；
- 额外问题是否影响使用。

不把一次情绪或单日异常自动解释为模型失败。

## 4. 恶化暂停

达到 B1-1 配置的恶化条件时，单事务执行：

1. 保存 evaluation 证据与结果；
2. baselineLearningSuspended 设为 true；
3. 不自动修改 active model；
4. 取消或失效该参数族尚未生效候选；
5. 创建持久通知，说明为何暂停；
6. 提供保持当前、安排撤回或手动恢复学习；
7. 恢复学习前确认冷却和证据窗口。

暂停只影响 baseline，不改变 activityImpact 模式。默认不自动回滚，避免震荡。

## 5. 决策结果

### 5.1 validated

- 达到最小有用改善；
- 不恶化边界通过；
- 没有高频取消、撤回或暂停；
- 用户认为参考价值提升且负担可接受。

### 5.2 rejected

- 达到足够观察窗口但无改善或明显恶化；
- 用户认为变化无帮助；
- 取消、撤回或暂停比例超过配置；
- 不能在简单、有界规则下避免震荡。

结果：暂停或关闭 baseline 生产学习，保留历史审计。

### 5.3 inconclusive

- 新 epoch 证据不足；
- regime 被手动变化或恢复打断；
- 方向自然不稳定；
- 观察负担数据不足。

结果：保持当前安全状态继续观察，不声称通过。

## 6. 自动化验证

即使真实结果尚未形成，也必须用明确测试证据覆盖：

- 刚激活时无足够观察；
- 冷却内只报告不学习；
- 正常改善；
- noChange；
- 恶化门刚好未命中和刚好命中；
- 命中后暂停且不自动回滚；
- 已有 scheduled 候选的暂停处理；
- 用户撤回、保持和恢复；
- activityImpact 不受 baseline 暂停影响；
- 重启、恢复和重复评估不重复通知；
- 旧 epoch 证据不复用；
- 备份往返保留评估与暂停。

执行 format、analyze、全量 test、coverage、模拟器可运行构建和 git diff --check。

## 7. 最终安装后的真实验收过程（本阶段不执行）

1. 记录激活前窗口和候选预期；
2. 确认激活生活日与通知窗口；
3. 在新 epoch 自然记录，不补造；
4. 每次结算后检查评估没有重复；
5. 达到配置观察窗后生成聚合报告；
6. 检查历史日仍引用旧版本；
7. 保存并恢复一次当前 schema v4 备份；
8. 根据配置与主观价值记录 validated、rejected 或 inconclusive；
9. 记录任何 P0 / P1 数据或体验问题。

## 8. 停止条件

- 自动来回改变 base；
- 恶化命中后仍继续生成 baseline 候选；
- 暂停自动回滚而配置未授权；
- 新旧 epoch 混合；
- 历史结果改变；
- 用户不能理解或撤回；
- 数据错误、静默变化或备份不可恢复；
- 为取得 validated 结论补造观测。

## 9. 退出证据

- 监测、暂停和恢复自动化测试全绿；
- 模拟器监测、暂停、恢复与历史冻结记录；
- 真机真实观察登记到总体验收，当前产品状态为 inconclusive；
- 没有未解决 P0 数据问题；
- B3-0 可以独立分析活动反馈，不能把 baseline 结果当作活动倍率证据。
