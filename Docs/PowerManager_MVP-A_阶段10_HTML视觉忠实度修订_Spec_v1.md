# 1. 本轮问题

## 1.1 能量球没有像 HTML 一样改变颜色

在 Pixel_7 模拟器复现到：

- 当前估计精力为 43，初始估计为 100，比例为 0.43；
- Flutter 能量球仍使用未点亮灰色 `#3A4152 / #262C3A`；
- HTML 在首次记录活动或主动跳过晨间确认后会执行 `lightUp(0)`，随后按实时比例显示色温；
- Flutter 把“球体是否显示色温”直接绑定为
  `morningStatus == completed`，导致以下两种状态一直灰暗：
  1. 已跳过晨间确认；
  2. 未回答晨间确认，但已经记录活动。

因此，本问题的首要原因不是绘制能力不足，而是**点亮状态和晨间完成状态被错误地当成了同一个状态**。

第二个差异是 Flutter 只保留了 5 个色阶端点，HTML 使用 9 个端点形成分段平台和过渡区。
缺少 `1.00 / 0.65 / 0.37 / 0.12` 等端点会让青绿、天青、琥珀和暖橙的出现时机偏离原型。

## 1.2 进入选项后出现两条横线

模拟器截图确认：

- 横线为亮黄色；
- 每一行文字各出现一条，所以两行标签看起来是“两条横线”；
- 单行标签和底部阶段提示同样出现黄色横线；
- 源码中的选项 `TextStyle` 没有设置 `TextDecoration.underline`。

进一步隔离验证后确认：

- 黄线只出现在独立插入的径向 `OverlayEntry` 中；
- 同一画面中的首页文字没有黄线；
- 径向 `TextStyle` 虽然指定了颜色和字号，但仍使用默认 `inherit: true`；
- Overlay 没有继承到正常的 Material 文本环境，于是继续继承了 Flutter 的
  双黄线调试型默认文字装饰。

因此它不是产品下划线、径向节点边框或全局文字基线开关，而是
**Overlay 文字样式继承不完整**。

# 2. HTML 基准实现

## 2.1 精确色温轴

Flutter 必须复制以下端点和顺序：

| 比例 | 主色 A | 辅色 B | 作用 |
|---:|---|---|---|
| 1.00 | `#5EEAD4` | `#A7F3D0` | 高能量上界 |
| 0.80 | `#5EEAD4` | `#A7F3D0` | 青绿平台结束 |
| 0.65 | `#7DD3FC` | `#5EEAD4` | 青绿到天青过渡结束 |
| 0.50 | `#7DD3FC` | `#5EEAD4` | 天青平台结束 |
| 0.37 | `#FCD34D` | `#7DD3FC` | 天青到琥珀过渡结束 |
| 0.25 | `#FCD34D` | `#7DD3FC` | 琥珀平台结束 |
| 0.12 | `#F0A868` | `#B08968` | 琥珀到暖橙过渡结束 |
| 0.00 | `#F0A868` | `#B08968` | 暖橙平台结束 |
| -0.30 | `#9B8AB8` | `#6E6284` | 透支薄雾 |

端点之间逐 RGB 通道线性插值；高于 1.00 和低于 -0.30 时固定使用首尾颜色。

## 2.2 点亮规则

保持产品语义与 HTML 反馈一致：

```text
没有晨间选择、没有跳过、没有活动
    → 灰暗未点亮

完成晨间确认
    → 点亮

主动跳过晨间确认
    → 点亮，但晨间状态仍记为“已跳过”

未处理晨间确认，但已记录至少一条活动
    → 点亮，但文字仍可提示“未晨间确认”
```

“显示色温”只表示已有可用的当日估计，不得伪造“晨间已完成”。

## 2.3 径向选项

径向节点继续采用 HTML 的：

- 深色圆形节点；
- 1px 低透明度边框；
- 两行居中标签；
- 候选项放大和光晕；
- 其余项降亮度。

产品界面不得出现文字下划线或 Flutter 调试基线。

# 3. 实施步骤

1. 将 HTML 的 9 个颜色端点提取为独立、可测试的 Flutter 色温源。
2. 能量球绘制统一从该色温源取主色和辅色。
3. 将“是否点亮”与“晨间是否完成”拆分。
4. 已跳过晨间确认或已有活动时启用实时色温。
5. 保留未晨间确认的文字提示，不篡改业务状态。
6. 径向节点和阶段提示改为完整的非继承文字样式：
   `inherit: false` 且 `decoration: TextDecoration.none`。
7. 增加色阶端点、插值、越界钳制、点亮条件和 Overlay 文字装饰回归测试。
8. 重新构建 APK，在 Pixel_7 模拟器复验 43 / 100 状态和径向大类层。
