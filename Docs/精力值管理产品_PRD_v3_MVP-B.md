# 精力值管理产品 PRD v3（MVP-B）

## 0. 文档状态

- 版本：3.2
- 日期：2026-08-15
- 状态：已确认，作为 MVP-B 产品实施基线
- 承接：MVP-A Stage 19

本文档是 MVP-B 用户可感知行为的唯一来源。数值与功能开关见《精力值规则配置 v3
（MVP-B）》，计算机制见《精力值算法规则 v3（MVP-B）》。

## 1. 产品目标

MVP-B 的核心目标是实现本地、持续、可解释的**自动学习**。

系统自动把合格的“估计—实际”配对和活动直接反馈转化为版本化个人模型，自动判断证据是否
足够，并在用户开启自动模式后，把满足安全门槛的小幅调整安排到满足通知窗口的未来生活日
生效。用户不需要逐次计算参数，也不需要在自动模式下逐条批准变化。

MVP-B 要验证的是：

> 自动学习能否在不明显增加记录负担的前提下，持续改善系统估计与用户主观状态的对齐；
> 同时每次变化都可解释、可追溯、可取消、可撤回，不成为无法控制的黑箱。

系统估计仍然不是客观生理测量、医学结论、能力评分或任务完成能力预测。实际状态是用户
在特定时刻的主观观测，也不是绝对真值。MVP-B 只尝试改善两者的长期对齐。

## 2. 核心产品原则

1. **先有可比较证据，再学习。** 没有同一参考时刻的估计与实际配对时，不更新模型。
2. **学习自动，变化透明。** 系统可以自动计算和应用，但必须记录原因、版本和生效时间。
3. **用户选择自动化程度。** 基准线和活动影响分别支持关闭、审核后应用、自动应用三种模式。
4. **未来生效，历史冻结。** 新模型只从最早可生效的未来生活日起生效，不重写当前日和历史。
5. **一次只学习一个参数族。** 同一学习运行不同时改变基准线与活动影响参数。
6. **小步、有界、可回退。** 自动变化受步长、范围、冷却和恶化保护限制。
7. **解释使用了什么。** 变化记录展示证据数量、日期范围、偏差方向和预计影响。
8. **缺数据也是结果。** 数据不足时继续观察，不为了更新模型降低门槛。

“可比较证据”必须已经随生活日结算而冻结。当前日仍可修改的状态或活动反馈可以显示进度，
但不能提前驱动自动变化。

## 3. MVP-B 核心范围

### 3.1 B0：观测与升级基础

- 把每日实际状态改成同一参考时刻的“估计—实际”配对。
- 增加“截至此刻主要活动是否基本记录完整”的低负担确认。
- 支持补填昨日结束时的实际状态，并绑定昨日最终估计。
- 保存活动绑定直接反馈，但不据此更新活动参数。
- 现有“此刻校正”继续用于描述性复盘，不冒充活动直接反馈或每日配对。
- 完成数据库和备份从 schema v1 到 v2 的兼容升级。
- 旧数据继续用于历史复盘，但默认标记为不可学习证据。

### 3.2 B1：自动影子学习

- 只读展示可学习观测进度、排除原因和方向性对齐结果。
- 自动学习引擎先按真实新证据生成影子证据运行；生产阈值未知时不伪造候选值。
- 真实数据审计形成明确的 shadow-only 候选配置后，自动生成候选个人模型和反事实记录。
- 影子模型不成为当前生效模型，不改变基准线或活动规则。
- 用影子模型的反事实与后续表现决定 B2 / B3 的生产阈值、步长和保护规则。

### 3.3 B2：基准线自动学习

- 只在 B1 审计通过、生产规则版本确认且用户选择学习模式后启用。
- 系统自动检测持续偏差并生成新的候选基准线版本。
- 审核模式由用户接受、拒绝或稍后处理。
- 自动模式直接安排满足最短通知时间的未来生活日生效，同时展示变更通知和取消入口，不要求
  逐条批准。
- 生效后进入冷却期；新证据明显恶化时暂停继续学习并提供撤回。
- 展示调整前后的后续对齐变化，不宣称统计显著或科学准确。

### 3.4 B3：活动影响自动学习

- 自动学习只使用与具体活动绑定、由已发布抽样策略选中的直接反馈。
- 用户主动评价仍用于单条复盘、影子研究和方向不符审计；由于它天然偏向“感觉不准”的活动，
  MVP-B 不直接用它更新生产倍率。
- B3 提供低频、可跳过、不按结果挑选的活动抽样反馈；提示上限和抽样策略由真实负担审计决定。
- 参数至少按“子类 × 影响方向”分开，不能用一次恢复反馈同时放大同子类的消耗档位。
- 默认值为 0、方向不符或恢复上限截断的记录，不直接驱动倍率更新。
- 审核模式与自动模式沿用 B2 的生效、通知、冷却和撤回机制。
- 系统不得为缺少证据的子类伪造个性化参数；没有合格反馈时保持当前版本并继续积累。

B2 与 B3 共同构成 MVP-B 的自动学习闭环。是否实际产生某个子类更新由真实数据决定，但
活动学习引擎、版本化和安全应用能力不是可选项。

## 4. 用户流程

### 4.1 每日实际状态

同日填写时，页面询问“你现在的整体状态”，并要求用户先选择五档实际状态，再揭示系统
在同一时刻的估计。保存前追加一个轻量问题：

```text
截至现在，今天的主要活动基本记录完整吗？
基本完整 / 不确定
```

选择“不确定”仍保存状态并用于复盘，但不进入基准线影子学习。

五档状态使用稳定的行为锚点，帮助用户按“此刻还能承担多少日常负荷”选择，而不是按当天
表现好坏评分：

| 状态 | 行为锚点 |
|---|---|
| 耗尽 | 很难继续普通负荷，更需要停止或休息 |
| 偏低 | 能处理必要的低负荷事项，但余力明显不足 |
| 尚可 | 可以继续一般事项，余力不多也不至于难以维持 |
| 良好 | 能较稳定地继续日常负荷，并有一定余力 |
| 充足 | 当前余力充足，可以承担更高负荷但不代表必须继续 |

界面应允许查看这些解释，但不把每次选择变成阅读考试。状态不评价意志、效率或完成量。

补填昨日时，页面询问“昨天结束时的整体状态”，并与昨日不可变最终估计配对。不得把补填
时间误当成状态参考时间。

### 4.2 活动直接反馈

用户可从当前生活日的活动记录主动选择：

- 影响比估计更强；
- 差不多；
- 影响比估计更弱；
- 方向不符合感受。

反馈必须明确指向一条活动。B0 / B1 不主动弹出活动反馈请求；后续是否抽样提示必须由真实
使用负担审计决定。B3 若要开启活动影响生产学习，必须先发布抽样策略；用户可以跳过，跳过
不降低任何产品能力，也不会被同日反复追问。

### 4.3 自动学习记录

每次影子学习、待审核变化或自动变化都必须回答：

1. 系统观察到了什么持续偏差；
2. 使用了多少条合格观测及其日期范围；
3. 哪些数据被排除以及为什么；
4. 当前值与学习后的候选值；
5. 何时生效；
6. 当前模式下如何接受、取消、稍后处理或撤回。

不得使用“系统发现你的体力下降”“你的真实能力是”等生理或能力判断文案。

### 4.4 用户控制

- 两个参数族的自动学习都默认关闭，并分别保存模式；B1 就绪后由用户阅读说明并选择。
- `off`：不运行新的学习任务，不安排模型变化。
- `review`：系统自动学习和生成候选，用户逐次确认是否应用。
- `automatic`：系统自动学习并自动安排满足安全门槛的变化，用户收到通知并可以取消或撤回。
- 关闭某个参数族后停止该参数族的新学习，并取消其尚未生效的变化。
- B3 上线时，活动影响模式仍为 `off`；不能因为用户过去允许基准线自动学习就自动继承授权。
- 已经生效的模型不静默回退；页面提供当前版本、来源和撤回路径。
- 关闭学习不删除实际状态和活动反馈，它们继续用于用户自己的历史复盘。
- 用户可以清除未处理候选，并重置未来个性化模型。
- 删除、重置和恢复备份前必须说明会影响什么，不会影响什么。

自动变化通知至少是可持久化、再次打开仍可见的 App 内记录；系统通知权限可以增强提醒，但
不能成为唯一入口。通知记录保存失败时不得安排自动生效。

## 5. 成功标准

### 5.1 数据与安全

- schema v1 真机数据可以按阶段无损升级到 MVP-B 当前 schema；
- 所有阶段备份向后兼容，当前版本数据可完整备份恢复；
- 重启、重复准备和恢复备份不会重复生成学习运行或重复激活模型版本；
- `off` 模式下参数不改变；`review` 模式未经确认不改变；`automatic` 模式只应用通过安全门槛的版本；
- 每次自动应用都有非阻断通知、变更记录和撤回路径；
- 历史活动和每日摘要保持原结果可解释。

### 5.2 用户价值

- 用户理解实际状态和系统估计是两条不同信息；
- 用户能在短时间内理解学习依据、变化内容和影响；
- 额外问题不阻断活动记录，可跳过且不反复催促；
- 新模型生效后的观察窗口中，方向性不一致没有明显恶化；
- 用户若频繁取消、拒绝、撤回或认为学习无帮助，MVP-B 判为产品假设未通过，而不是降低门槛。

必须持续记录以下本机指标，不上传明细：

- 按 reference type 的 `低于 / 相符 / 高于` 分布及新旧 regime 变化；
- 抽样活动反馈的 `aboutRight`、跳过、未响应和 directionMismatch 分布；
- 候选生成、自动安排、取消、拒绝、撤回、暂停和手动覆盖次数；
- 每日新增问题的展示、完成和跳过情况。

当前没有真实 MVP-B 数据，所以不在本文伪造“改善多少才成功”的数字。B1 / B3 决策记录必须
分别发布“不恶化边界、最小有用改善、最大提示负担和最大撤回 / 暂停比例”，否则可以继续
工程验证，但不能宣称对应参数族产品验证通过。

### 5.3 MVP-B 退出条件

MVP-B 核心完成需要同时满足：

1. B0 数据与迁移门禁通过；
2. B1 真实影子数据审计完成；
3. 自动学习引擎能够从新增证据生成不可变个人模型版本；
4. 基准线在三种模式下完成“学习 → 安排 → 生效 → 评估 / 撤回”的工程生命周期验证；
5. 活动影响学习完成同等级生命周期验证，且不会跨方向错误传播；
6. 真实数据运行能如实得到“更新 / 无需变化 / 证据不足”，不要求为了验收强行改变参数；
7. 学习结果可从冻结证据、算法和配置版本重现；
8. 后续观察没有发现数据错误、无法解释的变化或明显负向体验。

云同步和复杂趋势图不是退出条件；自动学习、基准线适配和活动影响学习属于退出条件。

这里的“核心完成”表示工程能力和安全闭环完成，不等于产品假设已经通过。真实数据结论必须
单独标记为 `validated / rejected / inconclusive`；证据不足时只能是 `inconclusive`，不能写成
“自动学习有效”。

## 6. 明确非目标

- 客观生理能量测量或医学建议；
- 不透明、无边界或不可撤回的自动参数更新；
- 登录、云同步、社交和多人模型；
- 健康设备、屏幕时间和课表自动接入；
- 高级规则编辑和历史规则迁移；
- 复杂趋势图、预测模型或机器学习平台；
- 同一次学习运行同时修改基准线和活动参数；
- 为了达标补造反馈或降低样本资格。
