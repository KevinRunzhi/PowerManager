# 1. 背景与问题

真实数据审计发现，活动的大类名称不能可靠表达最终精力变化。例如“休息恢复”中的活动会
随子类和时长出现正恢复、零变化或负消耗。如果界面只展示活动名与分钟数，用户必须记忆
规则表，容易误选，也难以理解记录后的结果。

阶段 15 不调整任何规则参数，而是把已有规则在选择发生前清楚呈现：

> 先展示该时长的规则估计；当恢复受当日初始估计上限截断时，再明确展示预计实际变化。

---

# 2. 目标与非目标

## 2.1 目标

1. 点击式记录在六个时长档位上同时展示分钟数和预计变化；
2. 径向手势在时长节点上展示同一套变化值；
3. 正数、零、负数均使用明确符号和“估计”语义，不只依赖颜色；
4. 正向恢复受上限截断时，展示预计实际值并说明原因；
5. 点击式与手势式入口使用同一预估服务和同一活动规则版本；
6. 编辑当前生活日记录时，也能根据编辑后的顺序给出预估；
7. 不写数据库、不改变历史记录，只有最终确认仍调用既有写用例。

## 2.2 非目标

- 不修改 v2 MVP-A 的 144 个规则值；
- 不引入 personalFactor、自动学习或基准线建议；
- 不把估计变化描述为真实体感；
- 不降低点击式 `+` 的视觉权重；
- 不重做能量球、颜色轴或径向菜单总体布局；
- 不提前进行真机触控和性能验收。

---

# 3. 核心语义

## 3.1 两个变化值

- `theoreticalDelta`：当前规则版本中“子类 × 时长”的规则估计；
- `projectedAppliedDelta`：把候选记录按 `completedAt → createdAt → id` 插入当天事件流并完整
  重放后，该候选记录预计真正应用的变化。

负数和零不会被恢复上限截断，因此二者相等。只有正恢复可能因为当前估计已经接近或达到
当日初始估计而变小，最低为 0。

## 3.2 展示规则

1. 未截断：`15 分钟` + `估计 +5`、`估计 0` 或 `估计 −5`；
2. 被截断：主值展示 `估计 +2`，辅助说明 `规则 +5 · 受今日恢复上限影响`；
3. 完全无法恢复：主值展示 `估计 0`，辅助说明 `规则 +5 · 已到今日恢复上限`；
4. 数字始终带正负号，零不加号；
5. 颜色只作辅助，文字和符号必须独立传达含义；
6. “估计”标签不可省略。

## 3.3 时序准确性

- 点击式新建：预估使用当前选择的完成时间；初始为“刚刚”，改变完成时间后重新预估；
- 点击式编辑：从事件流中移除原记录，再以编辑后的内容和完成时间插入重放；
- 径向手势：完成时间固定为松手时刻，节点预览按当前时刻计算；
- 保存前状态变化可能使预估失效，最终保存结果仍以事务内完整重放为准；撤销条展示最终
  持久化的 `appliedDelta`，作为事实结果。

# 4. 用户界面

## 4.1 点击式记录 Sheet

时长步骤保持两列、六个触控块：

- 第一行：`15 分钟`；
- 第二行：`估计 +5`；
- 必要时第三行显示恢复上限说明；
- 单个触控区域至少 48dp 高，相邻区域至少 8dp；
- 加载时预留数值行空间，避免异步结果造成布局跳动；
- 预估失败时显示 `暂时无法预估`，但不阻断记录；最终写入仍由既有规则校验。

选择完成时间页顶部增加只读摘要：大类、子类、时长和当前预估变化。改变完成时间后摘要
刷新，不自动提交。

## 4.2 径向手势

- 大类和子类节点不增加数值，避免信息过载；
- 六个时长节点改为两行：分钟数 + `+5 / 0 / −5`；
- 当前吸附节点附近的阶段提示补充完整语义，例如 `午睡 30 分钟 · 估计 +10`；
- 若受恢复上限影响，节点展示预计实际值，阶段提示追加 `受恢复上限影响`；
- 节点保持现有命中区域、粘滞和停留确认逻辑，不因文字增加缩小触控范围。

## 4.3 视觉与无障碍

- 沿用现有深色设计令牌，不采用外部推荐色覆盖产品色温轴；
- 数值使用等宽数字特性或稳定宽度，避免正负号切换抖动；
- 正值、零值、负值均有文本，不依赖青绿/琥珀/灰紫颜色；
- 语义标签需能读出“30 分钟，估计增加 10”或“估计减少 5”；
- 200% 字号允许节点和卡片增高或换行，不截断核心数值；
- 尊重系统减少动态效果设置，不新增装饰性动画。

# 5. 技术设计

## 5.1 预估服务

新增只读 `ActivityImpactPreviewService`：

1. 接收当前日投影、活动列表、规则配置和候选记录；
2. 校验大类与子类归属；
3. 从当前规则版本读取 `theoreticalDelta`；
4. 编辑场景先排除同 ID 原记录；
5. 构造不持久化的候选记录；
6. 使用既有 `CurrentDayProjector` 完整重放；
7. 返回不可变 `ActivityImpactPreview`。

Widget 不得自行复制规则表或恢复上限公式。

## 5.2 预估结果

结果至少包含：

- 子类与时长；
- `theoreticalDelta`；
- `projectedAppliedDelta`；
- `estimateBefore` 与 `estimateAfter`；
- `isRecoveryLimited`；
- 用于界面展示的中性说明由 presentation formatter 生成。

## 5.3 并发与失败

- 点击式快速切换选项时，只采纳最后一次请求结果；
- Widget 销毁后不得 setState；
- 预估不获取写事务，不修改活动的 `appliedDelta`；
- 预估异常只降级显示，不泄漏内部异常或规则 JSON；
- 保存仍由 `ActivityUseCases` 串行化和事务重放保证正确性。

# 6. 测试要求

## 6.1 单元测试

至少覆盖：

1. 负变化与理论值一致；
2. 正恢复未截断；
3. 正恢复部分截断；
4. 达到上限时实际为 0；
5. 插入较早时间会影响候选及后续恢复记录；
6. 编辑时原记录被替换而非重复计算；
7. 大类与子类不匹配时拒绝；
8. 活跃规则缺失或格式损坏时安全失败。

## 6.2 Widget 测试

至少覆盖：

1. 点击式六个时长均展示估计变化；
2. 截断时显示恢复上限说明；
3. 选择完成时间后摘要刷新；
4. 预估加载和失败不阻断流程；
5. 手势节点展示变化值；
6. 200% 字号、小屏无溢出；
7. 无障碍语义包含增减方向和数值。

# 7. 模拟器验收

在 Pixel_7（Android 14 / API 34）完成：

1. 进入点击式记录，选择至少一个消耗型活动，核对六个时长变化；
2. 选择至少一个会从正恢复变为零/负值的活动，确认各档位表达清楚；
3. 在接近恢复上限状态验证截断说明；
4. 改变完成时间，确认摘要刷新且未提前写入；
5. 完成记录，撤销条数值与保存前预估或最终重放结果一致；
6. 长按能量球进入径向手势，确认时长节点和阶段提示显示变化值；
7. 取消两种流程，数据库无新增记录；
8. 日志无 Flutter 异常、Crash 或 ANR。

---

# 8. 验收标准

1. 点击式与手势式入口读取同一规则版本；
2. 六个时长档位均显示正确的有符号估计变化；
3. 正恢复截断结果与完整事件流重放一致；
4. 恢复上限通过文字说明，不只依赖颜色；
5. 编辑、补记和当前时刻新建预估正确；
6. 预估过程零数据库写入；
7. 预估失败不阻断最终记录；
8. 200% 字号与小屏无 RenderFlex overflow；
9. 触控区域与现有手势命中范围不缩小；
10. 不修改算法规则、数据库 schema 或历史数据；
11. `dart format`、`flutter analyze`、完整 `flutter test` 通过；
12. Pixel_7 模拟器主流程通过；
13. 真机综合验收继续延期到 MVP-B 完成后。
