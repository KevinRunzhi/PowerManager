# PowerManager MVP-B 阶段 B1-1：学习模式与变更通知 UI Spec v1

## 0. 文档状态

- 版本：1.0
- 日期：2026-08-15
- 状态：工程合同已冻结，B2-0 / B2-1 实施
- 产品状态：inconclusive
- 默认模式：baseline `off`、activityImpact `off`
- 正式生产与自动应用门：保持关闭

本 Spec 定义 MVP-B 模式授权、候选审核、自动安排、取消、撤回、暂停和历史界面。它不改变
MVP-A 首页主流程，也不把影子证据描述为医学判断或真实能力。

## 1. 信息架构

设置页新增“本机自动学习”入口，进入后固定包含：

1. 总状态说明：所有学习只在本机，关闭不删除观测；
2. 基准线卡片：当前模式、是否暂停、当前版本和最近事件；
3. 活动影响卡片：独立模式和状态，不继承基准线授权；
4. 待处理变化：全局最多一个；
5. 变更与学习记录；
6. 数据与隐私说明。

Data Health 继续只展示证据进度、排除和运行状态，不承担模式编辑或候选接受操作。

## 2. 模式选择

### 2.1 三种模式

| 模式 | 用户可见说明 | 行为 |
|---|---|---|
| off | 只保留记录，不运行这个项目的个性化学习 | 不创建新运行；取消该参数族未激活变化 |
| review | 系统在证据足够时提出小幅变化，由你决定是否应用 | 未接受前当前模型不变 |
| automatic | 安全门通过后自动安排未来变化，并提前通知；生效前可取消 | 仍受通知、边界、冷却、暂停和撤回保护 |

两个参数族分别保存选择。activityImpact 第一次出现时必须仍为 off，即使 baseline 已经
automatic。

### 2.2 首次授权说明

用户第一次为某参数族选择 review 或 automatic 前，显示一次不可跳过阅读但可取消的说明页：

- 使用哪些本机数据，明确不上传；
- 证据不足时不改变参数；
- review 与 automatic 的区别；
- 单步和累计变化边界；
- 最短通知时间和最早生效日；
- 生效前取消、生效后未来撤回；
- 关闭学习不会删除历史观测；
- 估计不是医学或能力结论。

主操作文案为“我了解，继续选择”，不能使用默认勾选。授权回执按参数族和说明版本保存。

### 2.3 正式门关闭

当前正式配置下，review / automatic 行显示为不可选，并说明“真实使用验证完成后开放”；off
保持可选。不得用灰色无说明控件，也不得因点击禁用项写模式。

显式预生产构建可以启用模式矩阵，但页面顶部和每个候选详情必须显示：

```text
工程预生产验证 · 不会进入正式版本
```

水印不可仅依赖颜色，语义标签必须包含“预生产”。

## 3. Review 候选详情

页面按以下顺序展示：

1. “系统观察到持续偏高 / 偏低”，不用“你的体力下降”等判断；
2. referenceType 的自然语言名称；
3. 合格证据数量、生活日范围、双窗口原始方向分布；
4. 排除数量与可展开原因，不展示内部 hash / run ID / model key；
5. 当前 base、候选 base、单步变化和相对 anchor 累计变化；
6. 冻结窗口反事实：更接近相符 / 没有有用改善 / 被安全门阻止；
7. 接受后的最早生效生活日和通知时间；
8. “接受并安排”“稍后处理”“拒绝”三个明确操作。

接受必须二次确认具体数值和生活日。稍后不启动拒绝冷却，但候选仍受 7 天预生产寿命；拒绝
进入对应冷却。过期页面只显示“证据已过期，继续观察”，不能复活原候选。

## 4. Automatic 变更通知

自动安排与 App 内通知必须同一事务成功。通知卡包含：

- 参数族与原因方向；
- 当前值 → 新值；
- 证据数和日期范围；
- 安排时间与生效生活日；
- “取消这次变化”和“查看学习记录”；
- 明确“尚未生效”。

系统级通知是增强：权限关闭、发送失败或被清除时，App 内通知仍在。若 App 内通知写入失败，
不得创建 scheduled 版本。

automatic 不发送倒计时催促。预生产配置每个 candidate 最多一条安排通知；同一 notice ID 重启、
恢复或重复 prepare 不重复生成。

## 5. 取消、撤回与手动冲突

### 5.1 生效前取消

确认文案必须同时说明：

- 当前值不会改变；
- 本次候选会终止；
- 原始观测不会删除；
- 对应参数族进入冷却。

取消成功后通知卡保留为历史，状态显示“已取消”，不消失。

### 5.2 生效后撤回

历史详情提供“安排撤回”。确认页展示：

- 当前 active 值；
- 将恢复的值；
- 撤回仍在未来生活日生效；
- 当前日和历史不会重算；
- 即使数值相同也会创建新 epoch，避免复用旧证据。

默认不自动撤回。撤回版本安排成功前 active 不变。

### 5.3 手动修改

用户手动设置基准线时，如存在该参数族未激活候选，确认页说明它会失效。手动值成为新 anchor，
创建新 epoch；不能直接更新 settings 中的整数。

## 6. 暂停与恢复

恶化门命中后显示非阻断但持续可见的状态卡：

```text
基准线学习已暂停
新一组观测出现了明显反向偏差。当前估计保持不变，不会自动回滚。
```

操作：

- 保持当前；
- 查看证据；
- 安排撤回；
- 恢复学习。

恢复前显示冷却、当前模式和新窗口要求。baseline 暂停不得改变 activityImpact 卡片；反之亦然。
同一 evidence hash 的暂停通知只生成一次。

## 7. 历史记录

列表项显示参数族、来源、状态、数值变化和时间。详情至少展示：

- creation / schedule source 的用户文案；
- 算法与配置的可理解版本标签；
- 证据聚合和排除摘要；
- parent → current 数值；
- 安排、生效、结束和状态原因；
- 可用的取消或撤回入口。

普通 UI 禁止展示：完整 evidence hash、确定性 ID、model regime key、数据库表名、堆栈和原始
活动正文。诊断导出仍按敏感数据处理。

## 8. 状态与失败文案

| 状态 | 用户文案 |
|---|---|
| insufficientEvidence | 继续自然记录，证据还不足 |
| unstable | 两个观察窗口方向不一致，暂不变化 |
| noChange | 当前没有足够理由改变参数 |
| configurationBlocked | 当前版本未开放这项变化 |
| retryableFailure | 本次检查未完成，稍后会安全重试 |
| terminalFailure | 本次证据无法处理，参数没有变化 |
| expired / invalidated | 证据或来源已经变化，本次建议已失效 |

错误文案必须先说明“当前参数没有变化”，再给出恢复动作。不得提示用户补造记录或为了达标选择
confirmed。

## 9. 可访问性与布局

- 200% 字号和最小支持屏幕无裁切、无横向滚动；
- 状态不只靠颜色，图标必须有语义标签；
- 单选模式至少 48dp 点击区域；
- TalkBack 依次读出参数族、当前模式、可用状态和后果；
- 数值变化读作“从 100 调整到 98”，不用裸箭头作为唯一信息；
- 取消、拒绝、撤回和关闭均有清晰焦点顺序；
- 日期使用生活日语义，同时在详情显示本地 04:00 生效说明。

## 10. 测试矩阵

- 两参数族 off / review / automatic 独立组合；
- 首次授权接受与取消；
- 正式门关闭与预生产水印；
- review 接受、稍后、拒绝、过期；
- automatic 安排、系统通知权限关闭、App 内通知写失败；
- 生效前取消、生效后撤回、手动冲突；
- 模式升降级不偷跑旧候选；
- 暂停、保持、恢复和参数族隔离；
- 重启、重复 prepare 和恢复不重复通知；
- 200% 字号、小屏、TalkBack 标签与无内部标识泄露。

## 11. 非目标

- B1-1 不把这些页面接到正式候选；
- 不增加趋势图、统计显著性、健康建议或云同步；
- 不用系统通知替代 App 内记录；
- 不在首页制造频繁学习提醒；
- 不把工程预生产水印隐藏在调试菜单外的正式路径中。
