## 1. 实现内容

### 1.1 可验证升级准备

- `BackupContentDigester` 对 schema v1 业务内容生成稳定 SHA-256 摘要；忽略 exportedAt、
  appVersion 和路径，并规范对象键与顶层实体集合顺序；
- `MvpBUpgradeReadinessService` 串联生活日准备、事务快照导出、严格解析、latest 保存、磁盘回读、
  当前数据复核和证明持久化；并发准备复用同一 in-flight 操作；
- readiness 证明只保存时间、文件元数据、schemaVersion、摘要和通过状态，不保存业务正文；
- 当前数据、latest 文件或证明变化后重新计算，不依赖 Widget 内存布尔值；
- 导出、内存校验、写入、磁盘回读、磁盘解析、内容不匹配和证明失败使用稳定的安全状态，不向 UI
  泄露异常堆栈、文件路径或记录内容。

### 1.2 固定文件安全

- latest、before-last-restore 和 readiness 文件统一使用 `RecoverableAtomicTextFile`；
- 替换顺序为临时文件写入并 flush、旧目标轮转、临时文件提升、旧副本清理；
- 中断后可从 `.previous` 恢复，成功提升后会清理陈旧副本与临时文件；
- 同一绝对路径的读、写、回读和保存后元数据获取均串行，避免读取与替换交叉；
- 注入失败、两类中断状态和双向读写并发均有回归测试。

### 1.3 用户界面与口径

- 设置页增加“MVP-B 升级准备”卡片、一键保存并验证动作、时间、大小和 schemaVersion；
- Data Health 复用同一 readiness 报告；
- 原“14 日 MVP-B 讨论门槛”改为“旧版自用讨论计数”，明确它不等于 MVP-B 可学习证据；
- schema v1、当前固定规则和既有 MVP-A 行为保持不变。

## 2. 测试中发现并修复的 P0

### 2.1 文件选择返回后恢复流程被销毁

首次模拟器恢复演练中，用户确认文件后恢复没有执行。诊断证明 Android 文件选择器返回会刷新
`currentPreparationRefreshProvider`，继而使 `appSettingsProvider` 进入 reload；默认
`AsyncValue.when` 会暂时切到 loading 并销毁 `_SettingsContent`，恢复协程随后因 `mounted == false`
安全退出。

修复：设置页对 reload 保留已有 data 内容，只在首次加载显示 loading。新增回归测试在编辑框保留
未提交内容时触发相同依赖 reload，验证页面状态和协程宿主不被销毁。

### 2.2 固定文件重复替换的跨平台风险

复核恢复问题时同时发现，旧固定文件写入逻辑依赖 `rename` 覆盖已存在目标，不同平台语义不一致，
且读取没有覆盖完整临界区。已改为显式可恢复轮转和按路径串行，避免把偶发文件系统行为带入
schema 迁移前置门。
