## 1.2 当前设备验收决策

- 中间阶段：自动化测试 + Pixel_7 模拟器；不操作物理手机，不交付最终 APK；
- 真实实验：在手机安装前不补造数据。需要真实自然数据的 B1-1、B2-2、B3-0、B3-2 先完成
  工程协议、模拟器生命周期和失败保护，产品状态暂记 `inconclusive`；
- 生产门：真实证据未形成时保持关闭，预生产参数只能存在于有显式水印的隔离配置；
- 最终阶段：完成模拟器总矩阵后才构建最终 APK，先备份手机 schema v1 数据，再覆盖安装并执行
  v1 → v5、历史、恢复和重启验收。

## 2. MVP-A 与 MVP-B 的关系

- MVP-A 是已经实现的固定规则、记录、实际状态和描述性复盘闭环，其正式文档继续冻结保留。
- MVP-B 的核心目标是本地、持续、可解释、可撤回的自动学习，而不是只展示建议。
- MVP-B 不重写 MVP-A 历史，也不把旧观测自动升级为可学习证据。
- MVP-B 先补齐可比较观测和无损升级，再让学习引擎在影子模式验证，最后按用户选择进入
  `review` 或 `automatic` 生产模式。
- 达到最低观测门槛只允许运行影子学习；生产阈值和开关未发布前，不得激活候选模型。

## 3. 已关闭的 P0 决策

1. 每日实际状态必须与同一参考时刻的系统估计快照配对。
2. 实际状态只做有序类别比较，不映射为伪精确精力值。
3. “MVP-A 有效日”和“MVP-B 可学习观测”使用不同资格口径。
4. 活动影响学习只读取与具体活动绑定的直接反馈。
5. B0 只采集；B1 自动运行影子学习，但不激活任何候选模型。
6. 旧版固定 7 日 `CalibrationCycle` 不恢复；每次学习使用冻结证据和独立生命周期。
7. 基准线和活动影响分别支持 `off / review / automatic`；`automatic` 可自动安排安全变化，
   无需逐条批准，新参数族不能继承另一参数族的旧授权。
8. 基准线与活动影响属于两个参数族，同一次学习运行不得同时更新。
9. 活动影响至少按“子类 × 影响方向”隔离；活动学习能力是 MVP-B 核心，不是可选实验。
10. 所有模型变化版本化、只在未来生活日生效；自动模式还必须满足通知窗口。变化不重写历史，
    并且可取消、可撤回。
11. Schema v1 到 v2 的无损迁移和 v1 备份兼容先于任何生产学习功能。
12. 登录、云同步、高级规则编辑、历史规则迁移和复杂趋势图不进入 MVP-B 核心范围。

## 4. 有意保留的阻塞参数

以下内容不是遗漏，而是必须由 B1 真实影子数据解除的生产门禁：

- 基准线学习的方向一致性阈值、单次步长、累计边界和冷却窗口；
- 活动影响学习的最小样本数、覆盖日数、一致性阈值、倍率范围和取整方式；
- 自动应用后的恶化判定、暂停和撤回提示阈值；
- 哪些候选只允许进入 `review`，哪些候选可以进入 `automatic`。
- 参数族的最小有用改善、不恶化边界、最大反馈负担和最大撤回 / 暂停比例。

这些参数当前在规则配置中保持未定义，生产开关保持关闭。任何人不得在 Widget、Service、
数据库默认值或测试夹具中私自写入候选值。真实数据不足时，正确结果是保持当前模型并继续
观察，而不是降低门槛。
