# 精力值管理产品 MVP-B Backlog v1

## 0. 验收基线

- 版本：1.3
- 日期：2026-08-15
- 状态：B1-0 已实现并通过；B1-1 工程决策轨执行中

本 Backlog 只承接 MVP-B v3 文档。优先级含义：

- P0：自动学习闭环或安全发布所必需，进入下一阶段前必须完成；
- P1：重要体验或可观测性，核心路径稳定后完成；
- P2：不影响自动学习成立的增强项。

每个 EPIC 的执行过程和阶段级验收证据以对应独立阶段 Spec 为准。任何 Story 都不能绕过
《精力值规则配置 v3（MVP-B）》中的禁用门。真实数据门禁没有通过时，
应停止在影子或当前模型，而不是使用隐藏默认参数。

## EPIC B0.1：文档与开工门禁

### US-B0.1.1 确认 MVP-B 产品基线

优先级：P0

验收标准：

- PRD、配置、算法、技术方案、Backlog、阶段计划和追踪矩阵职责不冲突；
- 明确 MVP-B 核心是基准线与活动影响的自动学习闭环；
- 明确两个参数族分别使用 `off / review / automatic`，且都默认 `off`；
- 生产学习与两个参数族的自动应用门保持关闭；
- 所有暂缺生产阈值都有真实数据决策门；
- 项目作者确认后才开始应用代码变更。

### US-B0.1.2 冻结 MVP-A 历史语义

优先级：P0

验收标准：

- `energy-rules-v2-mvp-a` 不原地修改；
- schema v1 历史活动、摘要和观测不重算；
- MVP-A 文档继续作为已实现行为的依据；
- MVP-B 新语义只应用于新合同数据。

## EPIC B0.2：升级安全

### US-B0.2.1 schema v1 迁移准备版

优先级：P0

用户故事：作为已有真实数据的用户，我希望升级前先有一份经过验证的本机备份。

验收标准：

- 仍使用 schema v1；
- 启动后可生成最新本机备份并完成再解析验证；
- 设置页显示备份时间和完整性；
- 失败不删除或覆盖已有数据；
- 真机完成一次备份与恢复演练后才允许发布 schema v2。

### US-B0.2.2 数据库 schema v2 无损迁移

优先级：P0

验收标准：

- Drift 提供显式 `onUpgrade`，迁移在单事务中完成；
- 原七表数据逐字段保持；
- legacy 观测不被标记为可学习；
- 新索引、CHECK、外键和保护触发器有效；
- 迁移失败完整回滚，不清库。

### US-B0.2.3 备份 schema v2

优先级：P0

验收标准：

- v2 App 可以导入 schemaVersion 1；
- schemaVersion 1 的新增字段映射为 legacy；
- schemaVersion 2 完整导出和恢复新观测与活动反馈；
- 损坏文件在替换数据库前被拒绝；
- Data Health 可以验证升级后的备份往返。

## EPIC B0.3：正确观测合同

### US-B0.3.1 同日实际状态配对

优先级：P0

用户故事：作为用户，我希望系统学习的是我填写状态时的估计，而不是后来变化的日终结果。

验收标准：

- 选择前不在 Sheet 内展示估计；
- 保存事务同时冻结当前估计、初始估计、比较档位和模型哨兵版本；
- 保存活动覆盖确认；
- 任一字段失败时整条写入回滚；
- 当前生活日允许更新，更新时整组快照同时替换；
- 揭示结果来自已保存快照。

### US-B0.3.2 补充昨日状态配对

优先级：P0

验收标准：

- 文案明确询问昨日结束时状态；
- 比较值来自昨日不可变摘要；
- 保存提交时间与参考生活日分开；
- 昨日已有状态后只读；
- 没有昨日摘要时不允许生成伪配对。

### US-B0.3.3 可学习资格与排除原因

优先级：P0

验收标准：

- 资格逻辑只有一个 Domain 实现；
- Data Health、影子和生产学习复用同一结果；
- MVP-A 有效日不自动等于可学习；
- 每条排除数据都有稳定 reason code；
- 不同 model regime 的数据不合并；
- currentMoment 与 previousLifeDayEnd 分组统计且不互相补足门槛；
- 当前生活日未结算数据只展示进度，不进入学习；
- legacy 数据只参与描述性复盘。

### US-B0.3.4 数据体检升级

优先级：P1

验收标准：

- 显示合格观测、排除观测和主要原因；
- 显示当前 model regime 的进度与日期跨度；
- “达到门槛”只表述为可以运行影子学习；
- 不展示私人活动明细。

## EPIC B0.4：活动绑定反馈

### US-B0.4.1 主动评价一条活动

优先级：P0

验收标准：

- 从当前生活日活动记录进入；
- 反馈包含更强、相符、更弱和方向不符；
- 同一活动最多一条 active 反馈；
- 保存活动、固定规则理论变化、实际变化、影响方向和规则版本快照；
- B0 / B1 不出现系统主动抽样提示；
- 保存反馈不会改变估计或活动参数。

### US-B0.4.2 编辑与删除后的反馈失效

优先级：P0

验收标准：

- 活动删除时关联反馈在同一事务内 invalidated；
- 反馈后修改子类、时长或完成时间时反馈失效；
- 恢复活动不会自动恢复旧反馈资格；
- 历史反馈保留失效原因并可备份恢复。

## EPIC B1：自动影子学习与生产决策

### US-B1.1 实现确定性影子学习器

优先级：P0

状态：已完成；自动化与 Pixel_7 模拟器工程验收通过，生产候选与激活仍关闭。

验收标准：

- 只读取单一 model regime 的合格证据；
- 通过独立 schema v3 迁移保存只读 `learning_runs`；
- 自动生成基准线影子证据运行和证据哈希；当前没有候选算法配置时候选值为空；
- 规范哈希通过 golden vectors，且输入不包含活动标题或备注；
- 输出证据数、日期范围、方向分布、双窗口一致性和排除摘要；
- 超过最低数量时稳定选取最近证据，排序、窗口和跨度与配置完全一致；
- 相同输入与版本得到字节级稳定结果；
- 瞬时失败复用同一 run 重试，确定性配置失败不会忙循环；
- 只有生活日结算后新增的不可变证据才触发运行；
- 不写 pending base、不创建可激活版本、不改变规则。

### US-B1.2 真实观察期审计

优先级：P0

验收标准：

- 不使用开发注入或补造数据通过产品门禁；
- 记录实际状态、覆盖确认和活动反馈的完成负担；
- 审计排除率、方向分布、反馈分布和 model regime 稳定性；
- 比较两种 reference type 的完成负担和方向分布，确定生产允许来源与优先级；
- 数据不足或方向不稳定时保持影子状态；
- 形成基准线生产参数决策，以及活动影响参数待补清单。

### US-B1.3 基准线生产算法决策门

优先级：P0

验收标准：

- 先发布 shadow-only 候选配置并完成反事实回放，再确定生产阈值、步长、累计边界、冷却和
  恶化保护；
- 明确 `review` 和 `automatic` 的安全门；
- 发布新的规则配置和算法版本；
- 完成反事实回放、极端输入和用户文案审查；
- 数据不足时保持 `baselineProductionLearningEnabled = false` 和
  `baselineAutoApplyEnabled = false`。

## EPIC B2：基准线自动学习闭环

本 EPIC 在 B1 决策门未通过时不可开始生产路径。

### US-B2.1 schema v4 与不可变模型版本

优先级：P0

验收标准：

- 在已有 `learning_runs` 上增加 `personalization_versions` 和分参数族模式设置；
- 升级时从当前值创建非伪学习的初始 active 版本；
- 初始基准线成为累计自动变化 anchor，自动调整与撤回不重置 anchor；
- 所有模型版本的 base 与 anchor 继续通过 `60～140` 数据库约束；
- 初始模型参数未变时沿用 `fixed-mvp-a` 有效参数指纹，不清零 B1 合格证据；
- 每次真实激活和撤回创建新 regime epoch，不能复用旧窗口立即重复候选；
- Stage 19 已有 pending base 被原子桥接为手动来源版本，到期 / 未来 / 残缺 / 重启场景均不
  丢失或重复应用；
- schema v4 前确认 pending rule 已结清；未决或残缺时回滚并保留兼容恢复路径；
- v4 后投影和结算只读 active 个人模型，不保留第二份可写基准线真源；
- 证据哈希唯一约束和唯一 active 约束有效；
- v4 备份往返和迁移失败回滚通过；
- 历史生活日不引用升级后新造的学习结果。

### US-B2.2 自动生成基准线候选

优先级：P0

验收标准：

- 新合格证据触发串行、幂等学习；
- 冻结证据、源模型、当前值、候选值、算法、配置和原因；
- 相同幂等键不重复运行或生成版本；
- 冷却、边界、反事实或证据门失败时保持当前模型；
- 连续版本始终相对 baseline anchor 检查累计边界；
- 证据年龄和候选生命周期超限时失效，重启或切换模式不能复活；
- 全局已有任一参数族待处理版本时，不再生成基准线候选。

### US-B2.3 分参数族的三种学习模式

优先级：P0

验收标准：

- 首次启用前展示本机数据用途、自动变化边界和撤回方式；
- 基准线与活动影响模式分别保存且默认 `off`；
- 对应参数族的 `off` 不生成新的影子或生产运行，并取消该参数族未激活版本；
- `review` 自动学习但未经接受不安排变化；
- `automatic` 通过自动安全门后直接安排最早可生效的未来生活日；
- `review → automatic` 不自动应用旧候选，`automatic → review` 把未生效安排退回待审核；
- B3 新增活动影响能力时保持 `off`，不继承已有基准线授权；
- 拒绝、取消和撤回后进入配置冷却期，不用一条新证据立即重复提示；
- 模式切换和待处理状态原子更新，可备份恢复。

### US-B2.4 幂等激活、通知与撤回

优先级：P0

验收标准：

- 自动安排后立即展示变更内容、生效日和取消入口；
- 自动安排与持久化 App 内通知原子提交，系统通知权限关闭不丢失入口；
- 生效日严格晚于当前生活日，并保证配置规定的最短取消时间；
- 激活前证据内容、源 regime 或父模型变化会使候选失效；
- 生产门关闭、模式降级、暂停或算法 / 配置撤回时不激活旧候选；
- 跨 04:00、重启、重复 prepare 和恢复只激活一次；
- 恢复出的已到期 / 过期自动安排不会在首次启动静默补应用；明确接受或手动安排仍按原决定
  幂等处理；
- 激活后建立新 model regime，历史和已开始生活日不重算；
- 手动修改使旧候选失效；
- 撤回创建未来恢复版本而不是改历史。

### US-B2.5 调整后监测与暂停

优先级：P0

验收标准：

- 新旧 model regime 不混合；
- 展示方向性变化，不宣称科学准确；
- 达到恶化阈值后暂停基准线自动学习并通知用户；
- 暂停不会自动来回改值；
- 用户可以撤回、恢复学习或保持当前版本。

## EPIC B3：活动影响自动学习闭环

### US-B3.1 活动反馈可行性与生产参数门

优先级：P0

验收标准：

- 分析各“子类 × 影响方向”的反馈量、跨日覆盖、相符比例和失效比例；
- 检查同一键跨固定规则时长档位是否可由单一倍率解释；
- 单独识别零值、方向不符和恢复上限截断；
- 确定 directionMismatch 否决阈值，命中后停止该键倍率学习；
- 用真实反馈确定样本门槛、倍率范围、步长、冷却和恶化保护；
- 没有合格键时保持当前模型，不降低门槛；
- 发布 B3 规则配置、算法和 schema v5 迁移 Spec。

### US-B3.2 schema v5 与活动计算快照

优先级：P0

验收标准：

- 按个人模型版本、子类和影响方向保存倍率；
- 不存在倍率时稳定使用 `1.0`；
- 迁移后所有倍率仍为隐含 `1.0` 时不改变有效模型指纹；
- v2 主动反馈迁移后明确为 userInitiated，不能获得生产倍率资格；
- 新活动冻结所用个人模型版本和倍率；
- 倍率只在 base activity rule version 匹配时应用；
- schema v5 迁移、备份往返和失败回滚通过；
- 固定规则表和历史活动不被重算。

### US-B3.3 低负担活动反馈抽样

优先级：P0

验收标准：

- 只有用户开启 `review / automatic` 后才按已发布策略提示；
- 抽样不读取之后的反馈，也不只挑误差大或用户主动打开的活动；
- 提示可跳过，受每日上限和冷却控制，同日不反复追问；
- 保存 collection source、sampling policy、被抽中与响应状态；
- 主动反馈与抽样反馈在报告和生产资格中严格分开。

### US-B3.4 活动影响学习器

优先级：P0

验收标准：

- 只读取合格的活动绑定反馈；
- 生产倍率只读取受支持抽样策略产生的反馈；
- 恢复证据不能改变同子类消耗倍率，反之亦然；
- 零值、截断和 `directionMismatch` 不驱动倍率；
- 只使用当前 factor regime 开始后产生的反馈，旧 regime 证据不重复推动下一步；
- 只改变基准线时保留活动 factor regime，不把旧反馈伪装成新证据；
- 相同输入确定、同一证据幂等；
- 一次运行只改变活动影响参数族。

### US-B3.5 自动应用与调整后监测

优先级：P0

验收标准：

- `review / automatic` 复用 B2 的安排、通知、取消和撤回机制；
- 生产候选受 `activityImpactProductionLearningEnabled` 控制，自动应用额外受
  `activityImpactAutoApplyEnabled` 控制；
- 与基准线候选同时出现时只激活配置优先的一个参数族；
- 新反馈达到恶化条件时暂停对应参数族；
- 使用明确标记的测试证据完成“反馈 → 学习 → 安排 → 激活 → 评估 / 撤回”工程生命周期，
  真实数据仍必须独立满足生产门禁。

## P1 / P2 增强项

- P1：学习记录筛选、排除原因解释和当前模型详情；
- P2：更丰富的长期趋势可视化；
- P2：在不破坏参数族隔离的前提下研究时长分组。

## 明确不进入 Backlog

- 登录、云同步和社交；
- 自动读取健康设备、屏幕时间或课表；
- 不透明、无边界、不可取消或不可撤回的自动更新；
- 高级规则编辑和历史规则迁移；
- 通用机器学习平台或需要云训练的预测模型；
- 同一次学习运行同时修改基准线与活动影响；
- 为 24 个子类强行生成个性化结果；
- 为了通过门禁补造真实使用数据。
