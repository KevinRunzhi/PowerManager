# 精力值算法规则初稿

## 0. 文档定位

本文档用于补充 PRD 中不适合展开的算法细节，先作为第一版实现参考。

原则：
- 第一版采用可解释的规则算法，不做复杂机器学习模型。
- 所有自动调整都应保守、小步、可回退。
- 用户可理解优先于绝对精确。
- 算法参数后续可根据真实使用数据调整。

---

# 1. 核心对象

## 1.1 个人基准线

个人基准线表示用户近期稳定状态下的日常初始精力水平。

第一版规则：
- 默认值：100
- 每累计 7 个有效使用日评估一次
- 系统只给建议值，用户确认后才生效
- 单周期系统建议调整最多 ±8
- 常规调整范围为 ±3～5

## 1.2 当日初始精力

当日初始精力由三部分组成：

```text
当日初始精力 = 个人基准线 + 早间微调 + 短期修正
```

其中：
- 个人基准线：慢变量，每 7 个有效使用日评估一次
- 早间微调：当天主观状态带来的轻微修正
- 短期修正：上一生活日透支等短期状态带来的轻微影响

---

# 2. 第二天初始精力的透支修正

## 2.1 设计目标

透支应影响第二天自动初始精力，但不能像惩罚系统。

因此第一版采用：

```text
短期轻微影响 + 周期趋势判断
```

也就是说：
- 单日透支会轻微影响第二天自动初始精力
- 单日透支不会大幅降低个人基准线
- 多次透支会进入 7 个有效使用日周期评估

## 2.2 透支分档

以生活日结算时的最终剩余精力为准。

| 昨日最终剩余精力 | 第二天短期修正 |
|---:|---:|
| >= 0 | 0 |
| -1 到 -5 | -1 |
| -6 到 -10 | -2 |
| -11 到 -20 | -3 |
| < -20 | -4 |

## 2.3 短期修正规则

短期修正只影响第二天自动初始精力，不直接改变个人基准线。

示例：

```text
个人基准线 = 100
早间微调 = 0
昨日最终剩余精力 = -12
短期修正 = -3
第二天自动初始精力 = 97
```

## 2.4 连续透支处理

如果连续多个生活日透支：
- 每天仍按上表计算第二天短期修正
- 短期修正下限为 -5
- 不允许因为连续透支在单日内产生更大惩罚

连续透支主要通过 7 个有效使用日周期评估影响个人基准线。

# 3. 个人模型参数更新

## 3.1 第一版更新对象

第一版不直接暴露活动消耗系数给用户。

系统内部可以为每个子类维护一个轻量个性化修正值：

```text
子类个人修正值 personal_offset
```

计算时：

```text
本次精力影响 = 默认规则结果 + 子类个人修正值
```

说明：
- 消耗类活动的结果通常为负数
- 恢复类活动的结果通常为正数
- personal_offset 可以为正或负
- 第一版不建议按每个时长档位分别维护参数，先按子类维护即可

## 3.2 更新信号来源

第一版主要使用两类弱信号：

1. 校准期抽样反馈
   - 系统估计偏轻
   - 差不多
   - 系统估计偏重

2. 后续用户主动修正规则或近期重算结果
   - 只作为辅助信号
   - 不因单次修改立即改变长期模型

## 3.3 信号方向定义

为避免不同活动正负号混乱，统一按“影响强度”理解。

- 系统估计偏轻：用户感觉实际影响更强，后续应增加该子类影响强度
- 系统估计偏重：用户感觉实际影响更弱，后续应降低该子类影响强度
- 差不多：不推动参数变化

对于消耗类：
- 增加强度 = 数值更负
- 降低强度 = 数值向 0 靠近

对于恢复类：
- 增加强度 = 数值更正
- 降低强度 = 数值向 0 靠近

## 3.4 更新触发阈值

每累计 7 个有效使用日评估一次子类个人修正。

某个子类需要同时满足以下条件才允许更新：

- 最近 7 个有效使用日内，该子类至少有 3 条有效反馈信号
- 同方向反馈占比 >= 70%
- 至少覆盖 2 个不同生活日

不满足条件时，不更新该子类个人修正值。

## 3.5 单次更新幅度

第一版采用小步更新。

| 趋势强度 | 条件 | 单次更新 |
|---|---|---:|
| 弱趋势 | 3 条同方向反馈，且占比 >= 70% | ±1 |
| 中趋势 | 4～5 条同方向反馈，且占比 >= 70% | ±2 |
| 强趋势 | >= 6 条同方向反馈，且占比 >= 80% | ±3 |

说明：
- 对消耗类，增强影响时 personal_offset 向负方向调整
- 对恢复类，增强影响时 personal_offset 向正方向调整
- 降低影响时向 0 方向调整

## 3.6 子类修正值上限

为了避免模型漂移，第一版限制每个子类的个人修正值范围：

```text
-6 <= personal_offset <= +6
```

如果某个子类持续需要超过该范围，先不继续自动扩大，后续版本再考虑更细模型。

## 3.7 异常日过滤

以下生活日的数据不用于自动更新子类个人修正值，但仍保留原始记录：

- 当日记录次数明显异常，例如超过 12 次
- 当日最终剩余精力低于 -30
- 当日早间确认缺失，且仅满足弱有效使用日
- 用户当天进行了规则映射修改，导致近期重算

这些数据可以展示，但不作为参数更新依据。

# 4. 个人基准线周期评估

## 4.1 评估指标

个人基准线每 7 个有效使用日评估一次。

核心指标：
- 低精力 / 透支出现频率
- 当日最终剩余精力
- 早间综合状态趋势

辅助指标：
- 恢复类活动效果

## 4.2 建议调整规则

| 周期表现 | 建议调整 |
|---|---:|
| 明显变好 | +6 到 +8 |
| 小幅变好 | +3 到 +5 |
| 基本稳定 | 0 |
| 小幅变差 | -3 到 -5 |
| 明显变差 | -6 到 -8 |

## 4.3 透支对基准线的影响

透支不会因为单日事件直接调整个人基准线。

进入周期评估时：
- 最近 7 个有效使用日中透支 1 次：通常不单独触发下调
- 透支 2 次：可视为小幅变差信号
- 透支 >= 3 次：视为明显负荷偏高信号

最终仍需结合最终剩余精力、早间状态和恢复效果综合判断。

# 5. 活动变化值与重算

## 5.1 理论变化值与实际应用值

每条活动记录同时保存两个变化值：

```text
theoreticalDelta = 按默认规则 + 子类个人修正值计算出的原始变化值
appliedDelta = 实际应用到当前剩余精力的变化值
```

说明：
- 消耗类活动的 `theoreticalDelta` 通常为负数。
- 恢复类活动的 `theoreticalDelta` 通常为正数。
- 当恢复类活动触发恢复上限时，`appliedDelta` 可能小于 `theoreticalDelta`。
- 首页、今日概览、昨日总结、生活日结算优先使用 `appliedDelta`。
- 趋势分析和规则重算可以保留 `theoreticalDelta` 作为辅助判断依据。

## 5.2 恢复上限

恢复类活动只能补回当天已经消耗的精力，不能让当前剩余精力超过当日初始精力。

计算方式：

```text
如果 theoreticalDelta > 0：
appliedDelta = min(theoreticalDelta, 当日初始精力 - 当前剩余精力)

如果 theoreticalDelta <= 0：
appliedDelta = theoreticalDelta
```

示例：

```text
当日初始精力 = 100
当前剩余精力 = 96
恢复活动 theoreticalDelta = +10
appliedDelta = min(10, 4) = +4
```

## 5.3 撤销与事件流重放

第一版撤销采用逻辑删除：
- 活动记录状态从 `active` 变为 `cancelled`
- 写入 `cancelledAt`
- 业务计算只处理 `status = active` 的记录

撤销后的当前剩余精力，推荐通过事件流重放得到：

```text
当前剩余精力 = 当日初始精力 + 按完成时刻排序后的所有 active 记录 appliedDelta 之和
```

说明：
- 不使用简单的反向加减来回滚，避免恢复上限造成误差。
- 重算最近 7 个有效使用日时，同样按生活日内完成时刻顺序重放。
- `cancelled` 记录不参与首页、概览、结算、校准、模型学习和重算。
- 当日初始精力变化或规则变更后，需要通过事件流重放重新计算并刷新对应生活日内所有 `active` 记录的 `appliedDelta`。

# 6. 昨日标签规则

## 6.1 输入数据

昨日标签基于生活日结算数据生成。

输入包括：
- 当日初始精力
- 最终剩余精力
- 总消耗
- 总恢复
- 各大类时间
- 各大类 `appliedDelta` 汇总
- 是否进入低精力 / 透支

## 6.2 标签库

第一版使用固定标签库，最多展示 3 个。

| 标签 | 触发条件 | 固定解释文案 |
|---|---|---|
| 整体稳定 | 最终剩余精力在当日初始精力的 25% 到 75% 之间，且未透支 | 昨天的精力使用处在较稳定区间。 |
| 精力偏低 | 最终剩余精力低于当日初始精力的 25%，但未透支 | 昨天后段可用精力已经偏低。 |
| 发生透支 | 最终剩余精力低于 0 | 昨天的负荷超过了当日储备。 |
| 恢复不足 | 总恢复小于总消耗的 20%，且最终剩余精力低于当日初始精力的 50% | 昨天恢复投入相对不足。 |
| 恢复有效 | 总恢复大于等于总消耗的 30%，且最终剩余精力未低于当日初始精力的 25% | 昨天的恢复对状态有一定帮助。 |
| 学习占比较高 | 学习类时间占总记录时间的 50% 及以上 | 昨天主要精力集中在学习上。 |
| 实践事务占比较高 | 实践 / 事务类时间占总记录时间的 50% 及以上 | 昨天主要精力集中在实践事务上。 |
| 娱乐占比较高 | 娱乐消遣类时间占总记录时间的 40% 及以上 | 昨天有较多时间用于娱乐消遣。 |

## 6.3 标签优先级

当命中超过 3 个标签时，按以下优先级取前 3 个：

1. 发生透支
2. 精力偏低
3. 恢复不足
4. 恢复有效
5. 学习占比较高
6. 实践事务占比较高
7. 娱乐占比较高
8. 整体稳定

说明：
- 标签偏状态结果型，不做复杂原因归因。
- 文案使用固定模板，不在第一版生成复杂动态解释。
- 如果没有命中任何特殊标签，仍可兜底展示“整体稳定”，此时它表示没有明显异常状态，而不是严格命中 25% 到 75% 的触发条件。

# 7. 第一版暂不做

第一版暂不做：
- 按上午 / 下午 / 晚上分别建模
- 按具体时长档位分别学习参数
- 复杂机器学习模型
- 自动推断具体任务
- 向用户暴露每个子类的底层系数
- 全量历史重算
