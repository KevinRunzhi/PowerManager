# 精力值算法规则初稿

## 0. 文档定位

最近修订：2026-07-22，当前算法机制已与《精力值规则配置 v1》对齐；文件名保留“初稿”仅用于兼容现有引用。

本文档用于补充 PRD 中不适合展开的算法细节，先作为第一版实现参考。

具体参数以《精力值规则配置 v1》为唯一来源。本文档负责解释算法机制，不重复维护活动数值表。

原则：
- 第一版采用可解释的规则算法，不做复杂机器学习模型。
- 所有自动调整都应保守、小步、可回退。
- 用户可理解优先于绝对精确。
- 算法参数后续可根据真实使用数据调整。

---

# 1. 核心对象

## 1.1 个人基准线

个人基准线表示用户近期稳定状态下的日常初始精力水平。

第一版规则：
- 默认值：100
- 每累计 7 个有效使用日评估一次
- 系统只给建议值，用户确认后才生效
- 单周期系统建议调整最多 ±8
- 常规调整范围为 ±3～5

## 1.2 当日初始精力

当日初始精力由三部分组成：

```text
当日初始精力 = 个人基准线 + 早间微调 + 短期修正
```

其中：
- 个人基准线：慢变量，每 7 个有效使用日评估一次
- 早间微调：当天主观状态带来的轻微修正
- 短期修正：上一生活日透支等短期状态带来的轻微影响

---

# 2. 第二天初始精力的透支修正

## 2.1 设计目标

透支应影响第二天自动初始精力，但不能像惩罚系统。

因此第一版采用：

```text
短期轻微影响 + 周期趋势判断
```

也就是说：
- 单日透支会轻微影响第二天自动初始精力
- 单日透支不会大幅降低个人基准线
- 多次透支会进入 7 个有效使用日周期评估

## 2.2 透支分档

以生活日结算时的最终剩余精力为准。

| 昨日最终剩余精力 | 第二天短期修正 |
|---:|---:|
| >= 0 | 0 |
| -1 到 -5 | -1 |
| -6 到 -10 | -2 |
| -11 到 -20 | -3 |
| < -20 | -4 |

## 2.3 短期修正规则

短期修正只影响第二天自动初始精力，不直接改变个人基准线。

示例：

```text
个人基准线 = 100
早间微调 = 0
昨日最终剩余精力 = -12
短期修正 = -3
第二天自动初始精力 = 97
```

## 2.4 连续透支处理

如果连续多个生活日透支：
- 每天仍按上表计算第二天短期修正
- 不跨生活日累加短期修正
- 不允许因为连续透支在单日内产生额外惩罚

短期修正只读取紧邻的前一个生活日。如果前一个生活日没有每日状态，则修正为 0，空生活日会中断短期影响。

连续透支主要通过 7 个有效使用日周期评估影响个人基准线。

# 3. 个人模型参数更新

## 3.1 第一版更新对象

第一版不直接暴露活动消耗系数给用户。

系统内部为每个子类维护一个轻量个性化强度参数：

```text
子类个人强度倍率 personalFactor
```

计算时：

```text
默认值为 0：theoreticalDelta = 0
默认值非 0：theoreticalDelta = sign(defaultDelta) * round(abs(defaultDelta) * personalFactor)
```

说明：
- `personalFactor` 默认 1.00，范围 0.70 到 1.30
- 参数只改变影响强度，不改变默认值的正负方向
- 活动大类不决定数值方向；每个“子类 × 时长”单元格独立定义正、零或负值
- 默认值为 0 的记录不参与个性化强度学习
- 第一版按子类维护倍率，不按每个时长档位分别维护

## 3.2 更新信号来源

第一版主要使用两类弱信号：

1. 校准期抽样反馈
   - 系统估计偏轻
   - 差不多
   - 系统估计偏重

2. 后续显式规则迁移结果
   - 只用于判断周期数据是否需要失效和重新生成
   - 不作为单条活动的体感反馈

## 3.3 信号方向定义

为避免正负号混乱，统一按“影响强度”更新倍率。

- 系统估计偏轻：增大 `personalFactor`
- 系统估计偏重：减小 `personalFactor`
- 差不多：不推动参数变化

倍率方式会自动让负值变得更负或更接近 0，让正值变得更正或更接近 0，同时禁止符号反转。

## 3.4 更新触发阈值

每累计 7 个有效使用日评估一次子类个人修正。

某个子类需要同时满足以下条件才允许更新：

- 本周期内，该子类至少有 3 条 `active` 反馈信号
- 同方向反馈占全部 `active` 反馈的比例 >= 70%，`aboutRight` 计入分母
- 至少覆盖 2 个不同生活日

不满足条件时，不更新该子类 personalFactor。

## 3.5 单次更新幅度

第一版采用小步更新。

| 趋势强度 | 条件 | 单次更新 |
|---|---|---:|
| 弱趋势 | 3 条同方向反馈，且占比 >= 70% | 0.05 |
| 中趋势 | 4～5 条同方向反馈，且占比 >= 70% | 0.10 |
| 强趋势 | >= 6 条同方向反馈，且占比 >= 80% | 0.15 |

说明：
- “估计偏轻”时增加上述步长
- “估计偏重”时减少上述步长
- 更新后截断到 0.70 到 1.30

## 3.6 子类修正值上限

为了避免模型漂移，第一版限制每个子类的个人倍率范围：

```text
0.70 <= personalFactor <= 1.30
```

如果某个子类持续需要超过该范围，先不继续自动扩大，后续版本再考虑更细模型。

## 3.7 异常日过滤

以下生活日的数据不用于自动更新子类 personalFactor，但仍保留原始记录：

- 当日 active 记录次数超过 12 次
- 当日最终剩余精力低于 -30
- 用户当天进行了规则迁移重算

弱有效使用日中的直接反馈可以参与参数更新，因为它是用户对具体记录的显式体感信号。

这些数据可以展示，但不作为参数更新依据。

# 4. 个人基准线周期评估

## 4.1 评估指标

个人基准线按非重叠的 7 个有效使用日周期评估一次。

核心指标：
- 低精力 / 透支出现频率
- 当日最终剩余精力
- 早间综合状态趋势

辅助指标：
- 恢复类活动效果

标准有效使用日的计算权重为 1.0，弱有效使用日为 0.5。两类日期推进周期时都计为 1 天。

## 4.2 建议调整规则

对每个有效使用日计算：

```text
finalRatio = finalEnergy / initialEnergy
```

结果分：

| 条件 | outcomeScore |
|---|---:|
| finalEnergy < 0 | -2.0 |
| 0 <= finalRatio < 0.25 | -1.0 |
| 0.25 <= finalRatio <= 0.75 | 0.0 |
| finalRatio > 0.75 | +1.0 |

早间状态辅助分：差为 -0.5，一般为 0，好为 +0.5，缺失为 0。

```text
dayScore = outcomeScore + morningScore
cycleScore = sum(dayScore * dayWeight) / sum(dayWeight)
```

建议值：

| cycleScore | 建议调整 |
|---:|---:|
| < -1.50 | -8 |
| [-1.50, -0.75) | -5 |
| [-0.75, -0.25) | -3 |
| [-0.25, 0.25) | 0 |
| [0.25, 0.75) | +3 |
| [0.75, 1.25) | +5 |
| >= 1.25 | +8 |

建议后的个人基准线截断到 60 到 140。恢复投入只用于原因摘要，不直接增加得分。

建议变化为 0 时只生成“保持当前估计基准”的结果摘要，不进入需要用户决策的周调整流程。

## 4.3 透支对基准线的影响

透支不会因为单日事件直接调整个人基准线。

透支通过单日 `outcomeScore = -2.0` 进入周期得分，不再额外叠加第二套扣分，避免重复计算。

该建议是“近期适用的估计基准”，不是对用户能力的科学评分。系统只生成建议，用户接受后从决策发生时所属生活日的下一个生活日起生效。

# 5. 活动变化值与重算

## 5.1 理论变化值与实际应用值

每条活动记录同时保存两个变化值：

```text
theoreticalDelta = 按默认规则版本和子类 personalFactor 计算出的原始变化值
appliedDelta = 实际应用到当前剩余精力的变化值
```

说明：
- 消耗类活动的 `theoreticalDelta` 通常为负数。
- 恢复类活动的 `theoreticalDelta` 通常为正数。
- 当恢复类活动触发恢复上限时，`appliedDelta` 可能小于 `theoreticalDelta`。
- 首页、今日概览、昨日总结、生活日结算优先使用 `appliedDelta`。
- 趋势分析和规则重算可以保留 `theoreticalDelta` 作为辅助判断依据。
- 每条记录必须保存 `ruleVersion` 和个性化参数版本或快照，保证结果可追溯。

## 5.2 恢复上限

恢复类活动只能补回当天已经消耗的精力，不能让当前剩余精力超过当日初始精力。

计算方式：

```text
如果 theoreticalDelta > 0：
appliedDelta = min(theoreticalDelta, 当日初始精力 - 当前剩余精力)

如果 theoreticalDelta <= 0：
appliedDelta = theoreticalDelta
```

示例：

```text
当日初始精力 = 100
当前剩余精力 = 96
恢复活动 theoreticalDelta = +10
appliedDelta = min(10, 4) = +4
```

## 5.3 撤销与事件流重放

第一版撤销采用逻辑删除：
- 活动记录状态从 `active` 变为 `cancelled`
- 写入 `cancelledAt`
- 业务计算只处理 `status = active` 的记录

撤销后的当前剩余精力必须通过事件流重放得到，不允许对被撤销记录做反向加减。

```text
记录顺序 = completedAt ASC, createdAt ASC, id ASC
当前剩余精力 = 从 initialEnergy 开始逐条重新应用所有 active 记录
```

说明：
- 不使用简单的反向加减来回滚，避免恢复上限造成误差。
- `cancelled` 记录不参与首页、概览、结算、校准、模型学习和重算。
- 当日初始精力变化后，使用记录中已保存的 `theoreticalDelta` 重算全部 `appliedDelta`。

重放分为两种模式：

### 普通重放 operationalReplay

- 用于新增、撤销、补做早间和当日初始精力变化。
- 读取记录中已保存的 `theoreticalDelta`。
- 只重新计算 `appliedDelta`、当前精力和每日汇总。
- 不得改变历史记录的 `theoreticalDelta` 和规则版本。

### 规则迁移重放 ruleMigrationReplay

- 只在用户确认修改默认规则后显式执行。
- 使用指定的新规则版本和每条记录原有的个性化参数快照重新计算目标窗口内的 `theoreticalDelta`。
- 再按稳定事件顺序重算 `appliedDelta` 和每日汇总。
- 目标窗口为当前未结算生活日和最近 7 个有效使用日。
- 从最早受影响生活日起向后重算；窗口内相邻生活日重新计算短期修正，空生活日中断传播。
- 已接受或拒绝的校准周期保持冻结；包含受影响日期的 pending / deferred 建议失效并重新生成。
- 更早历史保留原规则版本和原始计算结果。

# 6. 昨日标签规则

## 6.1 输入数据

昨日标签基于生活日结算数据生成。

汇总口径：

```text
总消耗 = 所有 appliedDelta < 0 的绝对值之和
总恢复 = 所有 appliedDelta > 0 的值之和
```

汇总按数值正负判断，不按活动大类判断。

输入包括：
- 当日初始精力
- 最终剩余精力
- 总消耗
- 总恢复
- 各大类时间
- 各大类 `appliedDelta` 汇总
- 是否进入低精力 / 透支

## 6.2 标签库

第一版使用固定标签库，最多展示 3 个。

| 标签 | 触发条件 | 固定解释文案 |
|---|---|---|
| 整体稳定 | 最终剩余精力在当日初始精力的 25% 到 75% 之间，且未透支 | 昨天的精力使用处在较稳定区间。 |
| 精力偏低 | 最终剩余精力低于当日初始精力的 25%，但未透支 | 昨天后段可用精力已经偏低。 |
| 发生透支 | 最终剩余精力低于 0 | 昨天的负荷超过了当日储备。 |
| 恢复不足 | 总恢复小于总消耗的 20%，且最终剩余精力低于当日初始精力的 50% | 昨天恢复投入相对不足。 |
| 恢复有效 | 总恢复大于等于总消耗的 30%，且最终剩余精力未低于当日初始精力的 25% | 昨天的恢复对状态有一定帮助。 |
| 学习占比较高 | 学习类时间占总记录时间的 50% 及以上 | 昨天主要精力集中在学习上。 |
| 实践事务占比较高 | 实践 / 事务类时间占总记录时间的 50% 及以上 | 昨天主要精力集中在实践事务上。 |
| 娱乐占比较高 | 娱乐消遣类时间占总记录时间的 40% 及以上 | 昨天有较多时间用于娱乐消遣。 |

## 6.3 标签优先级

当命中超过 3 个标签时，按以下优先级取前 3 个：

1. 发生透支
2. 精力偏低
3. 恢复不足
4. 恢复有效
5. 学习占比较高
6. 实践事务占比较高
7. 娱乐占比较高
8. 整体稳定

说明：
- 标签偏状态结果型，不做复杂原因归因。
- 文案使用固定模板，不在第一版生成复杂动态解释。
- 如果没有命中任何特殊标签，仍可兜底展示“整体稳定”，此时它表示没有明显异常状态，而不是严格命中 25% 到 75% 的触发条件。

# 7. 第一版暂不做

第一版暂不做：
- 按上午 / 下午 / 晚上分别建模
- 按具体时长档位分别学习参数
- 复杂机器学习模型
- 自动推断具体任务
- 向用户暴露每个子类的底层系数
- 全量历史重算
