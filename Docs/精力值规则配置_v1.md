# 精力值规则配置 v1

## 0. 文档定位

本文档是第一版精力计算参数的唯一正式来源，负责定义：

- 规则版本与历史重放边界
- 20 个活动子类在 6 个时长档位下的默认精力变化
- 早间微调
- 透支短期修正
- 精力档位与提醒边界
- 校准抽样条件
- 个性化强度参数
- 7 个有效使用日的基准线建议公式

PRD 负责用户可感知行为，算法规则负责解释计算机制，技术方案负责实现方式；具体参数均以本文档为准。

当前版本：

```text
ruleVersion = energy-rules-v1
calibrationAlgorithmVersion = calibration-v1
```

规则调整时必须创建新版本，不得静默修改 v1 的含义。

---

# 1. 通用计算约定

## 1.1 时长档位

只允许以下时长：

```text
15, 30, 45, 60, 90, 120 分钟
```

## 1.2 默认变化值

每个“子类 × 时长”单元格独立产生正、零或负值：

- 正数：恢复
- 0：不改变当前精力
- 负数：消耗

活动大类只用于产品展示，不决定变化值方向。

## 1.3 理论值与实际值

```text
defaultDelta = 默认规则表中的值
theoreticalDelta = applyPersonalFactor(defaultDelta, personalFactor)
appliedDelta = applyRecoveryCap(theoreticalDelta, currentEnergy, initialEnergy)
```

默认值为 0 时，`theoreticalDelta` 固定为 0，不应用个性化强度参数。

正数变化受恢复上限约束，负数变化允许使当前精力低于 0。

## 1.4 取整

个性化计算使用四舍五入到整数，`.5` 远离 0 取整：

```text
adjustedMagnitude = roundHalfAwayFromZero(abs(defaultDelta) * personalFactor)
theoreticalDelta = sign(defaultDelta) * adjustedMagnitude
```

## 2.6 可编辑等级映射

实现时每个规则单元格保存稳定的 `levelKey`，数值由当前规则版本的等级映射生成：

```text
recoveryLight, recoveryMedium, recoveryHigh, neutral,
consumptionLight, consumptionLightMedium, consumptionMedium,
consumptionMediumHigh, consumptionHigher, consumptionHigh,
consumptionVeryHigh
```

v1 数值表可以通过上节映射唯一还原为 levelKey。用户修改的是 levelKey 到数值的映射，不直接逐格修改 120 个单元格。

用户映射必须满足：

```text
neutral = 0
1 <= recoveryLight <= recoveryMedium <= recoveryHigh <= 30
1 <= abs(consumptionLight)
  <= abs(consumptionLightMedium)
  <= abs(consumptionMedium)
  <= abs(consumptionMediumHigh)
  <= abs(consumptionHigher)
  <= abs(consumptionHigh)
  <= abs(consumptionVeryHigh)
  <= 40
```

恢复等级始终为正，消耗等级始终为负，设置页不得保存会反转符号或破坏强度顺序的映射。

# 3. 早间确认与当日初始精力

## 3.1 三项输入的职责

| 输入 | 是否影响 morningAdjustment | v1 用途 |
|---|:---:|---|
| 综合状态 | 是 | 当日初始精力微调、周期评估辅助信号 |
| 可自由安排时间 | 否 | 周期原因摘要和产品研究上下文 |
| 主要压力来源 | 否 | 低精力方向建议和周期原因摘要 |

自由时间不等于精力，压力来源也不直接代表精力高低，因此二者不参与数值计算。

## 3.2 综合状态映射

| 综合状态 | morningAdjustment |
|---|---:|
| 差 | -6 |
| 一般 | 0 |
| 好 | +6 |

跳过早间确认时：

```text
morningAdjustment = 0
```

首次默认快速开始使用：

```text
overallState = normal
freeTimeLevel = medium
pressureSource = both
morningAdjustment = 0
isDefaultQuickStart = true
```

## 3.3 当日初始精力

```text
initialEnergy = baseEnergy + morningAdjustment + shortTermAdjustment
```

个人基准线修改和周期建议接受后，从决策发生时所属生活日的下一个生活日起生效，不重算当前生活日。

# 4. 透支短期修正

短期修正只读取紧邻的前一个生活日：

- 前一个生活日没有 DailyEnergyState 时，修正为 0。
- 空生活日会中断透支的短期影响。
- 不跨多个生活日累计短期惩罚。

| 前一生活日 finalEnergy | shortTermAdjustment |
|---:|---:|
| `>= 0` | 0 |
| `-1 ... -5` | -1 |
| `-6 ... -10` | -2 |
| `-11 ... -20` | -3 |
| `< -20` | -4 |

---

# 5. 精力档位与提醒

按以下顺序判断，命中后停止：

```text
if currentEnergy < 0:
  overdraft
else if currentEnergy < initialEnergy * 0.25:
  low
else if currentEnergy < initialEnergy * 0.50:
  mediumLow
else:
  normal
```

因此：

- 恰好为 0 时属于 `low`，不是透支。
- 恰好为初始精力 25% 时属于 `mediumLow`。
- 恰好为初始精力 50% 时属于 `normal`。

一次记录跨过多个档位时：

- 只展示最终命中的最高严重度。
- 同时把本次跨过的较轻档位标记为已处理。
- 精力提醒在 5 秒撤销窗口结束后展示。
- 如果记录在窗口内撤销，不写入本次跨档提醒状态。
- 补做早间确认只能撤回当前提示，不触发更重的新提示。

同一生活日、同一档位最多展示一次。

# 6. 校准抽样规则

只有同时满足以下条件才可生成抽样反馈：

- 当前 CalibrationCycle 状态为 `collecting`。
- `dynamicLearningEnabled = true`。
- 活动记录为 `active`。
- `abs(theoreticalDelta) >= 16`。
- `theoreticalDelta != 0`。
- 当天已展示抽样次数少于 2。
- 距离当天上一次抽样展示至少 180 分钟。
- 第二次抽样的子类必须与第一次不同。

选择策略：

- 当天第一条满足条件的记录可触发第一次抽样。
- 满足时间间隔和不同子类条件后的第一条合格记录可触发第二次抽样。
- 抽样在 5 秒撤销窗口结束后展示。
- 用户跳过时不创建 CalibrationFeedback。
- 记录被撤销时，关联反馈变为 `invalidated`。

# 7. 个性化强度参数

## 7.1 参数范围

每个子类维护一个 `personalFactor`：

```text
默认值 = 1.00
最小值 = 0.70
最大值 = 1.30
```

它只改变影响强度，不改变默认值正负方向。

## 7.2 反馈方向

| 反馈 | 参数方向 |
|---|---|
| 系统估计偏轻 | 增大 personalFactor |
| 差不多 | 不推动参数变化 |
| 系统估计偏重 | 减小 personalFactor |

## 7.3 更新阈值

每个非重叠的 7 有效使用日周期评估一次。

某子类只有同时满足以下条件才更新：

- 至少 3 条 `active` 反馈。
- 至少覆盖 2 个不同生活日。
- 同一方向反馈占全部 active 反馈的比例至少为 70%；`aboutRight` 计入分母。

| 趋势 | 条件 | factor 变化 |
|---|---|---:|
| 弱 | 3 条同方向，且占比 `>= 70%` | 0.05 |
| 中 | 4～5 条同方向，且占比 `>= 70%` | 0.10 |
| 强 | 至少 6 条同方向，且占比 `>= 80%` | 0.15 |

更新后截断到 `[0.70, 1.30]`。

周期关闭时如果发生参数变化，则创建新的 personalizationVersion。新版本只用于之后创建的记录，不重算本周期历史记录。

以下生活日不用于参数更新：

- 活动记录数超过 12。
- finalEnergy 低于 -30。
- 当天发生规则迁移重算。

弱有效使用日中的直接反馈可以参与参数更新，因为反馈本身是用户的显式体感信号。

# 8. 有效使用日和校准周期

## 8.1 有效使用日

标准有效使用日：

- 完成早间确认。
- 至少有 1 条 active 活动记录。

弱有效使用日：

- 未完成早间确认。
- 至少有 2 条 active 活动记录。

两类日期推进周期时都计为 1 天。

基准线建议计算使用权重：

```text
standard day weight = 1.0
weak day weight = 0.5
```

## 8.2 周期边界

- 周期使用非重叠的 7 个有效使用日。
- 第 7 个有效使用日结算后冻结周期输入。
- 建议在下一个生活日首次打开时生成并展示。
- 用户延后期间新增的有效使用日归入下一周期，不改变已冻结周期。
- 接受、拒绝或延后都必须持久化。
- 已接受或已拒绝的周期不因普通重放改变。
- 显式规则迁移影响 pending / deferred 周期时，旧建议失效并按原冻结日期重新生成。
- 如果 baseEnergyDelta 为 0，周期进入 `noChange`，只展示一次校准结果摘要，不要求用户确认。

# 9. 个人基准线建议算法 v1

该算法是可解释的启发式估计，不代表对用户能力的科学测量。对用户统一称为“近期适用的估计基准”。

## 9.1 单日得分

先计算：

```text
finalRatio = finalEnergy / initialEnergy
```

结果分：

| 条件 | outcomeScore |
|---|---:|
| `finalEnergy < 0` | -2.0 |
| `0 <= finalRatio < 0.25` | -1.0 |
| `0.25 <= finalRatio <= 0.75` | 0.0 |
| `finalRatio > 0.75` | +1.0 |

早间状态辅助分：

| 状态 | morningScore |
|---|---:|
| 差 | -0.5 |
| 一般 | 0.0 |
| 好 | +0.5 |
| 缺失 | 0.0 |

```text
dayScore = outcomeScore + morningScore
```

恢复投入只用于原因摘要，不直接增加得分，避免通过大量记录恢复活动人为推高建议。

## 9.2 周期得分

```text
cycleScore = sum(dayScore * dayWeight) / sum(dayWeight)
```

其中标准有效日权重为 1.0，弱有效日权重为 0.5。

## 9.3 建议值

| cycleScore | baseEnergyDelta |
|---:|---:|
| `< -1.50` | -8 |
| `[-1.50, -0.75)` | -5 |
| `[-0.75, -0.25)` | -3 |
| `[-0.25, 0.25)` | 0 |
| `[0.25, 0.75)` | +3 |
| `[0.75, 1.25)` | +5 |
| `>= 1.25` | +8 |

```text
suggestedBaseEnergy = clamp(baseEnergyBefore + baseEnergyDelta, 60, 140)
```

系统只提供建议，用户接受后从决策发生时所属生活日的下一个生活日起生效。

# 10. 规则变更与重算窗口

## 10.1 普通设置变更

个人基准线修改只影响未来生活日，不重算历史活动。

动态学习关闭后：

- 冻结并继续使用当前 personalFactor。
- 不再生成抽样反馈。
- 不更新 personalFactor。
- 不生成新的基准线建议。
- 不推进个性化校准周期，关闭期间的有效使用日不在重新开启后补计。
- 已存在的 pending / deferred 建议置为 invalidated，并停止后续提醒。

重新开启后创建新的 CalibrationCycle；已有 personalFactor 继续作为起点。

## 10.2 默认活动规则变更

用户确认修改等级映射后，执行显式 `ruleMigrationReplay`：

- 目标为当前未结算生活日，以及最近 7 个有效使用日。
- 每条历史记录保留原 `personalFactorSnapshot`，迁移只替换默认规则版本，不套用当前个性化参数。
- 从最早受影响生活日向后按顺序重算。
- 窗口起点之前的 initialEnergy 和 shortTermAdjustment 作为固定输入。
- 窗口内相邻生活日重新计算 shortTermAdjustment；空生活日中断传播。
- 如果窗口之后已经存在当前生活日，则传播并重算到当前生活日为止。
- accepted / rejected 周期保持冻结。
- pending / deferred 周期若包含受影响生活日，则旧建议置为 invalidated，并基于原冻结日期重新生成。

更早历史不重算，保留原规则版本和原始结果。

# 11. 汇总统计口径

```text
totalConsumption = sum(abs(appliedDelta)) for appliedDelta < 0
totalRecovery = sum(appliedDelta) for appliedDelta > 0

categoryNetDelta = sum(appliedDelta)
categoryGrossDelta = sum(abs(appliedDelta))
```

今日概览：

- 默认按 `categoryGrossDelta` 降序排序。
- 展示总时长和 `categoryNetDelta`。
- `categoryGrossDelta` 仅作为排序依据，可不直接展示。

事件重放稳定排序：

```text
completedAt ASC, createdAt ASC, id ASC
```

# 12. 数据与时间约定

- 时间戳以 UTC 保存。
- `lifeDay` 在记录创建时按设备本地时区和 04:00 切换点计算后持久化。
- 用户切换时区后不重新归属历史记录。
- 5 秒撤销窗口使用单调计时器控制 UI；持久化校验同时记录 UTC 截止时间。
- JSON 导出必须包含 `schemaVersion`、`exportedAt`、规则版本和校准算法版本。
